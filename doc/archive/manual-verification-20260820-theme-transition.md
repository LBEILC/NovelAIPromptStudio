# 深浅主题向上揭示过渡人工验证

## 验证对象

- 变更：深色、浅色及跟随系统主题切换时的根视图向上揭示过渡
- 提交：`3665fbd`
- 目标操作系统：Windows 11

## 前置条件

- 已在提交 `3665fbd` 或包含该提交的更新版本上执行 `npm ci`。
- 使用 `npm run dev` 启动应用。
- 准备一个包含图片的图库，并在工作台打开至少一张图片，便于观察复杂页面的换色完整性。
- Windows“动画效果”和“对比度主题”保持日常使用设置；涉及减弱动效的步骤会单独说明。

## 验证步骤

1. 打开“设置 → 外观”，将“动效”设为“完整”，在深色与浅色之间各切换一次。
   - 预期结果：旧主题画面保持原位，新主题从窗口底部连续向上揭示；页面本身没有整体位移、缩放、骨架或逐组件闪换；过渡约 320 毫秒并自然减速。
   - 实际结果：通过，用户确认符合预期。

2. 分别停留在工作台、图库和设置页，重复深色与浅色切换，观察侧边导航、图片、浮动面板、弹出层及滚动区域。
   - 预期结果：每个页面均作为完整快照统一过渡；图片和布局不重新排布，底部到顶部的边界连续，没有黑屏、白闪、撕裂、残留旧主题色或弹层层级错误。
   - 实际结果：通过，用户确认符合预期。

3. 在一次过渡尚未结束时快速连续切换主题，最终停在任意明确主题。
   - 预期结果：进行中的过渡可被打断，界面及时响应，最终主题与选项一致；不会叠加多层动画、卡住遮罩或留下不可点击区域。
   - 实际结果：通过，用户确认符合预期。

4. 将主题从明确的深色或浅色改为“跟随系统”，先让系统主题与当前主题相同，再让它与当前主题不同。
   - 预期结果：解析后的主题没有变化时直接更新选项而不播放无意义动画；解析后的主题确实变化时播放一次向上揭示。之后由 Windows 系统主题变化触发的自动换色可以直接更新，不出现双重动画或中间错误主题。
   - 实际结果：通过，用户确认符合预期。

5. 将应用“动效”设为“关闭”，重复深浅主题切换；再设为“跟随系统”，开启 Windows 的减弱/关闭动画偏好后重复切换。
   - 预期结果：“关闭”始终直接换色；“跟随系统”在系统要求减弱动效时直接换色；主题、文字、图标和强调色仍同步更新。
   - 实际结果：通过，用户确认符合预期。

6. 关闭并重新启动应用，观察上次保存主题的恢复过程。
   - 预期结果：启动恢复不播放主题切换动画，不先展示错误主题后再扫过；应用正常进入最后保存的主题和页面。
   - 实际结果：通过，用户确认符合预期。

7. 在图库包含较多缩略图、工作台显示大图时各连续切换主题 10 次，并在切换间隙操作导航或滚动。
   - 预期结果：动画期间没有明显掉帧或输入长时间无响应；结束后导航、滚动、图片预览和设置控件均可正常使用。
   - 实际结果：通过，用户确认符合预期。

- 结果：通过。用户于 2026-08-20 确认完成 Windows 人工验证。
