# 工作台标签弹性收缩手工验证

## 待验证变更

工作台标签栏改为随可用空间弹性收缩，不再显示横向滚动条；非激活标签之间增加动态短分隔线与轻微悬停背景；窄标签会逐步收起次要状态元素；修改状态文案改为“Prompt 已相对原图修改”与“工作区草稿”。

## 目标操作系统

Windows 10/11。

## 前置条件

- 已执行 `npm ci`。
- 准备至少十二张可由工作台打开的 PNG、JPG 或 WEBP 图片，其中至少一张包含 NovelAI Prompt 元数据。
- 建议其中数张图片使用较长文件名，以检查标题截断。
- 使用 `npm run dev` 启动应用。

## 验证步骤

1. 在工作台中依次打开两至三张图片。
   预期结果：标签保持舒适宽度，最大宽度一致；标题过长时显示省略号；关闭符号 `×` 到标签右边界的视觉留白与标题到左边界大致一致；标签栏右侧可以保留空白，不会强制把少量标签拉满整行。
   实际结果：通过，与预期一致。

2. 继续打开图片，直到原先会出现横向滚动条的数量。
   预期结果：所有标签在同一行内平滑收缩，标签栏不出现横向滚动条，工作台内容区宽度不受影响。
   实际结果：通过，与预期一致。

3. 观察标签之间的分隔，并将鼠标依次移过多个非当前标签。
   预期结果：非当前标签之间显示短而克制的竖向分隔线；当前标签两侧不显示分隔线；悬停标签出现轻微背景，其两侧分隔线暂时隐藏；标签栏不会呈现密集的完整边框。
   实际结果：通过，与预期一致。

4. 调整应用窗口宽度，在较宽与较窄状态之间往返。
   预期结果：标签宽度随可用空间自动调整；标题始终正确截断；标签不换行、不重叠，也不会溢出标签栏。
   实际结果：通过，与预期一致。

5. 在标签较窄时依次悬停非当前标签，并切换当前标签。
   预期结果：非当前标签的关闭按钮默认让出标题空间，悬停时可以出现；当前标签仍可见关闭按钮，点击后只关闭目标标签。
   实际结果：通过，与预期一致。

6. 修改任意标签中的 Tag，使其 Prompt 不再与原图一致，然后在不同窗口宽度下观察该标签。
   预期结果：空间充足时显示蓝色“已修改”圆点；标签收缩到很窄时圆点自动隐藏；圆点的辅助说明为“Prompt 已相对原图修改”。
   实际结果：通过，与预期一致。

7. 悬停已修改标签，查看标签预览信息。
   预期结果：预览信息显示“Prompt 已修改”，不再出现“未保存修改”的说法。
   实际结果：通过，与预期一致。

8. 尝试关闭已修改标签，然后取消；再次关闭并确认。
   预期结果：确认框说明 Prompt 已相对原图修改，并明确关闭会丢弃工作区草稿；取消时标签保留，确认时标签关闭。
   实际结果：通过，与预期一致。

9. 在浅色与深色主题下重复步骤 2 至 7，并使用 `Ctrl + Tab` / `Ctrl + Shift + Tab` 切换标签。
   预期结果：两种主题下标签、激活背景、标题、关闭按钮和修改圆点均清晰可辨；键盘切换行为保持正常。
   实际结果：通过，与预期一致。

## 总体结果

通过。标签弹性收缩、标题截断、分隔与悬停状态、修改提示、关闭确认和键盘切换均正常。

## 发现的问题

无。
