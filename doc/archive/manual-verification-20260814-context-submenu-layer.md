# 右键菜单二级菜单层级手工验证

## 待验证变更

修正 Lobe UI 右键菜单一级菜单使用动态递增层级、二级菜单仍固定为 `1199` 所造成的层级倒置。保持组件默认的 `0ms` 关闭延迟与安全多边形交互不变，使二级菜单始终显示在一级菜单上方，同时保持在 Toast 层下方。

## 目标操作系统

Windows 10/11。

## 前置条件

- 使用包含多个 Tag 的图片进入工作台。
- 使用 `npm run dev` 启动应用。
- 为覆盖动态层级递增场景，准备重复打开右键菜单至少 15 次。

## 验证步骤

1. 在任意 Tag 上重复打开并关闭右键菜单至少 15 次，随后悬停“设置分类”。

   预期结果：二级菜单完整显示在一级菜单上方；两者发生重叠时，二级菜单的边框、背景和菜单项不会被一级菜单遮挡。

   实际结果：通过，与预期一致。

2. 从“设置分类”菜单项缓慢、斜向移动鼠标到二级菜单，并在不同分类项之间移动。

   预期结果：鼠标进入二级菜单前不会因重叠区域被一级菜单截获而关闭；进入后可正常高亮各分类项。

   实际结果：通过，与预期一致。

3. 分别选择一个新分类和当前分类，再次打开菜单确认状态。

   预期结果：分类操作正常执行；当前分类的勾选标记正确，右键菜单正常关闭。

   实际结果：通过，与预期一致。

4. 在窗口右侧、底部附近的 Tag 上重复上述操作，并分别检查浅色和深色主题。

   预期结果：菜单自动翻转或调整位置时仍保持二级菜单在上层，菜单内容清晰且不溢出窗口。

   实际结果：通过，与预期一致。

5. 打开二级菜单时触发一条 Toast（例如完成一次复制操作后立即再次打开菜单）。

   预期结果：Toast 仍显示在菜单浮层之上，不被二级菜单遮挡。

   实际结果：通过，与预期一致。

## 总体结果

通过。二级菜单层级、斜向移动、分类操作、边缘避让、主题和 Toast 层级均正常。

## 发现的问题

无。
