## 1. 产品定位

NovelAI Prompt Studio 是一个由图片驱动的 Prompt / Tag 编辑器，并提供一个轻量的本地图片库。

它解决两件事：

1. 从 NovelAI 图片读取 Prompt，在本地完成结构化编辑、翻译、分类与复制。
2. 保存值得复用的图片，并在需要时重新送入工作台。

应用不生成图片，也不重复实现必须回到 NovelAI 才能验证效果的调参流程。

## 2. 信息架构

应用有两个业务页面：

- **工作台**：打开图片后立即解析并编辑 Prompt。
- **图片库**：持久保存、查找和重新打开图片。

设置是应用级辅助页面，不构成第三个业务资源库。

```text
应用
├─ 工作台（默认）
├─ 图片库
└─ 设置
```

### 两种图片入口

| 入口 | 行为 | 是否写入图片库 |
| --- | --- | --- |
| 拖入或打开到工作台 | 创建临时工作草稿并进入编辑 | 否 |
| 导入图片库 | 复制图片及可恢复资源到用户资源目录 | 是 |

打开工作台不会修改原图，也不会把草稿自动回写到图片库。

## 3. 工作台

### 核心能力

- 读取 NovelAI PNG metadata，并兼容应用已经支持的历史 Prompt 写法。
- 区分 Prompt 与 Undesired Content。
- 以结构、分类或原始文本查看 Prompt。
- 添加、删除、排序、选择和批量处理 Tag。
- 编辑 Tag 文本、翻译、分类与权重。
- 在结构化 Tag 与原始 Prompt 文本之间同步。
- 复制完整 Prompt，或复制单个 Tag 的纯文本与带权重形式。
- AI 翻译与 AI 分类；超出单次请求上限时由程序自动分批处理。
- 恢复本次打开图片时的原始草稿状态。

### 编辑原则

- 工作台只保存自己的草稿状态，不写回图片 metadata。
- 原始 Prompt 保留用户可自由编辑的文本形态；结构化视图只负责解析和呈现。
- 带括号的 Tag 组在结构化视图中可拆分编辑，但序列化时必须保留正确的权重语义。
- AI 只辅助翻译和分类，不代替用户最终确认。

### Vibe

- 只读取图片中可恢复的 Vibe 数据。
- 可导出 `.naiv4vibe` 文件，并在系统文件夹中显示。
- 不提供 Vibe 库、强度编辑或本地效果预览。

## 4. 图片库

- 通过按钮、拖放或系统文件选择器导入图片。
- 在用户选择的资源目录中持久保存图片与可恢复的 Vibe 文件。
- 提供缩略图浏览、搜索、排序、详情预览和大图查看。
- 从图片卡片或详情侧栏将图片送入工作台。
- 在系统文件夹中显示资源。
- 从图片库移除资源时明确提示影响范围。
- 侧栏保持挂载，支持折叠、恢复、拖拽调宽和重新选择图片后自动展开。

图片库是收藏与回访入口，不承担 Tag 资产管理、关系图谱或生成历史管理。

## 5. 设置与本地数据

设置保留以下应用级能力：

- 跟随系统、浅色与深色主题。
- 主题色。
- Tag 等宽字体与界面非衬线字体分别选择，并基于系统字体提供预览。
- 界面密度与动效偏好。
- AI 服务连接信息。
- 翻译与分类 Prompt 的高级编辑。
- 资源保存位置，以及将现有资源迁移到新位置。

敏感连接信息继续使用安全存储。路径、文件对话框、字体、快捷键和资源迁移均按跨平台能力实现。

## 6. 明确不做

- Tag 库与 Vibe 库。
- Vibe 强度编辑、混合、试听或效果模拟。
- 图片系列、分支、版本树、实验、关系和对比系统。
- 独立的 Tag 资产收藏、标签关系图谱或统计面板。
- 在应用内生成图片。
- 修改原始图片 metadata。
- 未经用户确认，将工作台草稿写回图片库资源。

未来功能可以提高工作台与图片库的效率，但不应重新引入上述资源库或实验管理系统。

## 7. 数据安全

- 原始图片保持不可变。
- 数据迁移前创建可恢复备份；迁移失败时保留旧目录并给出明确提示。
- 删除或移除操作必须区分“移出应用”与“删除磁盘文件”。
- 不因界面移除旧功能而静默删除历史数据表或用户文件。
- Prompt 解析失败时保留原始文本，不能因结构化失败丢失内容。

## 8. 实施约束

- 页面与交互遵循 [Lobe 视觉规范](./lobe-visual-language.md)。
- Lobe UI 组件选择、导入路径和弃用迁移遵循 [项目 Skill](../.agents/skills/lobe-ui-frontend/SKILL.md)。
- 具体 API 以项目已安装的 `@lobehub/ui` 版本和本地类型定义为准。
- Windows 与 macOS 是一等支持平台；共享 npm 脚本与业务代码不引入平台专属 shell 语法。
- 当前实现状态以代码和测试为准；下一阶段目标以[效率功能开发规格](./workbench-gallery-productivity-development-spec.md)为准。
