# 011a 很长的 Tag 列表里有个别长项时，整块被判成了段落

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4，012（图片库界面）的前置
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：[011 汇报](./reports/011.md)；设计负责人用只读统计在真实图库的副本上跑出的结果

## 现象

在一份 162 张图的真实图库副本上：原样写回 0 失败；631 个块里 579 个是 Tag 块、52 个是段落块，V5 的段落 43 个，符合预期。

但 V4.5 有 7 处"单块结果与 `parsePrompt` 不一致"。逐个看结构特征（只看数字，不看文字），7 处是同一段排除内容，被 7 张图共用：

| 特征 | 值 |
|---|---|
| 长度 | 877 个字符，没有换行 |
| 用逗号分开的项 | 61 项 |
| 最长的一项 | 13 个词、59 个字符 |
| 带句末标点的地方 | 2 处 |
| 权重组 | 1 个 |
| 汉字 | 0 |

也就是一份 61 项的排除预设，其中有一项 13 个词（比 `MAX_TAG_PHRASE_WORDS` 多 1 个），有两处带句号。按现在的规则"每一项都要短"，整块被判成了段落。这是误判：它明显是一个 Tag 列表。

## 规则的修改（设计已定）

设计文档 2.1 节已更新。在现有判断之前加一条：

- 一个块用逗号分成的项不少于 10 项（权重组仍然整体算一项），并且其中"不像 Tag 的项"不超过一成（向下取整，至少允许 1 项），就是 Tag 块。
- "不像 Tag 的项"指：超过短语的词数或字符数上限，或者带句末标点并且达到较长分句的词数。
- 那几个长项照常作为一个 Tag 保留，解析结果与 `parsePrompt` 一致。
- 不满足这一条的，照原来的规则判断，"拿不准当作段落"不变。

阈值写成命名清楚的常量。

## 要求

1. 加一个合成样例复现上面的特征（61 项、一项 13 个词、两处句号、一个权重组；内容自己构造，不要用真实 Prompt），修改前判成段落，修改后判成 Tag 块，并且 Tag 与 `parsePrompt` 逐项相同。
2. 反方向的样例也要有，保证没有把真正的段落判成 Tag：
   - 多个句子的英文描述，每句里有两三个逗号（总项数超过 10）；
   - 11 项里有 2 项是长句；
   - 成段的中文。
3. 011 的全部测试保留并通过，包括 3000 个随机输入的原样写回。
4. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 通过。
