# 011 工程汇报：按块组织的 Prompt

日期：2026-10-11。角色：工程负责人。分支：`rebuild/ui-1.0`。

## 1. 完成了什么

实现了 `src/lib/promptDocument.ts`，只依赖现有纯逻辑模块和领域类型，不依赖 React、Electron 或 Node API。提供：

- `parsePromptSection` / `serializePromptSection`：一段文本的空行分块、标签提取、类型判断、原文范围和无损写回。
- `setPromptBlockType`、`editPromptParagraph`、`editPromptTag`：不可变更新；支持改类型、改段落、改 Tag 权重、删除 Tag。编辑后更新各块的位置，保留其类型。
- `createPromptDocument`：沿用 `promptStructure` 的来源优先级，读取基础正面/排除内容、各角色正面/排除内容。支持已有结构对象、结构 JSON、PNG 元数据结构及 `extra_json` 回退。
- `promptDocumentProject`：由各块写回兼容结构，保留角色坐标、顺序、自动 Tag 设置和未改动的标注。
- `copyPromptDocument`、`promptDocumentCopyOptions`、`copyPromptDocumentScope`、`copyVisiblePromptDocument`：复用原复制规则，保留自动 Tag 排除、筛选、选中项分类排序、角色拼接及负面内容排除语义。
- `check:prompt-blocks`：独立的 SQLite 只读统计命令。没有调用会迁移数据库的应用初始化代码。

没有修改界面、数据库格式、IPC 或用户类型选择的持久化方式。没有新增依赖，没有读取用户数据目录。

### 判断阈值及结果

| 常量 | 值 | 用途及取值理由 |
| --- | --- | --- |
| `MAX_BLOCK_LABEL_CHARACTERS` | 32 | 标签是一小段名称；限制长度，避免把长句的冒号误认成标签。 |
| `MAX_TAG_PHRASE_WORDS` | 12 | 容纳现有较长服装、光照和描述性短语；更长的普通分项保守判为段落。 |
| `MAX_TAG_PHRASE_CHARACTERS` | 100 | 限制无空格的超长分项；与词数一起使用。字符数按 JS 字符串长度计算。 |
| `MIN_SENTENCE_CLAUSE_WORDS` | 8 | 分项有句末标点且至少 8 个空白分隔词时，优先判为段落，先于短语判断。 |
| `MIN_PARAGRAPH_HAN_CHARACTERS` | 16 | 单个分句至少 16 个汉字，或带中文句末标点的全文累计至少 16 个汉字时，判为段落；避免把短中文角色名误当段落。 |

完整数值权重组在分类时替换成一个占位项，内部逗号不增加分项数。其余分项按中英文逗号或单换行划分；都满足短语阈值时才判为 Tag，未命中条件时判为段落。类型是启发式结果，调用方可以用 `overrides` 按原文或精确范围覆盖。

任务合成样例的 9 个块全部符合预期：4 个 Tag 块、5 个段落块；正确提取 `Rossi:`、`Panel 1:`、`Panel 2:`、`<style>` 和中文角色标签。额外验证了多个较短中文分句组成的段落、长英文无标点描述和数值权重组。

仓库 `demo/promo-v090/final/` 的 14 张演示图共 56 个正负 Prompt 区域，42 个非空区域；42 个全部是单 Tag 块，Tag 每个字段与原 `parsePrompt` 相同。剩余 14 个空区域没有块。

### 无损写回与最小编辑

每个块保存完整 `raw`；`separators` 保存首部、块间、尾部的 N+1 段原始分隔文本。写回只连接这些字符串，不调用旧格式化器。标签、标签后的空白、内容、首尾空白另行保存，编辑仅替换相应内容。范围采用半开区间的 UTF-16 下标，可直接用于 `String.slice`，不是编码后的字节下标。

`prompt.js` 的原扫描器新增位置记录；新函数 `promptTagRanges` 将规范化后的下标映射回原文，包括 CRLF 和全角逗号。`parsePrompt` 的公开返回值不增加字段、不改变解析规则。既有样例继续检验全部原断言，并增加块模型的对照断言。

调整独占权重组中的 Tag，只替换权重数字。调整共享权重组中的成员，在目标叶子的原位置关闭、重开必要的权重/花括号，其他叶子、分隔符和空白原样保留。删除只去掉叶子原文，因此可能留下空组或多余逗号；旧解析器会忽略它们。操作提交到返回值前重新解析，确认目标之外的 Tag 内容、权重和花括号深度都没变。

开发中暴露的边界是旧语法无法表示的嵌套 `::`：例如 `-2::{sky, 0.5::river, mist::}::` 在旧解析器中本来就不是一个正确嵌套的组。将其中含内嵌控制符的叶子直接包上新权重，会意外产生另一个 Tag。现实现会原子拒绝这类无法保留语义的编辑，不返回半修改结果；原样写回仍完全支持该输入。详见第 8、9 节。

### 与旧模块的关系

`promptStructure` 继续负责来源解析、角色结构和既有复制政策；块模块负责文本分块、类型和原文编辑。`parsePrompt` 继续作为 Tag 语义唯一来源，包括花括号、方括号的现有行为、数值组、引号、Text 段和语法提示。这里没有重新实现或修正旧语法。

当前不能删除旧模块。后续界面迁移后，可替换调用方“先把整个 Prompt 当成 Tag 数组”的显示/编辑路径，以及以整段 `formatPromptGroupedInline` 重写文本的编辑路径。`extractV4PromptData`、旧数据规范化、`parsePrompt` 和自动 Tag/复制规则仍需保留；本次复制适配器也依赖它们。

## 5. 推断清单

1. 空文本或纯空白文本表示零个块，空白整体放在分隔数组里；单个换行不分块。空白行按 JS `trim` 的空白定义识别，支持 CRLF、LF 和单 CR。
2. 冒号标签需要以字母/汉字开头，后接字母、数字、空格、下划线或连字符，冒号之后有空白或到达末尾。保留 `artist:`、`rating:`、`Text:` 的既有含义，不将它们提取为标签。尖括号标签同样限制为简短名称，不作为 HTML 解析。
3. 范围覆盖优先于原文覆盖；重复原文可以用范围单独指定。范围包含块首尾空白，不包含其后的换行分隔。类型覆盖不持久化。
4. 段落编辑保留为一个块，即便新文本内含空行；序列化正确。调用方若主动重新分块，应重新提供用户类型选择。
5. 删除时保留多余逗号和空包装，优先满足最小文本改动，不自动美化。无法在旧语法中安全表示的编辑抛出 `RangeError`，见第 9 节。
6. 全部/单区域/可见/选中复制沿用旧语义，包括旧 Text 处理、分类排序和自动词判断；不因显示类型变为段落而自行更改复制规则。内容编辑后重解析兼容 Tag，保留可匹配的已有 ID/标注；新兼容 ID按区域和位置确定，使重复复制稳定。
7. 无损属性测试使用固定种子的自定义 PRNG，无新增测试库。生成器混合语法片段、空白、标点、中文、表情、NUL、BOM 和任意 UTF-16 单元；比较字符串与 UTF-8 Buffer，并检查范围和 Tag 位置映射。
8. 统计覆盖数据库 `projects` 全部记录（含无元数据的记录），块数按基础、角色的正负区域合计；区域内空文本计零块。未读取图片文件，也未输出图片标识。
9. 为保证不泄露任意数据库文本，模型分组使用固定版本代码：`0` 未识别、`3` V3、`4` V4、`45` V4.5、`5` V5；同版本 Full/Curated 合并。`blockCounts` 的键是每图总块数、值是图片数量。占比为 0–1；空库占比为 0。
10. V4/V4.5 的不一致数以非空单块区域为单位；段落分类或标签剥离导致其与整段旧解析结果不同也会计入，供设计负责人观察误判。失败详情只返回数字，不回显 SQL 错误或路径。

```powershell
node --experimental-strip-types --disable-warning=ExperimentalWarning scripts/check-prompt-blocks.mjs "数据库文件的绝对路径"
```

## 9. 已知问题

- 启发式阈值不能保证识别所有自然语言，特别是很短的句子、混合写法和非常长的 Tag；类型覆盖是明确的纠正入口。
- 旧解析器不支持真正嵌套的数值权重语法。不能在保持其现有结果的同时为任意控制片段赋予有效数值权重；这类编辑由语义检查拒绝。将来接入界面时需要处理该异常，不能假定所有诊断片段都可调权重。
- 保留最小编辑会留下空组/多余逗号；这是有意保留的原文，不影响已验证的旧解析结果。
- 未知模型标识归入 `0`，统计不会输出其原名；需要区分更多版本时应扩充固定映射，不能直接回显数据库值。
