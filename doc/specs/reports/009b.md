# 009b 工程汇报

## 1. 完成了什么

确认存在产品竞态：`useAISettings` 首次读取尚未完成时，用户已能编辑表单；随后返回的已保存设置直接替换整份状态，覆盖未保存输入。`Activity` 隐藏分页会清理 effect，重新显示会再次读取；`loaded` 仅在读取成功后置位，因此也会在切回分页后触发这一问题。

现在将表单值与已编辑字段放在同一份 React 状态中。读取完成时，已编辑字段保留当前草稿，未编辑字段及默认规则、安全存储状态仍从已保存设置加载。字段编辑后又清空也保留为空。保存成功会完成初始化，尚未返回的旧读取不能撤回此次保存。

保留原有分页切换即时断言，补充五字段失败说明；API Key 仅输出是否为空和长度。新增由验收进程控制的延迟读取场景，先暂停真实设置快照的返回，完成输入和分页切换后才释放，检查返回后仍保留草稿。没有增加固定睡眠或放宽断言期限。

检查了其余四个分页：外观直接读取/保存共享偏好，无独立未保存表单；图片库读取目录和备份状态，无草稿回填；翻译词典的编辑状态由打开编辑操作设置，异步列表查询不写回编辑字段；关于与更新直接读取/保存开关及更新状态，无独立草稿。这些分页没有同样的草稿覆盖写法，无需修改。

## 5. 推断清单

- 以字段为单位保护草稿，使用户只编辑一个字段时其余字段仍能加载已保存值；已编辑字段恢复为空值仍算草稿。
- 保存成功视为已有比首次读取更新的权威状态，因此忽略随后返回的首次读取结果。
- 用可释放的 Promise 暂停读取，替代依赖机器速度的固定延迟；释放后追加 IPC 往返和两帧绘制，再读取真实输入值。
- 在已有 CI 减少动态偏好验收中附加慢读取模式，避免增加完整验收轮数。
- 未取得原 macOS CI 失败时的字段快照，无法还原那一次运行的精确时间线；本次由单元测试与真实应用共同证明同一操作路径确有产品竞态。

## 7. 新增断言与自动化没覆盖

单元测试新增四项：首次读取晚到保留五字段；隐藏/显示分页后晚到读取保留五字段；仅编辑再清空时保留空值并加载其他已保存字段；先保存成功再收到旧读取时保留新保存状态并清空 Key。

真实应用新增“晚到的已保存 AI 设置不覆盖五个草稿字段”，在慢读取模式下分别覆盖浅色与深色。原“分页切换保留 AI 草稿”增加脱敏失败说明。慢读取若破坏草稿，中止后续模型连接测试，防止访问被覆盖后的服务地址。

自动化没覆盖：本机不能执行 macOS 运行；已接入现有 macOS CI，但本工程任务只提交、不推送，远端结果待设计负责人推送后产生。没有新增依赖原生文件对话框、系统级输入或窗口拖动的行为，本任务无需新增人工验收或跨平台交接。
