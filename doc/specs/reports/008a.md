## 5. 推断与实现选择

- 每个请求最多 4 次尝试，退避 1、2、4 秒；每次沿用 120 秒超时。网络失败、响应体断线、HTTP 429 和 5xx 可以重试，其余 HTTP 错误立即失败。
- 解压与哈希验证位于重试循环之外；损坏的本地缓存立即失败，不下载覆盖。单独包版本变化后查找同页全量包是既有来源选择逻辑，予以保留；不会因哈希错误重复下载同一来源，最终候选哈希不符直接失败且不写文件。
- Range 条目请求要求 206，若返回 200，立即取消响应体且不重试，保留原有防止误下载整个大包的保护。
- 缓存仅包含 `.local/fonts/MiSansVF.ttf`。相对路径避免平台绝对目录不同；没有不精确的 `restore-keys`。
- 采用 `actions/cache/restore@v5` 和 `actions/cache/save@v5`，两端均设置 `enableCrossOsArchive: true`。在下载与哈希校验成功后立即保存，后续验收失败不会阻止已验证字体供其他运行复用。
- 缓存键继续为 `misans-v4.003-5daf8d5447bfd423cfdec94a0e07c53b205892223ccc6ea21b7b8a37248b44d9`，没有 OS、Node 或架构字段。CI 与 release 完全一致。路径从目录缩小为字体文件，首次采用新配置可能未命中旧缓存。

跨平台配置依据 [GitHub Actions cache 官方说明](https://github.com/actions/cache/blob/main/tips-and-workarounds.md#cross-os-cache)。缓存仍受 GitHub 分支可见性限制；冷启动时同时开始的矩阵任务可能各自下载，已完成保存的缓存供之后的恢复步骤命中，不会让已开始的未命中任务自动重新恢复。

## 6. 官网现状与实现时核实

2026-10-11 从[小米官方下载页](https://hyperos.mi.com/font/download)解析并实测：

| 官方来源 | TTF name 表版本 | 字节数 | SHA-256 |
| --- | --- | ---: | --- |
| `https://hyperos.mi.com/font-download/MiSans.zip` 内 MiSans VF | Version 4.009 | 20,093,424 | `0ddef90648998900175cfdca9a6f087a2544c182f130b0ad4f7e94a03a115e79` |
| `https://hyperos.mi.com/font-download/MiSans_Global_ALL.zip` 内嵌 MiSans.zip 的 MiSans VF | Version 4.003 | 20,000,736 | `5daf8d5447bfd423cfdec94a0e07c53b205892223ccc6ea21b7b8a37248b44d9` |

结论：单独包确已更新，但全量包仍含锁定原版；现有锁定值无需改变。本机用修复后的下载实现从空目录成功获取 4.003，接着禁用 fetch 验证缓存复用。截图、验收和打包命令本来就只读取本地字体；工作流命中缓存后只执行 `fonts:check`，不执行 `fonts`。

## 7. 验收断言及自动化没覆盖

新增 5 项字体自动测试：

1. 连接错误后响应体再中断，最终成功；Range 参数保持，退避为 1、2 秒。
2. 持续网络失败恰好尝试 4 次，退避为 1、2、4 秒后抛错。
3. 必须为 206 的 Range 请求返回 200 时取消响应，不读取大包且不重试。
4. 下载字体哈希不符，不重试、不写文件。
5. 本地缓存哈希不符，不访问官网。

原有缺失/损坏字体禁止打包测试保持通过。无需新增产品交互断言；009 的两类断言修正在独立提交中。

无产品范围偏离。任务要求的“哈希不符不重试”应用于下载重试和最终校验；保留既有从单独包寻找官方全量包锁定版本的路径，否则当前官网状态下任何冷缓存都无法取得 4.003。

## 9. 已知问题

官网持续不可用且没有可见缓存时，重试耗尽仍会失败；两个官方来源都不再提供锁定字体时，也会严格失败。没有第三方下载、静默升级或跳过哈希的后备路径。远端 CI 和发布结果由设计负责人推送后确认。
