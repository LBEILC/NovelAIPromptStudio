## 5. 推断清单

- 1240×760 指页面内容及输出 PNG 尺寸，使用 `useContentSize` 和 1 倍缩放；不包含系统窗口边框。
- 设置分页采用当前实现的 appearance、storage、ai、tags、support、updates。
- 工作台取按文件名排序的前三张；详情取当前图库首张；回收站取当前图库末张；普通收藏集加入前三个图库条目；智能收藏集使用 `1girl` 搜索规则。
- 保留产品自动建立的默认收藏夹；额外创建任务要求的一普通、一智能收藏集。
- 每个场景重新挂载真实窗口，使各组件内部状态可直接初始化；不通过点击、键盘或修改 DOM 内容切换页面。
- 截图关闭动画，真实主题/动效偏好写入临时偏好文件，并用 user-origin CSS 禁用动画、过渡和光标闪烁。
- 数据准备使用当前已迁移的原生 SQLite 引擎，不切换数据引擎；没有旧引擎同口径截图准备基线，因此不能声称性能提升或退化。

## 6. 实现核实与任务问题

任务没有单独标注【实现时核实】条目，实际核实如下。

### 隔离与清理

父脚本创建系统临时目录 `nai-app-screens-*` 并写归属标记，通过 `--app-screenshots=<目录>` 传入。主进程在 ready 前将 userData、sessionData、logs、crashDumps 全部指向其子目录，并跳过 `configureAppProfile`。数据库、偏好、资源库、工作台临时文件均从重定向后的 userData 派生，未使用默认或已有 demo。

子进程正常结束、报错、崩溃或超时，父进程都在 finally 中清理自己创建的准确路径，带文件占用重试。SIGINT/SIGTERM 先停止子进程再清理。若父子进程同时被强制杀死或断电，finally 无法执行，可能留下临时目录；它不会在下次被复用，可在确认无运行进程后删除日志所列的确切目录。不会扫描删除其他 Profile。

确认数据边界采用路径路由审查、带禁止 getPath 默认查询的 mock 测试，以及每轮清单中的实际 userData/sessionData 和清理输出；没有为验收去读取或散列日常图库。此证据证明本工具的应用数据访问路径全部隔离，不等同于操作系统级文件访问追踪。

### 入口限制与错误处理

只有主进程确认专用参数后才动态加载截图执行器，并给截图窗口传 `--app-screenshot-state`。普通窗口没有这个附加参数，preload 不暴露 `studioScreenshot`，也不安装截图监听器；产品 UI 没有触发入口。VM 执行真实 preload 的测试验证普通模式只暴露 `studio`，截图模式才有状态、待完成请求计数和错误报告。

页面条件初始化使用这个受控桥，不读取 URL 参数或 localStorage 作为截图开关。等待 App 状态就绪、主题匹配、IPC 完成、DOM 稳定、`document.fonts.ready`、可见图片 `decode()` 和双帧后才调用 capturePage。捕获拒绝、空图、console error、未捕获异常、未处理拒绝、渲染进程退出都会导致失败；父脚本另核对成功清单和所有输出文件，避免静默成功。

### CI 与 macOS

使用隐藏离屏窗口、软件渲染和固定缩放，不需要物理显示器，也不使用开发服务器。GitHub Windows/macOS runner 提供图形会话；macOS 不需 Xvfb。完全没有图形服务的 Linux 环境不在本次 CI 范围内，仍可能需要 Xvfb。

macOS 截图运行由配置后的 CI 验证，本次只提交未推送，不能把尚未执行的远端 CI 记作通过。CI 可覆盖启动、原生数据库、导入、协议图片加载和渲染；无法替代系统窗口控件、菜单、键盘、触控板及真实用户环境验证。不同操作系统的字体和原生控件外观允许不同，本次一致性验收在同一 Windows 环境进行。

### 原有内部状态限制

App 的页面、工作台会话、图库 view/preview，以及 Gallery 的展开状态和 Settings 的分页原本各自保存在内部。增加仅截图模式生效的初值/加载分支；工作台仍调用产品读取函数，图库仍经过产品分组与详情渲染。没有直接切换不到而被省略的画面。
