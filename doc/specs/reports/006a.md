# 006a 工程汇报：截图工具在 Windows CI 上失败

## 1. 完成内容与原因

修复截图工具对原生窗口尺寸的依赖。截图模式在页面初始化前，通过 Electron 内置调试协议将渲染视口固定为 1240×760、设备比例固定为 1；随后通过 `Page.captureScreenshot` 截取同一视口。保留原有 `innerWidth` / `innerHeight` 严格检查，并新增输出 PNG 必须为 1240×760 的检查。

核对了 CI 运行 `38121203519`（提交 `f31949f`）的失败日志：Windows Node 22、24 都在原来的视口断言处失败。旧日志没有记录实际窗口、视口和显示器尺寸，因此不能把“runner 分辨率一定是 1024×768”当作已测事实。

本机复现确认了导致同类错误的机制：离屏窗口的初始渲染视口仍取决于原生窗口大小。把隐藏窗口的最小尺寸解除、最大尺寸和实际尺寸限制为 1024×768 后，旧实现报告原生窗口、内容区域和 `innerWidth` / `innerHeight` 都是 1024×768，随后抛出同样的 `Unexpected viewport size`。离屏渲染本身没有固定布局视口；现有 `enableLargerThanScreen` 也不能作为跨平台固定视口的保证（本仓库 Electron 类型声明标注该选项仅针对 macOS）。

仅覆盖布局视口仍不够：实测 `capturePage()` 在这个受限窗口上返回 1024×768 的图片。因此最终同时修复布局视口和截图来源，没有放宽断言、缩放图片或填补缺失区域。`captureBeyondViewport` 明确设为 `false`，避免完整页面捕获改变滚动条占位和 Tag 换行。

新增 `--constrain-window` 截图回归参数；Windows/macOS、Node 22/24 的 CI 截图步骤均启用它。截图日志记录每个场景的原生窗口、内容区域、显示器和实际视口。无新增依赖。

协议参考：[设备尺寸覆盖](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setDeviceMetricsOverride)、[截图参数](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-captureScreenshot)。修复效果以以下真实 Electron 运行结果为依据。

## 3. 验证结果

- `npm run format:check`：通过。
- `npm run typecheck`：通过。
- `npm test`：56 个测试文件、349 项测试通过，0 失败。
- `npm run build`：通过（由最终 `npm run screenshots:app` 调用）。保留既有 chunk 超过 500 kB 的提示。
- 旧实现的受限窗口复现：失败，退出码 1，错误为 `Unexpected viewport size`；观察到实际视口 1024×768。
- `node scripts/app-screenshots.mjs --constrain-window`：最终实现通过，导入 14 张样例，生成 22 张 1240×760 PNG，退出码 0，临时目录清理成功。每张截图日志均记录原生窗口 1024×768、渲染视口 1240×760、设备比例 1。
- `npm run screenshots:app`：最终实现通过，生产构建成功，导入 14 张样例（1174 ms），生成 22 张 1240×760 PNG，退出码 0，临时目录清理成功。

复现方法：首次失败复现使用临时 Electron 入口，在真实应用窗口首次 `loadFile` 前调用 `setMinimumSize(0, 0)`、`setMaximumSize(1024, 768)`、`setSize(1024, 768)`，加载原始截图代码并打印实际视口。最终将相同约束收敛到截图模式内部，用 `--constrain-window` 保留可重复运行的回归入口。没有修改本机显示设置，没有模拟键盘或鼠标，没有替换页面或截图场景。后续要对旧代码重现，可在旧 `runAppScreenshots` 的 `createWindow(state)` 后加入上述三个约束调用，再运行原截图命令。

本机为 Windows、Node 24.14.0、Electron 43.1.1，显示器 2560×1440、比例 1。首次沙箱内 Electron GPU 子进程无法启动；同一隔离截图命令在获准的沙箱外环境中正常运行。此环境问题与 CI 的视口断言失败不同。

## 5. 推断清单

- 用限制隐藏原生窗口来代表小屏幕 CI 对窗口大小施加的限制；这是对失败条件的等效复现，不是对 GitHub runner 实际屏幕分辨率的直接测量。
- 用 Electron 内置调试协议固定视口和截图，是本次选择的工程实现方式；任务说明未指定 API。
- 将受限模式用于已有的全部 CI 平台组合，以持续验证截图不依赖原生窗口大小；未扩展 CI 矩阵或修改其他步骤。
- 少量边缘像素的 1–2 色阶差异推断来自渲染/合成取整；可以直接证实的是不同像素位置、颜色差值和布局一致，未进一步将其归因到 Chromium 的某个内部实现。
