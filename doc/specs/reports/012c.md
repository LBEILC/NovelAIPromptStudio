# 012c 工程汇报：名称与批量起名

## 1. 完成内容

- 新增共享纯函数：识别 NovelAI `s-数字`（包括重复序号）、至少 16 位十六进制和 UUID 文件名；用户明确起过的名字即使符合这些形状也保留显示。
- 未起名图片的详情省略标题，导入时间后显示等宽的文件名，中间省略并保留完整悬停提示；动作改为“起名”。大图省略名称，网格及同摞缩略图改用导入时间描述。
- 多选操作条在“加入收藏集”后提供“起名”；详情支持整摞起名和“只改这一张”。共用对话框显示编号预览，空白名称和提交期间禁用确认。
- 按当前排列顺序编号：单张无编号，其他至少两位，100 / 1000 张分别使用三位 / 四位。允许重复名称。完成通知提供恢复原名称的撤销操作。
- 批量起名和撤销均为一个 SQLite 事务；失败全部回滚。保持图片路径及文件内容不变，不增加表或列，不引入依赖。
- 新导入保留完整原始文件名；改名后仍支持按原文件名搜索；另存为根据是否起名选择显示名称或原文件名，并保留原始扩展名大小写。
- 起名验收独立为 `图片库·起名`，同时接入图片库分类和全套 Windows/macOS CI。CI 全套慢模式及文档改为默认 4 倍，定向慢模式保留 6 倍。

## 5. 推断清单

- 单张已有名称预填原名称；未起名或整摞/多选从空名称开始，避免把某一张已有的编号重复套到整摞。
- “只改这一张”默认不选，放在结果预览下方，复用既有 Checkbox 及表单间距。
- 图片超过 999 张时继续按总数的十进制位数编号，不截断编号。
- 首尾空格按已有改名逻辑去除；保留已有 160 字符名称上限（含编号）。撤销允许逐字恢复超过此上限的旧名称和首尾空格。
- 卡片日期使用当前系统时区。另存为沿用跨平台非法字符处理；已有同格式扩展名时不再重复追加。
- 中间省略保留最后 20 个字符，前段根据可用宽度省略；完整文件名始终保存在 `title` 中。
- 为实现“用户起过名之后就算有名字”且不改表结构，显式起名标记使用现有 `app_meta`；新导入的原文件名附加在现有元数据 JSON 中。
- 旧版只存过清理字符后的名称，且图库副本本来就使用 UUID 文件名。无法反推出丢失的原文件名字符；旧记录使用现存名称加图片扩展名作为回退，在首次改名前保存，后续改名不会覆盖。

## 7. 新增断言与自动化没覆盖

新增或扩展的检查包括：

- 两种生成名称形状、扩展名与重复序号、长普通名称不误判、显式起名覆盖形状规则。
- 单张及 2 / 99 / 100 / 999 / 1000 张的编号规则。
- 事务中途失败回滚名称、起名标记及卡片缓存；允许重名；撤销、重开数据库、长旧名逐字恢复；列表和详情逐字 JSON 一致。
- 未起名详情无标题、文件行完整 `title`、长文件名中间省略、真实 IBM Plex Mono 字体、大图无名称、卡片日期无障碍名称。
- 空名称与空白名称禁用确认；起名后标题出现，包含形似 `s-数字` 的用户名称。
- 多选起名入口顺序、六张两位编号预览、按显示顺序而非勾选顺序编号、完成通知、撤销。
- 整摞按缩略图顺序编号、“只改这一张”不影响另一张、一百张真实三位编号。
- 起名对话框在工作区居中；未起名及有名字的另存为默认文件名通过原生对话框替身读取；改名后按完整原文件名搜索。

自动化没覆盖：真实操作系统文件选择器的交互、真实读屏软件播报；使用替身核验文件名参数、使用 DOM 无障碍属性核验描述。macOS 本机未运行；同一新增场景已接入现有 macOS CI，等待设计负责人推送后确认。不新增人工验证任务或 macOS 交接。
