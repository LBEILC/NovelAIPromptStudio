- 保留旧排序、清空回收站、ZIP 框选等操作，使用现有基础组件补齐稿中未展开的状态；没有为这些缺口增加设计令牌。
- 模型和 Vibe 筛选保留旧数据模型的多选语义，以复选项表达；稿中单个选择框无法覆盖旧多选能力。需设计负责人确认最终控件形态。
- 详情宽度使用旧存储键，默认取 `--detail-w`，边界复用已有 `--popover-w` / `--prompt-w`。搜索最小宽度、筛选标签列和 ZIP 容器约束复用已有尺寸令牌，语义是否应有专门令牌待设计后续判断。
- 等高排版采用逐行累加至目标宽度的规则，再按行宽统一缩放；最后一行不放大。窗口化在可见区域上下各保留一个目标行高，兼顾快速滚动。
- 多选以组为单位，批量动作作用于组内全部图片，沿用旧逻辑。大图切换范围为当前摞，没有摞时仅当前图。

- 基础 Prompt 独立复制采用逐字节原文要求；含角色时继续使用工作台函数，详见下一节。
- 列表 Promise 完成即结束整理进度；迟到的完成事件不重新打开进度。展示延迟 300ms，以单元测试核对 299/300ms 边界。
- 图库的跨页面数据库、导入会话和工作台动作继续由 App 调用已有接口；页面偏好、选择、详情和分组派生状态抽到专用 hook，并未另造数据库状态层。

## 6. 实现时核实的结论和证据

### Prompt 复制规则

工作台使用 `formatPositivePromptForCopy`：基础正向 Prompt 在前，角色按原顺序在后；原文含非空白内容时保留原字符串，否则回退为 `formatPromptInline(scope.tags)`。自动内容状态为 `confirmed` 或 `inferred` 时默认取 `automation.cleanedRaw`。过滤最终空字符串，以换行、竖线、换行（`\n|\n`）拼接，不包含排除内容。只有基础 Prompt 时，图库直接复制保存的 `raw_prompt`，包括首尾空白；单元测试覆盖这一特殊要求及多角色路径。

真实验收逐一打开全部 14 张演示图片（包括临时恢复原回收站演示图），点击图库复制和工作台“复制全部 Prompt”，比较传入剪贴板的字符串、现有函数结果和实际系统剪贴板。Windows 系统文本读取可能把 LF 规范为 CRLF，原始字符串仍按字节严格比较，系统读回只对换行作平台规范化。每个排除 scope 单独与保存原文比较。两主题、正常/关闭动效都执行。

### 旧偏好读取

旧缩略图键 `novelai-prompt-studio.gallery-card-size.v1` 的值是宽度。新行高 = `clamp(round(旧宽度 / (832 / 1216) / 20) × 20, 120, 360)`；例如旧默认宽度 190 对应 280。以后仍向原键写入 `行高 × (832 / 1216)`，保留旧单位；无旧值使用 `--thumb-row` 的 180。分组继续使用 `gallery-grouping.v1`，详情宽度继续使用 `gallery-preview-panel-width.v1`。旧排序没有持久化键，本次增加 `gallery-sort.v1`，默认最近导入。

### 5000 张实际界面测量

Windows x64，Node 24.14.0，AMD Ryzen 9 9955HX，约 32GB 内存，1240×760 Electron 离屏/CDP 视口。使用 `benchmark:data-layer` 产生的 5000 张 synthetic 数据快照，保留每图 59 个 Tag 和原大 metadata 负载，在临时副本中给记录分配 14 张真实演示图及 384px WebP 缩略图；没有导入 5000 个不同像素源。原合成数据库约 1.06GiB。

| 指标 | 实测 |
|---|---:|
| 点击图片库到可操作网格（首次缓存） | 6990.6ms |
| 返回工作台后再次打开 | 25.6ms |
| 连续滚动到底最长一帧 | 66.6ms |
| 帧间隔 P95 | 16.7ms |
| 连续滚动帧数 / 最大渲染卡片数 | 563 / 35 |
| 5 次选中到详情更新 | 15.6、17.9、15.9、16.9、33.7ms |

证据：[metrics.json](../../../.codex-runs/library-benchmark/metrics.json) 和同目录 `library-5000.png`。最长帧并非稳定 60fps 的保证；此结果只代表上述负载和环境。

另把同一临时数据扩展至 20000 张，保留完整 Tag/metadata 负载，成功打开并定位 index 19999，最多渲染 25 张，5 次详情更新均在 25.8ms 内。首次打开含缓存耗时 96711.4ms，再次进入 38.6ms。该轮与其他验证有资源竞争，作为可打开性证据，不和 5000 张独立测量直接作吞吐比较。[20000 张证据](../../../.codex-runs/library-benchmark/20000/metrics.json)。

复测脚本只接受带 `{kind:"synthetic-data-layer",count:5000}` manifest、项目名全部为 `Synthetic ` 的合成快照。默认读取 `.codex-runs/012/benchmark-fixtures/fixture-5000`，可通过第一个位置参数指定其他合成快照。新快照可用 `scripts/data-layer/worker.mjs seed node:sqlite <独立目录> 5000` 生成，再写入上述 `fixture.json`；源数据库只读，UI 运行只修改临时副本。

### 剪贴板与关于截图

保留标准格式后只恢复写入一次，立即核对；若失败，最多 10 次、每次间隔 25ms 重读。检查 JSON 保存原始/写入前/写入后各格式的字节数和 SHA-256，不保存原文。单元测试模拟读回延迟和空剪贴板恢复。本次最终双主题的 6 次恢复均 `immediate:true`，没有重现偶发失败；不能据此断言已确定 010c 偶发失败的唯一原因。

“关于”页字体探针核对后、拍摄前移除；新截图不再包含 `blue_hair 1.25`。
