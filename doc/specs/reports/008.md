# 008 字体随包：工程汇报

日期：2026-10-11。角色：工程负责人。分支：`rebuild/ui-1.0`。改动前基准：`26e165d`。本报告随实现提交；按派发任务规则只提交、不推送。

## 1. 完成了什么

- MiSans VF 4.003 从小米官方下载页取得，固定 SHA-256，缓存于被忽略的 `.local/fonts/MiSansVF.ttf`。Vite 原样带入构建产物，开发服务器也只提供校验通过的字节。没有转换、子集化或新增字体二进制到 Git。
- 注册 MiSans 及设计令牌已使用的 `NPS MiSans`、`MiSans VF` 别名，三个声明共享同一个文件。全部字体声明使用 `font-display: swap`。
- 引入 Newsreader 拉丁可变字体（保留 `wght`、`opsz`）与 IBM Plex Mono 拉丁 400 / 500；移除三个旧 `@lobehub/webfont-*` 依赖与声明，旧界面改用设计令牌中的后备字体。
- 缺失／损坏 MiSans 时，开发和普通构建输出一行警告并使用后备字体；`npm run package` 在构建前拒绝，electron-builder 的 `beforePack` 再检查缓存和构建产物，避免直接调用 builder 发布旧的无字体构建。
- 默认字体、内置选项顺序与标注、旧设置的条件回退、段落字体令牌应用均已接通。设置读取不重写原偏好；保存外观时保留其他偏好字段。
- 关于页加入指定署名和三份完整许可，打包继续利用已有 `extraResources` 复制到 `resources/LICENSES/`；替换无备份文案，README 加入获取命令。
- CI 和 release 加入固定版本缓存、字体获取、严格检查；CI 在 Windows / macOS 的 Node 22 / 24 矩阵增加目录打包与字体、许可内容检查。release 校验所有生成的 macOS 架构目录。

## 5. 推断与实现选择

1. 三个字体下拉框都先列出三种内置字体，顺序为 MiSans、IBM Plex Mono、Newsreader，再保留原有系统字体的分类方式；不是只在对应角色中列出一种内置字体。
2. 系统字体枚举失败表示“未知”，此时保留旧选择，不能将失败误判成未安装。下一次启动枚举成功后再按实际结果解析。
3. 字体兼容在读取层解析，不在启动时写回旧偏好；用户下一次保存外观时才保存解析后的值，其他数据不动。
4. 使用设计令牌已有的 MiSans 别名注册同一资源，使段落和等宽中的中文也能正确回退，无须改动设计文件。
5. 原实现保存段落字体但未应用。为满足字体设置作用于界面的要求，接通 `--font-prose`，已有关于页名称也会跟随该令牌。
6. 当前旧工作台没有自然语言段落块。应用截图检查实际导航、Tag 和关于页名称，另在截图进程内复用 `.nps-quote` 和真实字体令牌生成中英文段落样张。样张不属于生产组件、不写入用户设置或业务数据。
7. CI 获取失败时使截图检查失败，不生成后备字体的“成功”截图，避免提供错误的视觉验收依据；详细行为见下节。

## 6. 实现时核实与问题回答

任务无单独标记的【实现时核实】条目；以下对其验收要求提供实测证据。

**获取脚本的复用和站点变更。** 只读参照 DispatchDock，复用了固定哈希校验、读取官方下载页及同域脚本、识别直接链接／动态下载目录、ZIP 中央目录解析、HTTP Range 获取所需条目、Deflate 解压，以及单包版本不符时检查官方全量嵌套包的逻辑。新增缓存命中校验、项目内缓存路径和严格检查入口；没有修改 DispatchDock。许可原文从该项目完整复制，并与[小米官方下载页](https://hyperos.mi.com/font/download)显示的协议核对。此次单独 MiSans.zip 的版本已变化，脚本实际从 `https://hyperos.mi.com/font-download/MiSans_Global_ALL.zip` 获取指定版本。页面结构无法识别、网络失败、指定条目消失或所有候选文件哈希不符时明确失败，不猜测地址、不接受新版本。

**CI 下载失败。** 缓存键包含版本和完整哈希，每次使用仍重新校验。有效缓存命中无需联网；无有效缓存且下载失败时，CI 获取步骤失败，后续截图和打包不执行。release 同样失败，不上传无字体安装包。即使绕过下载步骤，打包入口和 `beforePack` 仍拒绝缺失／不符的字体。缓存使用 [actions/cache](https://github.com/actions/cache) 的 v5，沿用 GitHub 托管 runner。字体缓存不作为独立发行附件上传。

**字体轴与真实渲染。** 对字体二进制的 `fvar` 表进行只读解析：MiSans `wght=150..700`；Newsreader `wght=200..800`、`opsz=6..72`，CSS 对外使用 400–500。没有修改原字体。证据在 `font-axes.json`。

截图通过 CDP `CSS.getPlatformFontsForNode` 检查实际绘制字形，要求 `isCustomFont=true`、`glyphCount>0`，不是只检查 `font-family` 声明。`manifest.json` 中导航为 `MiSans VF`，工作台 Tag 为 `IBM Plex Mono / IBMPlexMono-Regular`；段落样张为 `Newsreader 16pt`，其中中文由 `MiSans VF` 绘制；500 样张为 `IBMPlexMono-Medium` 和 Newsreader 的 Medium 实例。浅色和深色均通过；`fonts-light.png`、`fonts-dark.png` 为样张。20 张应用截图的导航字体也逐张校验。

**已有设置兼容。** 启动枚举系统字体并传给 preferences。先按既有规则规范旧别名 `geist`、`geist-mono`、`harmony`，再仅对三种移除字体按不区分大小写的名称匹配：确认系统没有时按字段回退到新默认值；已安装时保留。其他自选字体即使缺失也不重置，通用字体保持不变。新增测试覆盖三种名称、三个旧别名、三个字段、系统已安装、枚举未知、自选／通用字体、读取不写盘以及保存外观不改动其他偏好。前后体积见第 3 节。
