# 010b 词典变化与首次建立缓存工程汇报

## 1. 完成内容

`loadLibraryCards()` 的持久缓存改为保存与词典无关的精简输入。译文、分类和相似度权重按当前词典在内存中派生，共享同一 Tag 输入的计算结果；词典变化不会再删除、重写全部卡片，也不会重新读取图片的完整元数据。原有卡片字段、详情接口和分组语义不变。

首次建立采用最多 25 张、约 12 ms 工作预算的短事务，事务之间通过 `setImmediate` 让出主线程。多个列表请求等待同一建立任务；批次之间允许写入，一轮处理后重新检查脏标记，完成前再核对词典。只在完整结果可用时返回列表。新增只读进度事件，未增加界面或依赖，数据库仍在 Electron 主线程运行。

所有测试、基准和真实旧引擎验证均使用临时目录或合成样本副本。未使用日常图库，未操作其他项目的进程。提交保留在 `rebuild/ui-1.0`，按工程派工规则不推送。

## 5. 推断清单

- 选择保存词典无关输入，而不是用词典 Tag 索引逐图删除持久缓存。输入保留原始译文、分类来源、权重及负面词修复需要的内容，词典删除后能回到图片原值。
- 相同 Tag 输入共享丰富后的筛选项及相似度键值对；重复权重仍取最大值，继续复用既有分类、规则推断和遗留负面词修复算法。
- 相同 Prompt 输入序列共享完整筛选项数组和相似度对象，减少重复计算及 IPC 克隆。缓存编码只省略可恢复的尾部默认值；非有限权重仍保留原算法的截断语义。
- 派生版本升级为 `5:dictionary-independent-columns`。遇到 010a 的旧缓存时丢弃该派生表并重建；没有增加表或改变原始业务表与图片文件。长指纹直接存入缓存表的独立列，避免冷读取时再次解码其 JSON 转义。
- 每批最多 25 张，并在工作超过约 12 ms 后停止继续取下一张，为事务提交、进度通知及事件循环留出时间。最后的 IPC 回复也与建立工作分开到新的事件循环轮次。
- 已有缓存按每次 100 行读取，累计约 48 ms 解码工作后让出主线程，避免过密调度拉长冷读取。完整快照生成后再让出一次，保证热读取和 IPC 回复克隆不叠加在同一轮次。
- 进度计数包含回收站图片，因为同一次建立服务 `all`、`favorites`、`trash` 三个视图。期间导入、删除或修改时计数可重新核对，不承诺总数固定或中间完成数单调增长。
- 事件反映持久缓存的建立；空库、已有缓存的读取及仅词典内存派生更新不产生建立进度。是否加载完成仍以列表 Promise 为准。
- 主进程向当前应用窗口广播事件，preload 按项目既有事件方式提供订阅和取消订阅；没有增加渲染器写入缓存的接口。
- 内部数据库方法变为 Promise；原有公开 IPC 本来就返回 Promise，外部接口的完整列表含义保持不变。

## 6. 实测及任务问题答复

### 词典变化的处理与耗时

每次读取核对词典的语义字段，保留未变化条目的对象身份；时间戳和展示名不参与比较。只有引用了变化条目的输入重新丰富，只有受影响卡片重新组装筛选项及权重。更新不写派生表，旧引擎直接修改词典也能在下次读取时被发现。基准包括写入本身及随后的完整列表读取。

单位为毫秒，均包含本次词典写入及随后的列表返回。

| 场景 | 5000 张 | 20000 张 | 5000 张阈值 |
| --- | ---: | ---: | ---: |
| 仅一张图使用的 Tag，修改译文 | 37.25 | 116.61 | 400 |
| 同一稀有 Tag，修改分类 | 33.36 | 100.24 | 400 |
| 八成图片使用的 `1girl`，修改分类 | 39.95 | 121.71 | 1500 |
| 导入 200 条，其中 20 条被图片使用 | 45.11 | 127.48 | 1500 |
| 仅时间戳、展示名变化 | 35.82 | 122.38 | 100（额外耗时检查） |

最后一项的“不重算”同时由单元测试检查：语义快照不变，不重读元数据或 Tag 表，不重写持久缓存。基准另有实际使用数断言：两档唯一 Tag 均为 1 张，常见 Tag 分别为 4000/16000 张，批量导入均有 20 条被使用。

样本每图仍为 59 个 Tag，`extra_json` 平均 62 KiB、峰值 271 KiB，结构平均 21 KiB、峰值 41 KiB。把 `image-0` 的一个 Tag 替换为 `benchmark_unique`，并把每五张中的四张的一个 Tag 替换为 `1girl`；总 Tag 数不变。导入场景的前 20 条为图库已使用的 `synthetic_0` 至 `synthetic_19`，其余 180 条未使用。脚本对这些分布有断言。复用 010a 样本时只修改新的临时副本。

阻塞探针测量相邻事件循环轮次间的实际墙钟间隔，包含同步 SQL、提交、JS 和 GC；Electron 探针继续覆盖最后一次结果回复的结构化克隆，不把异步调用总耗时当作单次阻塞。Node 测首次无缓存调用；Electron 在独立窗口完成已有缓存 IPC 测量后删除派生表，再测完整建立过程及其他请求响应。

生产应用验收使用构建后的正常渲染器和隔离演示 profile。建立过程中通过 DOM 点击打开设置页，并断言另一个主进程请求在列表完成前成功返回；同时断言多个视图请求都拿到完整结果。截图来自同次运行。

### 建立期间写入与中断

每个批次独立事务提交。项目、Tag、元数据及展示字段变化沿用持久触发器留下卡片脏标记；卡片保存与该图片标记的清除在同一个事务内完成，失败一起回滚。批次之间不持有事务，因此导入、改名、删除和词典修改可以正常执行。

一轮建立完成后重新消费脏标记并查缺失卡片，已经处理过的图片若又被修改就再计算；完成前再次同步词典并检查标记，之后才解析等待中的列表请求。词典不进入持久投影，因此不可能把分批期间的旧词典结果永久保存。

关闭或崩溃后，已提交批次可保留；未提交批次由 SQLite 回滚，缺失行及脏标记驱动重做。若启动指纹修复要求失效，则安全重建相应派生结果。测试覆盖普通关闭、已提交批次后强制杀掉本测试子进程、批次事务内强制终止，并检查完整性及与清空缓存后重算的逐项一致性。

## 7. 新增断言与自动化没覆盖

- 词典更新不读取元数据或原始 Tag 表、不重写持久卡片，完整派生结果仍一致。
- 不同视图的并发请求等待同一建立过程，未变图片只建立一次。
- 批次间导入、改名、移入回收站、永久删除、改 Tag 权重和改词典，完成后与全量重建逐项一致。
- 建立中关闭可恢复；已提交批次和未提交事务两个强制中断点均可恢复，SQLite 完整性检查通过。
- 010a 旧格式缓存可安全替换，原始内容与公共卡片值保持一致。
- 强化原有测试：筛选 Tag 和正负面相似度键值对直接逐项比较，包含空负面词的遗留语义。
- 旧 SQLite 数据中的正负无穷权重，编码后仍与完整读取的权重截断结果一致。
- 合成样本的唯一 Tag、八成 Tag、导入 200 条中实际使用 20 条均有检查。
- 真实应用新增三项断言：建立期间设置导航及主进程响应、并发完整视图、进度字段及最终计数。两套验收运行共新增 6 条。
- 5000 张基准包含带阈值的首次建立阻塞和所有词典场景；保留 010a 原有目标，并把热读取阈值设为本任务要求的 100 ms。

本机 Windows 自动化覆盖本任务要求的行为；没有新增需要用户手动操作的验收项。既有 CI 的 Windows/macOS × Node 22/24 矩阵会执行新增单元断言和生产应用验收，性能基准在本机运行。本次未推送，因此没有本提交的远端 macOS 运行结果。本任务不涉及系统级拖窗或原生文件对话框的改动。
