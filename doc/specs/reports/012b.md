# 012b 工程汇报：CI 动效失败与慢测试

角色：工程负责人。分支：`rebuild/ui-1.0`，基于已合入的 012a（`782a2b0`）及任务派发提交 `f811636`。只提交，不推送。

## 1. 完成了什么

修复“完整”被系统减少动态效果覆盖的问题，并补齐真实应用的动效组合验收。缩小两项慢测试的准备工作，为四项涉及真实磁盘／子进程的测试单独设置超时，未放宽全局超时。

### 动效根因与复现

`src/ui/ThemeProvider.tsx` 原来用 `motion === 'off' || reduced.matches` 决定关闭动效，未判断用户是否选择“跟随系统”。另外 `src/ui/ui.css` 的减少动态效果媒体查询也无条件关闭组件过渡。现在只有“跟随系统”受系统偏好控制；“完整”保留动效，“关闭”始终关闭。状态和 CSS 两层同时修复。

使用 010c 的 `checkSoon` 失败说明，在修复前构建上验证了两条路径：

| 复现条件 | 保存后读回 | 页面 `dataset.motion` | `matchMedia('(prefers-reduced-motion: reduce)').matches` | 结果 |
|---|---|---|---|---|
| 验收进程启用系统减少动态效果，前面的 CDP 模拟正常撤销 | `motion: full` | `off` | `true` | 图片库第一步超时，与任务描述一致 |
| 保留 CDP 的 `reduce` 模拟，再选择完整并刷新 | `motion: full` | `off` | `true` | 完整模式及刷新后的断言均失败；组件过渡实际为 `1e-05s` |

证据：`.codex-runs/012b/repro-system.log`、`repro-cdp-matrix.log`、`repro-cdp-manifest.json`。诊断记录包括完整外观设置、有效动效、系统偏好和按钮实际过渡时长。

旧脚本正常路径确实发送了 `features: []`，但这只恢复宿主偏好，不保证恢复为“无减少动态效果”。本机普通环境的旧构建单主题完整验收通过 388 条，因此旧验收没有暴露问题：它仅在“跟随系统”下测试 `reduce`，没有测试 `reduce + 完整`；原组件单元测试甚至要求完整模式跟随减少动态效果，现已修正。历史 CI 日志未记录系统偏好，不能事后确定当时 `reduce` 来自宿主还是模拟残留；两种触发条件均已本机复现并纳入回归。

### 四项慢测试

本机为 Windows、Node `v24.14.0`。下表为全量测试中的单项耗时，CI 数值来自任务说明中的 Windows + Node 22 失败运行；不是相同硬件／Node 版本的性能对比。

| 测试 | 本机修改前 | CI 修改前 | 本机修改后 | 改动 |
|---|---:|---:|---:|---|
| Tag 搜索、筛选、编辑、分页、删除 | 0.060 秒 | 6.5 秒 | 0.074 秒 | 仅三行数据，保留每个真实读写操作；单项超时 20 秒 |
| 固定旧文件的表、行、图库数据兼容性 | 3.043 秒 | 6.2 秒 | 3.395 秒 | 保留固定旧文件、两份逐字节备份、逐表比较和重开；单项超时 20 秒 |
| 合成库的 Prompt CLI 只读检查 | 0.421 秒 | 14.9 秒 | 0.350 秒 | 建表与 9 次插入合为一个事务，保留五张图片、全部隐私及只读断言和真实 CLI 子进程；单项超时 30 秒 |
| 生产路径建库、21 张表与孤儿记录兼容性 | 0.340 秒 | 9.9 秒 | 0.216 秒 | 兼容性 fixture 去掉无语义 JSON padding，词典／Danbooru 缓存准备规模由 2400／750 改为 3／3；保留 3 张图片、每张 59 个 Tag、3 条孤儿元数据、21 张表逐行比较、完整性校验和重开；单项超时 20 秒 |

分析依据：数据库使用 `journal_mode=DELETE`、`synchronous=EXTRA`、`fullfsync=ON`，上述测试涉及实际建库、同步写盘、备份和重开；CLI 还启动独立 Node 进程加载 TypeScript。共享 CI 的磁盘／进程启动竞争会放大这些成本，默认 5 秒不适合这几项集成测试。没有 CI 的分段 I/O 或 CPU 跟踪，不能把差距进一步归因于某种磁盘、杀毒软件或 Node 版本；这些只是可能因素，不作为已证实结论。固定旧文件和仅三行的 Tag 测试没有可以安全去掉的关键工作。每个超时旁均写明原因。基准测试的默认 fixture 规模完全保留。

耗时原始数据：`.codex-runs/012b/before-tests.json`、`after-tests.json`。

## 5. 推断清单

- 用 Chromium `force-prefers-reduced-motion` 作为进程级系统偏好的模拟，不改本机系统设置。与 CDP 临时模拟分开，启动断言确认媒体查询为真，撤销 CDP 后再次确认恢复基线。
- 兼容性测试需要覆盖表、字段、孤儿及重开语义，无需重复性能 fixture 的填充字节和数千条缓存；因此仅 opt-in 的 `compact` fixture 缩减这些内容。
- 20／30 秒为单项 CI 容量余量，依据任务中的最坏耗时及保留的工作量选择；不是性能目标，后续 CI 耗时仍需实际确认。

## 6. 实现时核实

任务没有单独标记【实现时核实】的条目；要求的两种错误条件、保存读回、实际 CSS 时长和四项本机耗时均已实测，证据见第 1、3 节。

其他验收对系统环境的依赖也已检查：

- 主题：通过 `nativeTheme.themeSource` 显式驱动 light/dark，最后恢复；不假定本机主题。
- 动效：本次矩阵显式驱动两个媒体查询值，撤销后核对实际基线；额外整轮减少动态效果覆盖后续图片库、设置、组件和重启流程。
- 字体：使用内置字体并通过 CDP 核对实际绘制的自定义字体，不要求机器预装 MiSans。
- 安全存储：仍取决于 `safeStorage.isEncryptionAvailable()`，不可用时已有明确的未覆盖记录，不伪装为通过。
- 显示缩放在验收进程固定为 1；最大化依赖桌面工作区，使用实际窗口状态和相对布局断言。平台修饰键按系统选择，剪贴板保存后恢复。未发现其他把某个系统偏好值当作固定前提的验收等待。

## 7. 新增验收断言；自动化没覆盖

新增／替换的真实应用断言：

1. 系统减少动态效果关闭／开启 × 完整／跟随系统／关闭，共六种组合：同时核对保存值、有效动效和按钮实际过渡时长。
2. 保留 CDP `reduce` 模拟并刷新，完整设置仍生效。
3. `finally` 撤销模拟后媒体查询恢复进程的原始系统偏好。
4. 图片库完整／关闭入口分别检查有效动效；失败说明记录保存设置、媒体查询、页面模式及实际过渡。
5. `--reduced-motion` 每次启动（含重启阶段）在尚未使用媒体模拟时确认系统减少动态效果为真。

单元测试覆盖三种模式对实时系统切换的反应，以及验收启动参数启用／不启用两种配置。

自动化没覆盖：未操作 Windows 设置应用／注册表中的真实全局开关；使用与应用媒体查询相连的进程级偏好模拟。没有在本机运行 macOS 或 Node 22。原生标题栏拖动、原生文件选择器实际外观、系统外快捷键等仍属于现有 harness 不覆盖的范围；本次没有新增这些功能或要求用户手动检查。

## 8. 偏离说明

无功能范围偏离。系统减少动态效果通过进程级模拟验证，不改用户全局环境。为避免再次仅在开发机通过，把额外整轮验收同时加入了四种 CI 组合。
