## 5. 推断清单

- 两主题采用两个独立临时目录，各自运行完整流程，顺序执行，避免真实剪贴板并发污染。每个主题再用同目录启动两次，分别验证自定义配置和恢复默认配置。
- 组件展示页单独生产构建到临时目录，在同一个真实 Electron `webContents` 加载，不使用 Vite 开发服务器；不向产品渲染器注入测试桥。
- 用 DOM 事件驱动应用处理器；浏览器默认 Tab、Esc、Space、range 和指针捕获通过 CDP 送入当前页面，不模拟操作系统输入。
- 默认三字体使用产品中的真实元素及一个临时采用 `--font-mono` 的可见文本探针，通过 CDP 判断实际字体且要求来自自定义字体。字体更换选择已随包的其他字体，以便跨平台确定可用；没有穷举系统字体。
- 准备演示库、收藏、回收站和 205 条词典时可调用真实数据接口；后续用户操作走真实界面与 IPC，重启逐项比较完整序列化内容。
- 没有验收参数时以单元测试证明不会安装替身、修改路径或加速配置，已有 preload VM 测试证明普通渲染器没有截图桥；不启动用户日常 Profile 来验证这一点。
- 更新结果固定为本地 `99.0.0` 发布说明；AI 服务使用回环地址、固定模型和假 Key；安全存储使用 Electron 真接口。
- 打包使用 electron-builder 的 unsigned directory 模式，不安装软件。保留原 `screenshots:app` 命令。

## 6. 实现时核实与隔离证据

任务没有单列【实现时核实】条目，以下为关键本机实测：

- **真实运行**：普通验收构建正式应用；打包验收检查 `app.isPackaged` 和页面 URL 位于包内，真实打开 SQLite、导入 14 张演示 PNG、绘制页面。
- **字体**：CDP 返回 `MiSans VF`、`IBM Plex Mono`、`Newsreader 16pt`，`isCustomFont: true`。浅深包内页面均通过；禁止外部 HTTP 请求仍正常渲染。
- **替身限定**：只有 `--verify-app` 指向 `os.tmpdir()` 直属、带 `nai-acceptance-` 前缀和 owner 标记、非符号链接的目录才启用。四个 Electron 用户路径均定向其中。没有参数直接返回 `null`，正常接口保留，测试覆盖。
- **文件对话框**：仅验收模式替换主进程方法，用显式队列返回路径或取消；无预定响应就报错。shell 外部打开只记录。更新分支和自动更新禁用都受同一模式限制。
- **AI**：独立 Node runner 启动本机 OpenAI 兼容服务，支持成功、503、超时三种状态；实际场景测试成功、503 和重试。没有真实账户调用。
- **安全存储**：本机可用，真实加密保存并重启验证。若某 CI 平台不可用，仅相关 Key 检查写入 `uncovered` 及原因，其余 AI 检查继续。
- **剪贴板**：真实 Electron 接口，标准 text/html/rtf/bookmark/image 一次性恢复并比较；私有格式会在写入前报错，不静默丢弃。每阶段恢复检查均通过。
- **窗口**：通过 `BrowserWindow` 进入最大化并确认状态、计算元素边界；主题切换记录真实 `setTitleBarOverlay` 调用参数。macOS 不具备 Windows 标题栏覆盖层参数检查，其他主题与几何检查保留。
- **网络**：页面会话拒绝回环假服务之外的 HTTP 请求并断言没有外部请求；主进程 AI 地址是测试服务，更新请求被模式分支替代。

## 8. 偏离说明

- 应用全通过及故障恢复后全通过两条验收标准未满足，原因是发现既有动效实现不符合零时长要求，修复又超出“不改产品行为和外观”的约束。不得以 338 项通过替代整体验收通过。
- 菜单 Tab 保留 004 规则；009 的循环要求待设计裁决。其他浮层与模态对话框循环已实现检查。
- 按角色要求采取保守实现并记录未覆盖变体，未调整交互、样式、文案或令牌。新增对产品入口的修改只在显式验收模式生效。

## 9. 已知问题

- 当前 `verify:app` 及接入它的 CI 会因四条真实动效断言失败而返回非零；后续成功依赖该问题获准修复，不能用于宣告发布验收已通过。
- 验收对 DOM 类名、可访问名称和演示夹具有依赖；迁移时需要同步场景定位，不能仅删除失败检查。
- Windows 本机通过不能替代 macOS CI 结果；尚未推送。
- 包含私有格式的剪贴板会使验收在写入前停止，当前工具无法保证这种格式的无损恢复。
