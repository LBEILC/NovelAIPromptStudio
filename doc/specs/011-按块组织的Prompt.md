> 阶段：[重构计划](../rebuild-plan.md) 阶段 4，图片库详情和工作台迁移的前置
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：[设计文档](../design.md) 2.1 节（"Prompt 是由块组成的文档"和"分块和判断的规则"）、[V5 调研](../research/novelai-v5.md) B 节

## 目标

在 `src/lib/` 里实现一个纯逻辑模块（TypeScript，不依赖 React 和 Electron），把一段 Prompt 文本解析成由"块"组成的文档，并能原样写回。之后图片库详情栏和工作台都用它显示和编辑 Prompt。

这个任务只做逻辑和测试，不改任何界面，不改数据库。

## 文档模型

- 一份 Prompt 文档分为：基础 Prompt、各个角色 Prompt、各自的排除内容。来源和现在 `src/lib/promptStructure.js` 能读出的结构一致。
- 每一部分由若干**块**组成，按出现顺序排列。块有两种：
  - **Tag 块**：一组 Tag。每个 Tag 的解析（权重、花括号和方括号、`数字::…::` 权重组、语法提示）**必须复用现有的 `src/lib/prompt.js`**，结果与现在完全一致。
  - **段落块**：一段自然语言，作为整体保存原文。
- 块可以带一个**标签**：块开头形如 `Rossi:`、`Panel 1:`、`<style>` 的一小段。标签单独保存，后面的内容再判断类型。
- 每个块记录它在原文里的范围，以及块与块之间的分隔原文（空行、多余空白、换行符种类）。

## 分块与判断的规则

照设计文档 2.1 节实现：

1. 按空行分块（一个或多个只含空白的行都算一处分隔）。
2. 识别块开头的标签。
3. 判断类型：有句末标点并有较长分句，是段落；含成段的中文，是段落；逗号分隔、每项都短，是 Tag 块；`数字::…::` 整组算一项；逗号分隔的描述性短语按 Tag 块处理。**拿不准时当作段落。**
4. 接受一个"用户指定类型"的输入（按块的原文或范围对应），有指定时不再自动判断，用于"用户改过的类型要记住"。

具体的阈值由你决定，写成命名清楚的常量，并在汇报里说明取值理由。

## 硬性要求

1. **原样写回**：对任何输入（包括奇怪的空白、Windows 换行、连续空行、行尾逗号、多余的 `::`），解析后不做任何修改直接写回，结果与原文**逐字节相同**。用基于属性的测试（随机生成大量输入）证明。
2. **V4 / V4.5 不变**：一段没有空行的普通 Tag Prompt，解析结果是一个 Tag 块，其中的 Tag 与现有 `parsePrompt` 的结果逐项相同。用现有测试里的全部样例，以及仓库里 `demo/promo-v090/final/` 演示图片的 Prompt 验证。
3. **最小改动**：修改一个 Tag 的权重、删除一个 Tag、修改一个段落、改变块的类型后写回，只有相应位置的文字发生变化，其他位置逐字节不变。
4. **复制语义不变**：现有"复制可见 Prompt""复制全部 Prompt（含或不含 NovelAI 自动 Tag）"等复制结果，在块模型上算出来与现在逐字节相同。

## 测试数据

**不要使用任何真实用户的 Prompt 作为测试数据。** 仓库是公开的。按下面列出的写法自己构造合成样例，内容用中性的描述（风景、物品、原创角色名），覆盖：

- 第一段是一串带权重的风格与画师 Tag，包括 `1.3::artist:xxx::`、负权重 `-2::flat color::`、`{}` 和 `[]` 强调；
- 空行之后是多段英文自然语言，分别描述主体、构图、场景；
- 段落和 Tag 之间夹着一行普通 Tag（例如 `1girl, solo, 原创角色名`）；
- 带标签的块：`角色名: 描述……`、`Panel 1: …`、`Panel 2: …`、`<style> …`；
- 整段中文描述；
- 用逗号分开的描述性短语（例如 `quiet afternoon light, warm interior, soft focus background`）；
- 怪异的空白：连续多个空行、只含空格的行、行尾逗号、`\r\n`。

### 真实图库的只读检查脚本

另外提供一个命令（不进 CI），接受一个数据库文件路径，只读打开，对其中每张图的 Prompt 跑一遍解析，**只输出统计数字**：图片数、按模型分组的块数分布、各类型块的数量与占比、带标签的块数、原样写回失败的数量、V4/V4.5 单块结果与 `parsePrompt` 不一致的数量。**不输出任何 Prompt 文字、文件名或路径**。设计负责人会用它在真实图库上检查，你不要自己去读用户的数据目录。

## 不做

- 不改界面、数据库、IPC。
- 不做段落翻译（那需要 AI 服务，属于后面的任务）。
- 不做"用户指定类型"的持久化存储，只提供输入参数。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 全部通过。
2. 上面四条硬性要求各有测试；原样写回的属性测试至少跑 2000 个随机输入。
3. 只读检查脚本在合成数据库上跑通，输出里没有 Prompt 文字（有测试证明）。
