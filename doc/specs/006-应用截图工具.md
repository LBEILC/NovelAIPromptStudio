# 006 应用截图工具

> 阶段：[重构计划](../rebuild-plan.md) 阶段 0 遗留的验收工具，阶段 4 的前置
>
> 执行者：工程负责人

## 目标

提供一条命令，在一个隔离的环境里启动**真正的应用**，把各个页面和状态存成图片。之后逐页迁移界面时，设计负责人靠这些图片验收，CI 也靠它确认应用在 macOS 上能启动、能打开数据库、能渲染。

按 `AGENTS.md` 的规定：这个脚本不能模拟鼠标和键盘，用 Electron 自带的截图接口。

## 范围

### 1. 隔离的环境和数据

- 每次运行都用一个全新的临时数据目录，结束后清理。绝不使用默认的数据目录，也不使用本机已有的 `demo` 环境。实现方式可以沿用现有的 `--profile` 机制，也可以用专门的参数指定数据目录，由你决定并说明。
- 数据由脚本自己准备：把 `demo/promo-v090/final/` 里的 14 张图片通过产品自己的导入逻辑导入，再建一个普通收藏集和一个智能收藏集，把一张图移入回收站。不要手写数据库内容。
- 在工作台里打开其中三张图片，让工作台有多个标签。

### 2. 不靠模拟输入来切换页面和状态

应用需要一个**只在截图模式下存在**的入口，让脚本可以直接指定：当前页面、深浅主题、选中哪张图、设置页的哪个分页、动效是否关闭。

- 这个入口只有在带着专门的启动参数时才存在。正常启动的应用里不能有它，也不能通过界面触发。给出证据。
- 截图时关闭动效，等字体和图片加载完成后再截，保证同样的输入得到同样的图片。
- 窗口大小固定为 1240×760。

### 3. 要截的画面

浅色和深色各一套：

| 文件名 | 画面 |
|---|---|
| `workbench` | 工作台，三个标签，当前标签有 Prompt |
| `workbench-empty` | 没有打开任何图片的工作台 |
| `gallery` | 图片库，全部图片，选中一张，详情栏打开 |
| `gallery-collections` | 图片库，收藏集面板打开 |
| `gallery-trash` | 回收站 |
| `settings-*` | 设置的每一个分页各一张 |

页面清单写在一个容易修改的地方：界面迁移后页面和状态会变，届时由后续任务更新。

输出到 `.codex-runs/screens/`（不进 git），并附一个清单文件，记录每张图对应的页面、主题和所用的应用版本。

### 4. 命令与 CI

- `npm run screenshots:app`：先构建，再截图。
- 加进 CI，在 Windows 和 macOS 上都运行，把图片作为产物上传。任何一个画面截取失败、或者页面里出现未捕获的错误，命令都要以失败结束。
- 截图用的是构建后的应用（不是开发服务器）。

## 不做

- 不改任何页面的外观和行为。
- 不做图片之间的自动比对，这次只负责产出图片。
- 不模拟鼠标、键盘。
- 不使用用户的真实数据目录。

## 验收标准

1. `npm run screenshots:app` 在本机一次跑通，产出上表全部画面的浅色和深色版本。
2. 连续运行两次，同一画面的两张图片完全相同，或者逐条说明不同的原因。
3. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 全部通过。
4. 证明正常启动的应用里不存在截图入口。
5. 运行前后，默认的数据目录没有被读写：说明你是如何确认的。

## 汇报要回答的问题

2. 截图入口是怎么限制在截图模式下的？
3. 在没有显示器的 CI 上能不能跑？macOS 上有没有需要额外处理的地方？
4. 哪些画面因为现有代码的限制没法直接切换到，你是怎么处理的？
5. 准备数据（导入 14 张图）用了多长时间？更换数据引擎之后这个时间有没有变化？
