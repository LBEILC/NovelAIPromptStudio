# 009a CI 上验收断言不稳定、macOS 仍然下载不到 MiSans

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：CI 运行 38128087308（提交 `bb15346`）。四个组合里只有 Windows + Node 24 通过。

## 现象

| 组合 | 失败的步骤 | 原因 |
|---|---|---|
| macOS + Node 22 | `npm run fonts` | 官网全量包重试 4 次都是 `SocketError: other side closed` |
| macOS + Node 24 | `npm run verify:app` | `[基础组件·light]` 和 `[基础组件·dark]` 的"滚动立即关闭提示"断言为 false |
| Windows + Node 22 | `npm run verify:app` | `[基础组件·light]` 的"滚动立即关闭提示"断言为 false（dark 通过） |

本机和 Windows + Node 24 上同一条断言是通过的，所以它是时序问题。

## 范围

### 1. "滚动立即关闭提示"

`electron/acceptance/componentDetails.js` 里派发 `scroll` 事件后立刻断言提示已经不在页面上。提示的关闭要等 React 完成一次渲染，下一次 `executeJavaScript` 不保证排在它后面。

设计上的定义（已定）：**"立即"指滚动事件之后 100 毫秒内提示从页面上消失，不播放退出动效。** 按这个定义改断言：在 100 毫秒的期限内等待提示消失，超时算失败。产品代码不改；如果你发现产品在 100 毫秒内确实关不掉，停下来写进汇报。

### 2. 排查同类写法

把验收脚本里所有"触发一个事件或状态变化之后，不等待就直接断言结果"的地方找出来，逐条判断会不会有同样的问题。会的改成带期限的等待，期限写成命名清楚的常量；不会的在汇报里说明为什么。等待的期限要短（界面反馈类不超过 200 毫秒），不要用加长超时来掩盖真正的慢。

改完后在本机连续跑 5 次 `npm run verify:app`，5 次都是 0 失败，把每次的通过数和耗时写进汇报。

### 3. macOS 运行器不再自己下载 MiSans

008a 加了重试和跨平台缓存，但缓存没命中时 macOS 运行器还是要自己去官网下载，而它连官网的全量包一直不稳定。

把 `ci.yml` 和 release 工作流改成：先由一个单独的任务（在能稳定下载的运行器上）负责"恢复缓存，没有就下载、校验并保存"，矩阵里的各个组合依赖它，只从缓存恢复字体并执行 `fonts:check`，不再访问官网。缓存恢复失败时直接报错，错误信息要说清楚是字体缓存没准备好。

- 锁定版本（4.003）和哈希不变。
- 本机的 `npm run fonts` 行为不变。
- 标签触发的 release 工作流读不到分支上的缓存，确认它在自己的运行里也能走通同一套流程。

## 不做

- 不改产品代码和界面。
- 不换 MiSans 的版本。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run verify:app`、`npm run verify:packaged` 全部通过。
2. `verify:app` 连续 5 次 0 失败。
3. 工作流文件能通过语法检查（仓库里已有的检查方式，或 `actionlint`，没有就说明你是怎么核对的）。

远端 CI 的结果由设计负责人推送后确认，不要声称已经通过。
