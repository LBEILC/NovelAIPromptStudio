# 012b 012 推送后 CI 四个组合全部失败

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：CI 运行（提交 `5ee36ca`，即 012 的全部提交加 012a 的任务说明）。本机 012 的验收是全过的。

## 现象

### 1. 应用验收卡在图片库的第一步（Windows + Node 24、macOS + Node 22、macOS + Node 24）

两个主题都在同一处超时，之后的图片库断言都没有执行：

```
Error: 等待超时：[图片库·正常动效] document.documentElement.dataset.motion === 'full'
    at wait (electron/acceptance/harness.js:25:11)
    at async libraryChecks (electron/acceptance/library.js:95:5)
```

`library.js` 先调用 `saveAppearanceSettings({motion:'full'})`，刷新后等待 `dataset.motion === 'full'`。在 CI 上它一直等不到。注意 run.js 在这之前有一段用调试协议模拟 `prefers-reduced-motion` 的检查，CI 的运行器本身的"减少动态效果"设置也可能和本机不同。

### 2. 单元测试超时（Windows + Node 22）

四个测试超过了 vitest 默认的 5 秒：

- `electron/database.test.js`："searches, filters, edits, paginates, and deletes Tag cache entries"（6.5 秒）
- `electron/database-native.test.js`："opens the fixed old file without changing tables, rows or library payloads"（6.2 秒）
- `electron/promptBlocksCheck.test.js`："runs the CLI against a synthetic database …"（14.9 秒）
- `scripts/data-layer/compatibility.test.mjs`："seeds through production, preserves all 21 tables …"（9.9 秒）

## 要求

1. **查清第 1 条的原因**。用 010c 的失败说明记录当时的 `dataset.motion`、保存后读回的外观设置、`matchMedia('(prefers-reduced-motion: reduce)')` 的结果。在本机模拟 CI 的条件（系统开启减少动态效果、以及前面那段调试协议模拟没有被撤销）复现。如果是产品问题（例如"完整"被系统设置覆盖，或者保存没有生效），修产品；"完整"的含义是不论系统设置如何都播放动效。如果是验收脚本的问题（模拟没有撤销、等待的条件不对），修脚本。
2. **第 2 条**：这些测试本来就重。不要只是把超时改大了事：先看它们为什么在 CI 上比本机慢这么多（本机分别是多少），能减少工作量的减少（例如更小的合成数据、复用已经建好的数据库副本）；减少之后仍然需要更长时间的，给这几个测试单独设置合理的超时，并在注释里写明原因。
3. 推送后的 CI 由设计负责人确认。本机：`npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run verify:app` 通过，并且在"系统开启减少动态效果"的条件下 `verify:app` 也通过一次。

3. 有没有别的验收步骤也依赖本机的系统设置？
