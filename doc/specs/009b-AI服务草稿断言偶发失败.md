# 009b "分页切换保留 AI 草稿"在 CI 上偶发失败

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：CI 运行（提交 `7c0b667`）。只有 macOS + Node 24 失败，其余三个组合通过；这个提交只改了文档，产品代码和上一次全绿的运行（`e58a367`）相同。

## 现象

```
FAIL [设置·AI 服务] 分页切换保留 AI 草稿
Error: 断言值：false
```

`electron/acceptance/settings.js`：在"AI 服务"里填好地址、Key、模型和两段规则，切到"外观"再切回"AI 服务"，立刻断言五个输入框的值都还在。

## 两种可能，要查清是哪一种

1. **断言时序**：切回来之后表单还没有填好（例如先显示已保存的值，再套上草稿），断言赶在中间。这是验收脚本的问题，按 009a 的做法改成带期限的等待。
2. **产品问题**：切回来时，读取已保存设置的异步结果比草稿晚到，把草稿覆盖掉了。用户在真实使用中也会丢掉没保存的输入。这种情况要修产品：草稿一旦存在，晚到的已保存值不能覆盖它。

用 010c 加的"失败时附带说明"记录五个输入框的实际值（Key 只记录是否为空和长度，不记录内容）。在本机人为让"读取已保存设置"变慢来复现，判断是哪一种。

## 要求

- 查清原因并写进汇报，附上复现的办法和结果。
- 是产品问题就修产品，并加一条单元测试覆盖"晚到的已保存值不覆盖草稿"；是时序问题就改断言。
- 顺带检查设置页其他分页里有没有同样的"先读取已保存值、再套草稿"的写法，有的话一并处理。
- `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 通过，`npm run verify:app` 连续 5 次 0 失败，人为放慢读取时也通过一次。

## 不做

- 不改设置页的界面和文案。
