# 009 自动化验收脚本

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4，之后每个迁移任务都要往里加断言
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 规则：`AGENTS.md` 的 Application verification（用户 2026-10-11 决定不再做手动验证）
>
> 参照：用户另一个项目 DispatchDock 的 `app/src/main/shots.ts`、`app/src/main/shots-packaged.ts`、`tools/verify-packaged.mjs`（只读参照）。本项目已有的截图工具（任务 006、006a）。

## 目标

把已有的截图工具扩展成**验收脚本**：在隔离环境里启动真正的应用，一步步操作界面，逐条断言结果，同时截图。从此交互行为靠它验证，不再写手动验证清单。

这个任务要把下面五份已归档的手动验证文档里的检查项，尽可能全部转成自动断言：

- `doc/archive/manual-verification-20261011-shell-settings.md`（外壳与设置页，最重要）
- `doc/archive/manual-verification-20261011-ui-foundation.md`、`…-ui-finish.md`（基础组件）
- `doc/archive/manual-verification-20261011-app-screenshots.md`（截图工具不影响正常启动）
- `doc/archive/manual-verification-20261011-data-engine.md`（数据引擎的界面部分）

## 做法

### 1. 断言的写法

照 DispatchDock 的做法：

- 每条检查有一个中文标签和一个布尔表达式，例如 `check('翻译词典按分类筛选后只剩外貌身体', '…')`。结果不为真就让命令失败，并打印能帮助定位的上下文。
- 操作用页面里的方法完成：`executeJavaScript` 里调用 `click()`、派发键盘与输入事件、滚动、派发指针事件。中文输入法组合输入用 `compositionstart` / `compositionend` 事件模拟。
- 系统层面的设置用 Electron 的接口或调试协议模拟：深浅色用 `nativeTheme.themeSource`，"减少动态效果"用 `Emulation.setEmulatedMedia`，窗口最大化和尺寸用 `BrowserWindow` 的方法，实际渲染字体用 `CSS.getPlatformFontsForNode`。
- **不模拟操作系统层面的鼠标和键盘**，不使用桌面控制。
- 需要"重启后检查"的项，在同一个临时数据目录上关闭应用再启动一次。
- 运行结束输出一个清单文件，列出每条检查的标签和结果，和截图放在一起。

### 2. 替身

有些操作会碰到系统或网络。在**验收模式下**用替身代替，正常启动的应用里不能存在这些替身（要有测试证明）：

| 真实行为 | 验收模式下的替身 |
|---|---|
| 系统文件对话框（打开图片、导入、更改资源库位置） | 主进程里返回脚本指定的路径，或返回"取消" |
| 在文件管理器中显示、打开文件夹、打开外部链接 | 记录被请求的路径或网址，供断言检查，不真的打开 |
| AI 服务 | 脚本在本机起一个假的 OpenAI 兼容服务，可以控制它返回成功、失败或超时 |
| 检查更新 | 返回脚本指定的版本信息，不访问网络 |
| 系统安全存储 | 能用就用真的；某个 CI 平台上不可用时，把相关检查标为"本平台未覆盖"并写进清单，不要让它静默通过 |

剪贴板用真的（Electron 的 `clipboard`），在检查前后保存和恢复原有内容。

### 3. 要覆盖的检查

至少包括以下内容，标签写成中文。每一项都要深浅两套主题各跑一次的，注明"两套主题"。

**外壳**
- 导航：依次进入工作台、图片库、设置，当前导航项的样式正确，旧的左侧竖栏不存在。
- 主题：浅色、深色、跟随系统；快速来回切换后停在最后的选择；"跟随系统"时改变 `nativeTheme` 能跟着变。每次切换后，传给标题栏覆盖层的背景色和符号色与当前主题的令牌一致（在主进程里记录调用参数来断言）。
- 动效：设为"关闭"时，以及系统开启"减少动态效果"时，新组件的过渡时长为 0。
- 窗口最大化后，标题栏和内容不重叠，设置按钮不被系统窗口按钮遮住（用元素位置和覆盖层可用区域计算）。
- 快捷键：工作台里 `Ctrl/Cmd+I` 打开（对话框用替身）、`Ctrl/Cmd+V` 从剪贴板打开图片、`Ctrl/Cmd+W` 关闭标签、`Ctrl/Cmd+Tab` 与 `Ctrl/Cmd+Shift+Tab` 切换标签；图片库里 `Ctrl/Cmd+I` 导入、`Ctrl/Cmd+V` 从剪贴板导入、`Ctrl/Cmd+K` 聚焦搜索。在文本输入框里 `Ctrl/Cmd+V` 仍然是普通粘贴。修饰键按平台取。

**设置 · 外观**
- 改界面字体、等宽字体、段落字体后立即生效，重启后保留。界面字体和等宽字体的实际渲染字体与选择一致。

**设置 · 图片库**
- 显示的文件数和占用与临时环境一致。
- 更改位置：先取消，位置不变；再选一个空目录，有进度，完成后位置更新、图片仍能显示、旧目录里的文件在校验完成前没有被删除。
- 数据与备份：数据库路径位于临时数据目录；"打开文件夹"请求的路径正确。没有备份时显示"还没有升级前的备份。软件在升级数据格式之前会自动留一份。"。脚本放入一个假的 `studio.pre-*.sqlite` 后刷新，列表出现它，"在文件夹中显示"请求的就是它；删掉这个文件后再点，显示错误，列表刷新后消失。数据库和其他备份没有被修改。
- 清空回收站：先取消，回收站数量不变；再确认，数量为 0。工作台里有草稿的图片被清空时，确认对话框里有相应提示。

**设置 · AI 服务**
- 输入地址、Key、模型和两种提示词后切到别的分页再回来，草稿还在。保存后重启，地址、模型、提示词保留，Key 显示为"已保存"且输入框为空。
- 读取模型列表、选择模型、测试连接成功；把假服务改成失败后再测，显示错误并可以重试。
- 两种提示词分别恢复默认，保存后重启保留。

**设置 · 翻译词典**
- 搜索原 Tag 和译文；按分类和来源筛选；分类下拉里每个选项前有分类圆点和文字，用方向键移动、Enter 选中；没有结果时有空状态。
- 编辑单条译文和分类，先取消再保存，保存后列表更新。
- 勾选多条，成批设置分类；删除时先取消、再确认。
- 数据超过一页时可以翻页。

**设置 · 关于与更新**
- 显示实际版本号和"非官方工具，与 NovelAI 没有隶属关系。"
- 自动检查更新的开关重启后保留；检查更新显示替身给出的结果；有发布说明时"更新说明"能打开对话框并关闭。
- "报告问题""提出建议"请求打开的是项目 GitHub 上对应的表单网址，网址里不带任何本机数据。
- "复制诊断信息"后剪贴板里只有版本和平台，不含路径、图片名、Prompt。
- "查看声明"对话框能打开、内容包含三种字体和 Remix Icon 的许可、能用 Esc 关闭。

**基础组件（在组件展示页上，真实 Electron 里跑）**
- 滑块：用指针事件拖动到两端、点击轨道；键盘右方向键、Home、Shift+右方向键、End 的取值正确；可访问的数值随之更新。
- 可拖宽面板：拖动、方向键、Shift+方向键、双击恢复默认宽度。
- 菜单、编辑浮层、对话框：打开后焦点进入，Tab 在内部循环（对话框打开时背景不能获得焦点），Esc 关闭后焦点回到触发处。
- 通知：出现、悬停时不消失、移开后消失。
- `motion=off` 时加载按钮的圆环不转。

**正常启动不受影响**
- 不带验收参数启动时，页面里不存在验收用的接口，替身没有安装（单元测试或启动后检查均可，选一种并说明）。

**数据**
- 重启后图库、收藏集、回收站、Tag 译文都在，数量与重启前一致。

### 4. 打包后的检查

`npm run verify:packaged`：打一个不签名的目录包，用验收参数启动它，至少确认：能启动、能打开数据库并导入演示图、能渲染、实际渲染字体是随包的三种字体。照 DispatchDock 的 `tools/verify-packaged.mjs`。

### 5. 命令与 CI

- `npm run verify:app` 跑全部检查并截图；`npm run screenshots:app` 保留，作为只截图的快捷方式，或者并入前者，由你决定。
- CI 在 Windows 和 macOS 上都跑 `verify:app`，上传检查清单和截图。`verify:packaged` 在两个平台上也都跑；如果它让 CI 时间明显变长（超过 10 分钟），改为只在推送到 `rebuild/**` 和 `main` 时运行，并在汇报里说明。

## 不做

- 不改产品的行为和外观。为了让脚本能操作而需要的改动（例如给元素加稳定的 `data-` 属性），只能是不影响外观和行为的标记。
- 不使用操作系统层面的输入模拟，不使用桌面控制。
- 不读取、不写入用户真实的数据目录。

## 验收标准

1. `npm run verify:app` 在本机通过，检查清单里有上面第 3 节列出的每一类，每类都有具体的断言。
2. 故意弄坏一处（例如让翻译词典的分类筛选失效），`verify:app` 会失败并指出是哪一条；改回后通过。在汇报里贴出失败输出，然后确认已经改回。
3. `npm run verify:packaged` 在本机通过。
4. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run audit:ui` 全部通过。
5. 汇报里有"自动化没覆盖"一节，逐条列出五份归档文档里没能转成断言的检查项和原因。
