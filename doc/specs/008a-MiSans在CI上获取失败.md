# 008a MiSans 在 CI 上获取失败

> 阶段：任务 008 的修复
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`

## 问题

推送 `a4cb57e` 后，CI 的两个 macOS 组合在"Acquire and verify MiSans"这一步失败，两个 Windows 组合通过。macOS 的日志：

```text
单独下载包的字体版本已变化，检查同页官方全量包中的指定版本。
[TypeError: fetch failed] { [cause]: SocketError: other side closed }
```

也就是说：官网单独下载包里的 MiSans VF 已经不是我们锁定的 4.003；脚本转去全量包里按范围读取 4.003，从 macOS 机器访问时连接被断开。

## 要做的

1. **查清现状**：官网单独下载包里现在是哪个版本、SHA-256 是多少；全量包里是否仍然有 4.003。写进汇报。**不要换版本**，锁定的版本和哈希保持不变。是否升级由设计负责人决定。
2. **下载重试**：网络错误和连接中断时自动重试（带退避，有上限）；哈希不符不重试，直接失败。
3. **跨平台共用缓存**：字体文件与平台无关，让 Windows 和 macOS 共用同一个缓存（缓存键不含操作系统，并开启跨平台缓存），任何一个平台成功获取后，其他平台直接命中。`release.yml` 同样处理。
4. 截图、验收和打包步骤在缓存命中时不再访问官网。

## 不做

- 不改锁定的 MiSans 版本和哈希。
- 不把字体文件放进仓库或其他任何公开位置。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 全部通过。
2. 有测试覆盖：网络错误会重试并最终成功；哈希不符不重试。
3. 汇报里写清官网的现状（第 1 项）和缓存键的设计。推送后两个平台的 CI 能否通过，由设计负责人确认。
