# 013 工作台界面

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 前置：011、011a、011b（按"块"组织的 Prompt）、012 系列（图片库）
>
> 依据：[设计文档](../design.md) 2.1、2.4a、2.9、2.11、2.14、2.15 节；界面稿 `design/preview.html?page=wb&sub=<状态>&stage=1.0`（状态列表见 2.14 节，深浅两个主题都要对照）。界面稿里把"看到哪一期"切到 1.0 看到的就是这次要做的范围。

## 目标

把工作台整页换成新的界面：不再使用 `@lobehub/ui`，用 `src/ui/` 的组件和 `design/tokens.css` 的令牌；Prompt 用 011 的块模型显示和编辑。现有的每一项能力都保留，除了"去掉"里列出的。做完之后，产品代码里不再有 `@lobehub/ui`（帮助中心和更新说明如果还在用，留到阶段 5，在汇报里列出）。

这是 1.0 的范围：没有版本栏、参数页签、Seed、生成。

## 范围

### 1. 页面结构

- 标题栏里的标签；中间是图片；右边是 Prompt 栏，可以拖宽（`ResizablePanel`，宽度记住，沿用现有的存储键）。
- 新文件用 TSX，放在 `src/workbench/`。页面状态从 `App.jsx` 拆到 `src/state/`，做法和 007、012 一致。旧的 `WorkbenchPage.jsx`、`PromptOverview.jsx`、`TagManagement.jsx`、`ImageStage.jsx` 等在新页面接上之后删除。
- 一行里的控件不换行（设计文档 2.11 节最后一条）：Prompt 栏拖窄时搜索框先让出宽度，再隐藏快捷键提示，再把带文字的安静按钮收成图标。

### 2. 标签

- 没有起名的图片只显示缩略图，起过名的在缩略图后面显示名称（规则见 2.15 节，"没有起名"的判断写成纯函数并有测试）。
- 缩略图高度 `--tab-thumb-h`，宽度跟着图片比例，限制在 `--tab-thumb-min-w` 到 `--tab-thumb-max-w`。
- 当前标签有朱砂方块；有改动的标签带小圆点。
- 标签放不下时两头出现翻页按钮；可以拖动换位置，键盘操作沿用现有的（空格拿起、方向键移动、空格放下、Esc 取消）。
- 右键菜单：关闭、关闭其他标签、关闭右边的标签、在图片库里显示（图片在图片库里时才有）。Ctrl / Cmd W 关闭当前标签。关闭有改动的标签时的确认沿用现有的。
- 打开图片：加号按钮、拖进窗口、Ctrl / Cmd V、从图片库打开，都沿用现有的接口。空工作台照界面稿的"空状态"页。

### 3. 图片区

- 图片、标题（没有起名时省略）、参数（尺寸、模型短名称、步数、引导强度、Seed，缺的不显示，规则同 012a）。
- "存入图片库" / "已存入图片库"；在文件夹中显示、复制图片、另存为。
- Prompt 改过后多一行"Prompt 已经和原图不一样"和"还原成原图的 Prompt"（还原要确认）。
- 图片不见了：照界面稿，Prompt 仍然可以编辑和复制。
- 图片里有 Vibe 时的信息显示沿用现有的内容，用 `Banner` 的信息样式。

### 4. Prompt 文档

- 节：基础 Prompt、每个角色、各自的排除内容。节可以收起；节标题右边是"复制这一节"和"更多"（编辑原始文本、全部翻译与分类）。
- 块：用 011 的 `createPromptDocument` 等接口。块标题显示类型、标签（有的话）、数量；右边是块菜单：转为段落 / 转为 Tag 块、翻译与分类这一块、复制这一块、上移、下移、删除这一块。"存为常用块"这一项显示为不可用（1.1）。两块之间悬停出现"在这里加一块"。
- **块类型的记忆**：用户转换过的类型要保存下来，下次打开这张图（包括重启后、存入图片库后）仍然是用户选的类型。保存在这张图已有的 Prompt 结构数据里，不新增表和字段。旧版本读到多出来的内容不能出错【实现时核实：用真实的旧版引擎验证】；做不到时停下来写进汇报。
- Tag：点击编辑（Tag、译文、分类、权重，删除，翻译与分类）；拖动换位置，可以跨块、跨节；Alt 加方向键移动当前 Tag；有语法问题的用警告样式，说明沿用现有的文字。权重的修改和删除用 011 的最小改动接口；011 报告里说的"无法安全表示的编辑"要接住，用通知告诉用户这个 Tag 的写法不规范、请用"编辑原始文本"修改。
- 添加 Tag：块末尾的输入框。逗号或换行一次添加多个，添加前说明"将添加 N 个 · M 个重复"。
- **Tag 提示**：输入时在下面列出候选，英文 Tag、译名、使用次数。输入中文按译名找。来源是软件里已有的内置词典和用户的翻译词典【实现时核实：现有的词典里有哪些字段、多少条、有没有使用次数，写进汇报】。上下方向键选择，回车采用，Esc 关闭；输入法组字期间回车不采用（`Autocomplete` 组件已有的行为）。不联网。
- 多选：Ctrl / Cmd 加单击、Shift 加单击、从空白处拖动框选。操作条：复制、移动到（只列同一种正负的节）、翻译与分类、删除、取消。
- 段落：点击进入编辑，照界面稿的上下两栏。"译成中文"和"按中文改写英文"调用现有的 AI 服务配置；没有配置 AI 服务时这两个按钮不可用，并提示去设置里配置。进行中显示加载状态，可以取消；失败时保留用户已经输入的内容并说明原因。译文和这段英文一起保存（存在哪里照现有 Tag 译文的做法，不新增表和字段；做不到时停下来写进汇报）。
- 编辑原始文本：以节为单位，保存后用 011 重新分块，原有的译文、分类、用户选的块类型尽量保留（能对上原文的保留）。
- NovelAI 自动加的内容：收成一行说明，可以点开；判断规则和文字沿用现有的。
- 角色：添加（上限沿用现有的）、重命名、移除（确认文字沿用现有的）。

### 5. 搜索与显示

- 搜索框搜 Tag 和译名，Ctrl / Cmd K 聚焦。
- "显示"浮层：语言、排列（按块 / 按分类）、只看、分类。语言和排列沿用现有的存储键；筛选不保存。
- 筛选生效时：条件条、不符合的 Tag 变淡、没有符合内容的块收起并在最后说明有几块被收起。
- "按分类"排列时，同一节里的 Tag 按分类归到一起显示，段落块照常；这时不能拖动排序，说明文字沿用现有的意思。

### 6. 复制

照设计文档 2.4a 节。

- 复制的文本从块模型的原文算出来：没有筛选、没有选中时，"复制 Prompt"的结果与现在的"复制全部 Prompt"逐字节相同。
- 只选了排除内容，或筛选成只看排除内容：复制这些排除内容。
- 正向和排除都选了：只复制正向的，通知里说明没有包含几个排除 Tag，菜单里有"复制其中的排除内容"。
- 每一节的"复制这一节"复制这一节的原文。
- 菜单：复制全部 Prompt、含 NovelAI 自动加的（有才显示）、复制全部排除内容、只复制某一节。
- 011 里沿用旧规则的那几个复制函数按这里的规则更新，测试一并更新。

### 7. 去掉

- 旧的 Tag 总览里和新界面重复的入口（以新界面为准）。逐项列出旧界面的操作和新界面里的位置，没有对应的写进汇报，不要自己决定去掉。

### 8. 顺带处理的两件小事（第 ① 阶段做）

- `electron/database-native.test.js` 的"closes and rolls back when startup repair fails"、`electron/libraryCards.test.js` 的"preserves dirty markers…""rebuilds a dropped derived table…"在 Windows + Node 22 的 CI 上要 7 到 8 秒，超过默认的 5 秒。照 012b 的做法缩小数据或单独放宽时限。
- "滚动立即关闭提示"在 macOS 的 CI 上测出 111 毫秒（上限 100 毫秒）。现在的计时包含了验收脚本和页面之间的通信时间。改成在页面内部计时：从滚动事件发生到提示消失，用页面里的时间戳算。100 毫秒的要求不变。

### 9. 旧工作台复制菜单在 Windows CI 上的失败

旧工作台的复制菜单在 Windows 的 CI 上点开后页面会卡住（012e 汇报里有记录）。不要为旧页面修它：新页面接上、旧页面删除后，这条检查由新工作台的复制菜单检查代替。**新工作台的复制菜单和其他弹出菜单必须在 Windows 的 CI 上通过**，这是本任务的验收条件之一，由设计负责人推送后确认。

## 文案

界面稿里出现的文字就是定稿；现有界面里的提示文字（语法提示、自动内容的说明、确认框）界面稿没有覆盖的，沿用现有的。两边都没有的，用 `【文案待定：…】` 占位并写进汇报。

## 分阶段提交

每次提交前 `format:check`、`typecheck`、`npm test`、`build` 都要通过，旧工作台在新页面接上之前保持可用。建议的顺序：① 状态拆分、名称判断、复制规则；② 标签和图片区；③ Prompt 文档的显示、搜索与显示方式；④ Tag 的编辑、添加、提示、多选、拖动；⑤ 段落编辑与 AI、原始文本、角色；⑥ 接上新页面、删除旧页面；⑦ 验收断言与截图。

## 验收断言

加进 `npm run verify:app`，深浅两个主题、正常和关闭动效都跑；截图加进 `screenshots:app`，界面稿的每个状态一张，并生成和界面稿的并排对照图。AI 服务用验收里已有的假服务。

1. 打开图片的四种方式；标签的切换、拖动、键盘移动、右键菜单的每一项、关闭有改动的标签的确认。
2. 没有起名的标签不显示名称，起名后显示；横图、竖图、方图的缩略图宽度符合比例（验收数据里的横图和方图沿用 012 的做法临时裁出）。
3. 存入图片库；改 Prompt 后出现"还原"，还原后和原图逐字节相同。
4. 块的每个菜单项；类型转换后原文逐字节不变；重启后类型还在。
5. Tag 的编辑、改权重、删除、拖动（块内、跨块、跨节）、Alt 加方向键；每次操作后，除了改动的地方，原文其余部分逐字节不变。
6. 添加 Tag：单个、一次多个、重复的提示、中文找到英文、提示列表的键盘操作、输入法组字期间回车不采用。
7. 多选的三种方式和操作条的每个按钮。
8. 段落编辑：两个 AI 按钮（假服务）、取消、失败保留输入、没有配置 AI 服务时不可用。
9. 编辑原始文本后重新分块，译文和分类保留。
10. 搜索、每种显示方式、每种筛选、清除。
11. 复制的每一种情况（2.4a 节的四种，加菜单里的每一项），和预期文本逐字节比对；"复制 Prompt"与旧实现逐字节相同（演示数据里的每一张图）。
12. 角色的添加、重命名、移除。
13. 图片不见了的状态；空工作台。
14. Prompt 栏拖到最窄时没有任何控件换行。

## 不做

- 版本栏、参数、生成、Seed（1.1）。
- 常用块、Vibe 库（1.1、1.2）。
- "整理 Prompt"、Tag 与段落的 AI 互转、拆分角色（1.1）。
- 图片库的改动（批量起名在 012c）。

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run audit:ui`、`npm run verify:app`、`npm run verify:packaged` 全部通过；`verify:app` 在"系统开启减少动态效果"的条件下也通过一次（012b 的做法）。

3. 15 个状态的并排对照图，深浅各一套。
