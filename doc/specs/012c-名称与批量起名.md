# 012c 图片库：没有起名的图片不显示名称，批量起名

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：[设计文档](../design.md) 2.15 节；界面稿 `design/preview.html?page=lib&sub=unnamed`、`sub=rename`、`sub=select`

## 背景

真实图库里 97% 的"名称"其实是文件名（NovelAI 下载时的文件名，或一串十六进制），显示出来又长又没有意义。规则见设计文档 2.15 节。

## 范围

1. **"没有起名"的判断**：名称去掉图片扩展名后，以 `s-` 加数字结尾（后面可以带 ` (1)` 这样的重复序号），或者是 16 位以上的十六进制、UUID。写成 `src/lib/` 里的纯函数并有测试；013 的工作台标签也要用它，放在两边都能引用的位置。只按这两种形状判断，不看长短。
2. **详情栏**：没有起名时，标题那一行省略；在导入时间后面加一行"文件 …"，等宽小字、中间省略，悬停看完整文件名。"重命名"按钮写成"起名"。有名字的照旧。
3. **大图**顶部同理：没有起名时不显示名称，只显示尺寸和位置。
4. **网格**里卡片的无障碍名称：有名字用名字，没有就用"图片，导入于 10 月 11 日 14:02"这样的说法，不念文件名。
5. **批量起名**：
   - 多选操作条加"起名"（放在"加入收藏集"后面）。对话框照界面稿：输入名称，下面预览"名称-01 … 名称-06"，说明"按现在的排列顺序编号。只改软件里显示的名称，图片文件不动。"
   - 编号位数按数量定：不到 100 张用两位，不到 1000 张用三位。只有一张时不加编号。
   - 名称为空时确认按钮不可用。和已有名称重复不算错误。
   - 一摞图片：详情栏里对一摞图片点"起名" / "重命名"时，出现同一个对话框，给这一摞里的每一张按顺序编号；只想改当前这一张时，对话框里有一个选项"只改这一张"。
   - 完成后的通知："已给 6 张图片起名"，带"撤销"（撤销恢复原来的名称）。
   - 一次改名在数据库里是一个事务，中途失败全部回滚。
6. **"另存为"的默认文件名**：有名字用名字，没有就用原来的文件名。
7. **搜索**仍然能搜到文件名。

## 顺带：慢机器模式全套用 4 倍

012d 之后设计负责人的决定：全套验收的慢机器模式用 4 倍（本机约 8 分钟）；6 倍只用于按分类的定向运行，全套 6 倍本机要十几分钟，不值得。

- `.github/workflows/ci.yml` 里 Windows + Node 24 加跑的那一步从 `--slow=6` 改成 `--slow=4`，上传路径相应改。
- `doc/automated-acceptance.md` 的"交付前验证频率"改成：全套慢机器模式默认 4 倍；修偶发失败时相关分类在 6 倍下重复 10 次。
- "图片库"下面新增的起名相关断言放进一个可以单独运行的分类。

## 不做

- 不改图片文件名，不改数据库结构。
- 不做 AI 起名（1.1）。

## 验收

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run audit:ui` 通过；`npm run verify:app` 全套普通模式、`--slow=4`、`--reduced-motion` 各跑一遍，0 失败。开发过程中只跑相关的分类（`--category="图片库"` 等），不要反复跑全套。
2. 验收断言：没有起名的图片详情栏没有标题、有"文件"一行；起名后标题出现；批量起名的编号、顺序、位数、撤销；一摞图片的两种改法；另存为的默认文件名（用替身读取）；搜索文件名仍能找到。
3. 重新生成 `unnamed`、`rename`、`select` 三个状态的并排对照图（深浅各一套）。
