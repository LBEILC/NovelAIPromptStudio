# 012e Windows 的 CI 上工作台复制菜单打不开

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 依据：CI 运行 38188762131（提交 `3bfd848`，012d 之后）。产物 `acceptance-windows-latest-node24` 里的 `acceptance/light/timeout-0-1.png` 和 `timeout-0-1.json`。

## 现象

macOS 两个组合全部通过。Windows 两个组合都在同一处失败：

```
等待超时：[图片库·复制] 上一条通过：重新加载后封面仍在；
操作：复制菜单显示可用的"复制全部 Prompt"；已等待 12000 ms（上限 12000 ms）
```

012d 加的前置条件（目标图片已在工作台显示、复制菜单按钮可见可用、页面入场结束）这次都等到了，点击之后 12 秒菜单仍然没有出现。所以**这不是时序问题**。

已经知道的：

1. 只在 Windows 的 CI 上出现，从 012 加入这条检查起每次必现。本机（包括 6 倍慢机器模式重复 10 次）和 macOS 的 CI 从不出现。
2. 超时截图里，工作台正常显示了目标图片（第 4 / 4 张），下拉按钮带着焦点样式，页面上没有菜单。
3. 截图是 1008×704：Windows 的 CI 屏幕只有 1024×768，窗口比本机和 macOS 的 CI 都小。这是目前看到的最明显的环境差别，但还没有证实它就是原因。
4. 结构摘要只收了 `.nps-layer` 里的内容，旧工作台的菜单（`@lobehub/ui`）不在里面，所以看不出菜单节点是根本没有生成，还是生成了但不可见。
5. 这条失败之后，Windows 上剩下的三百多条验收都没有执行。

## 范围

### 1. 在本机复现

- 给 `verify:app` 加一个指定窗口大小的参数（`screenshots:app` 已经有 `--constrain-window`，做法可以沿用），用 1008×704 跑 `--category="图片库·复制"`。
- 复现不出来时，再依次对照其他差别：窗口没有系统焦点（`document.hasFocus()` 为假）、屏幕工作区大小、Windows Server 的系统设置。每排除一项写进汇报。
- 本机实在复现不出来，就把下面第 2 项的诊断加好，说明还需要 CI 的哪些信息，不要猜一个原因来改。

### 2. 超时的诊断补全

结构摘要现在只看新界面的浮层。补上：

- 文档里所有 `[role=menu]`、`[role=menuitem]`、`[role=listbox]`、`[role=dialog]`，各自的位置和大小、是否在窗口范围内、是否可见；
- 正在操作的那个按钮的 `aria-expanded`、`aria-controls`；
- `document.hasFocus()`、`document.activeElement` 的角色和名称、窗口内容区的宽高。

不记录任何用户数据。

### 3. 查清原因并处理

- **是产品的问题**（比如窗口小的时候菜单打不开、或者弹到了窗口外面）：这是用户在小窗口下也会碰到的问题，要修。注意这里是旧的工作台页面，013 会整页换掉：能用小改动修好就修；需要大改时停下来写进汇报，由设计负责人决定是不是留给 013。同时检查新界面的 `Menu`、`Popover`、`Select` 在 1008×704 下有没有同样的问题，有的话一起修，并加一条小窗口下的断言。
- **是验收环境的问题**（比如没有系统焦点时旧菜单组件不响应）：改脚本的做法，并说明为什么用户实际使用时不会碰到。

### 4. 一个分类失败不影响后面的分类

现在一条等待超时会让整个验收进程结束，后面的分类都不跑，CI 上看不到其余部分是好是坏。改成：一个分类里出现等待超时，记为这个分类失败（截图和诊断照常保存），重新加载应用回到干净状态，接着跑下一个分类；最后的退出码仍然是失败。依赖前一个分类留下的状态的分类，要么自己准备状态，要么明确标记为"因前一个分类失败而跳过"，不能悄悄算通过。

### 5. CI 用小窗口多跑一个分类（可选）

如果第 3 项查出来和窗口大小有关：本机默认窗口的全套照旧，另外在 `verify:app` 全套里对弹出菜单、浮层这一类检查用 1008×704 再跑一遍，写进 `doc/automated-acceptance.md`。和窗口大小无关就不加。

## 不做

- 不重写旧工作台。
- 不为了让 CI 变绿而跳过或删掉这条检查。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build` 通过。
2. `npm run verify:app` 全套普通模式、`--slow=4`、`--reduced-motion` 各一遍，0 失败；`--category="图片库·复制"` 在 1008×704 下通过。开发中只跑相关分类。
3. 人为让一个分类超时，确认后面的分类照常执行、最后退出码为失败、清单里这个分类是失败。

远端 CI 由设计负责人推送后确认。本机 8766 端口上有设计负责人的界面稿预览服务，不要占用或关闭它。

2. 用户在实际使用中会不会碰到？在什么条件下？
3. 新界面的菜单和浮层在小窗口下有没有同样的问题？
