# 007 应用外壳与设置页

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4，第一个迁移任务
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`。这个分支上的改动在全部页面迁移完成之前不会合并回 `main`，也不会发版。
>
> 参照：`design/preview.html` 的"设置"页（点左侧侧栏切换各分页）和"组件"页、`design/tokens.css`、[设计文档](../design.md) 2.9 和 2.11 节、[产品边界](../product-boundary.md) 第 7 节

## 目标

用这一个任务跑通"新组件 + 拆状态 + 改 TypeScript"的完整迁移流程，产出两样东西：

1. **新的应用外壳**：设计令牌接入、主题与动效、标题栏和导航。之后迁移的每个页面都放在这个外壳里。
2. **新的设置页**：按界面稿重做。

工作台和图片库这次不迁移。它们会暂时以旧样子显示在新外壳里，可以看起来不协调，但必须照常可用。

## 范围

### 1. 分支与 CI

- 在 `.github/workflows/ci.yml` 的触发条件里加上推送到 `rebuild/**` 分支，让这个分支的每次推送也在 Windows 和 macOS 上检查。
- `npm run screenshots:app` 的画面清单更新为新设置页的各个分页（见下），工作台和图片库的画面保留。

### 2. 设计令牌与主题

- 应用入口加载 `design/tokens.css`，在 `<html>` 上设置 `data-theme`（`light` 或 `dark`，"跟随系统"时随系统变化）。用 004 做好的主题组件替换 `LobeProvider` 在外壳和设置页上的作用。旧页面里仍然用到 `@lobehub/ui` 的地方，它们需要的提供者照旧保留，等页面迁移时再去掉。
- **变量冲突**：旧的 `src/styles.css` 里有与令牌同名的变量（至少 `--text`、`--danger`、`--font-ui`、`--font-mono`），优先级规则也不同。处理原则：令牌的值必须生效；冲突一律改旧样式那一侧（例如给旧变量改名），不改 `design/tokens.css`。改完后旧页面要保持可用，截图里看起来和现在一致或接近即可。
- **默认主题改为跟随系统**。已经保存过主题的用户保持他们的选择。
- **去掉主题色设置**（用户 2026-10-11 确认）。偏好文件里已有的 `primaryColor` 值不删除、不报错，只是不再读取和显示；旧页面暂时按原来的默认色显示。
- 动效：应用的动效设置（完整、跟随系统、关闭）作用到新组件上，规则和 004 的组件一致。

### 3. 标题栏与导航

按界面稿的标题栏实现：

- 一行，高 `--titlebar-h`，背景 `--pane`，底部一条 `--border` 的线。
- 从左到右：标志、导航（工作台、图片库）、空白、设置按钮（齿轮图标），Windows 上最右边是系统的最小化、最大化、关闭按钮。
- 标志用 `design/identity/logo/` 里的矢量文件，不要自己画。
- 当前页面的导航项文字用 `--text` 加 `--fw-strong`，其余用 `--text-2`。
- 原来左侧的竖条导航去掉。
- **Windows**：隐藏系统标题栏，用 Electron 的标题栏覆盖层（`titleBarOverlay`）显示系统的窗口按钮，按钮区的背景色和符号色跟随当前主题，主题切换时同步更新。标题栏的空白处可以拖动窗口，导航和按钮不可以；双击空白处最大化。
- **macOS**：保留现在的 `hiddenInset`，标题栏左侧给交通灯按钮留出空间，其余与 Windows 一致。
- 工作台的图片标签这次**不**放进标题栏，仍然留在旧工作台里，等迁移工作台时再搬。
- 原来的应用菜单和快捷键（打开、导入、粘贴、关闭标签、切换标签）行为不能变。

### 4. 设置页

按界面稿"设置"页实现 1.0 的五个分页（把界面稿顶部的"看到哪一期"切到 1.0 看）：外观、图片库、AI 服务、翻译词典、关于与更新。NovelAI 账号和 Agent 接入是 1.1 的内容，这次不做。

| 分页 | 内容与来源 |
|---|---|
| 外观 | 主题（跟随系统、浅色、深色）；界面字体；等宽字体；段落字体；动效。字体下拉沿用现有的系统字体列表逻辑。**段落字体是新增的偏好项**，存进偏好文件的外观设置里，默认值取令牌 `--font-prose` 的第一个字体，这次只保存，不用于任何页面。界面稿里的"Prompt 的显示"一节**这次不做**，它属于工作台 |
| 图片库 | 现有"资源库"分页的全部功能（位置、文件数与占用、打开文件夹、更改位置与迁移进度），加上界面稿里新增的"数据与备份"：数据库位置与打开文件夹、升级前的备份（列出数据目录里存在的 `studio.pre-*.sqlite`，可以在文件夹中显示）、回收站数量与清空回收站。清空回收站沿用现有的确认与逐项结果 |
| AI 服务 | 现有"AI 服务"分页的全部功能：服务地址、API Key、模型与读取模型列表、测试连接、保存、翻译与分类提示词、恢复默认 |
| 翻译词典 | 现有"Tag 数据"分页的全部功能，改成界面稿的表格：搜索、按分类和来源筛选、勾选后成批设置分类和删除、单条编辑译文与分类。"重新翻译"按钮现在没有对应功能，**这次不做** |
| 关于与更新 | 版本；非官方声明（"非官方工具，与 NovelAI 没有隶属关系。"）；现有"关于与更新"的全部功能（自动检查、检查更新、下载、重启并安装、macOS 手动更新）；"更新说明"打开一个对话框显示现有的发布说明内容；现有"反馈与支持"的全部功能（报告问题、提出建议、复制诊断信息）；字体与开源组件的署名和"查看声明" |

- 界面稿里的文字就是产品文案，照抄。界面稿没有写到、而现有功能需要的文字（错误提示、确认对话框、进度文字等），沿用现有代码里的文字。仍然缺的，用 `【文案待定：…】` 占位并写进汇报。
- 侧栏每一项带图标，图标与界面稿一致（Remix Icon，线条风格）。把 `remixicon` 加为依赖，版本与 DispatchDock 一致（4.9.1），许可文件随包分发。图标只在新外壳和设置页里用，旧页面继续用原来的图标。
- 设置页只用 `src/ui/` 里的组件。004a 遗留的"下拉选项前面放分类圆点"在翻译词典的分类筛选里需要用到，在这个任务里补上。

### 5. 状态拆分与 TypeScript

- 外观、AI 服务、资源库位置、更新状态、Tag 词典这几块状态从 `src/App.jsx` 里搬出去，放进按领域划分的独立模块。设置页直接使用这些模块，不再通过 `App.jsx` 层层传 props。工作台和图片库如果也用到其中的状态（例如外观），改为从同一个模块读取。
- 新写和迁移的文件一律用 TypeScript / TSX，开启严格检查。设置页通过 `window.studio` 调用主进程时，用 001 定义的 `StudioApi` 类型。
- 删除被替换掉的旧文件（旧的设置页组件、只被它们用到的样式和测试），对应的测试改写成针对新代码的测试，测试意图保留。

## 不做

- 不迁移工作台和图片库，不改它们的功能。
- 不做字体随包分发（下一个任务）。本机没有对应字体时落到替补字体，这是预期的。
- 不做 1.1 的内容。
- 不改数据库和 IPC 的行为。新增偏好项"段落字体"是唯一的偏好文件格式变化，旧版本读到它时应当忽略（核实旧版的读取逻辑会忽略未知字段，写进汇报）。
- 不移除 `@lobehub/ui`。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run audit:ui` 全部通过。
2. `npm run screenshots:app` 产出新设置页每个分页的浅色和深色截图，以及新外壳下的工作台和图片库截图。设计负责人会和界面稿对比，差异在汇报里逐条说明。
3. 设置页和外壳的代码里没有引用 `@lobehub/ui`，没有令牌以外的颜色和像素字号。
4. 现有的设置功能一项不少。在汇报里列一张表：旧设置页的每个功能 → 新设置页的位置。
5. 写一份 Windows 手动验证文档，覆盖：标题栏拖动和双击、系统窗口按钮跟随主题、导航、每个设置分页的主要操作、主题与动效切换、快捷键没有变化。只写在验证副本或演示环境上的步骤，不要求用户在日常图库上操作。
