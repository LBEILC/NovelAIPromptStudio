# 008 字体随包

> 阶段：[重构计划](../rebuild-plan.md) 阶段 4
>
> 执行者：工程负责人
>
> 分支：`rebuild/ui-1.0`
>
> 参照：`design/identity/fonts.md`、[设计文档](../design.md) 2.10 和 2.11 节，以及用户另一个项目 DispatchDock（`E:\AIProject\DispatchDock`）里获取和随包分发 MiSans 的做法：`tools/fonts.mjs`、`THIRD_PARTY_NOTICES.md`。只读参照，不修改那个项目。

## 目标

新设计用三种字体，各管一件事：界面和中文用 MiSans，Tag 和数字用 IBM Plex Mono，成段的自然语言用 Newsreader。把它们随应用一起分发，让每台机器上看到的都一样；同时去掉旧设计带来的 HarmonyOS Sans SC 和 Geist。

## 范围

### 1. MiSans VF

MiSans 的授权允许随软件分发，但**不允许在软件之外单独分发字体文件，也不允许修改、转换或子集化**，并要求在软件里注明。因此：

- 仓库里**不放**字体文件。照 DispatchDock 的做法，写一个脚本从小米的官方下载页获取 MiSans VF，核对 SHA-256，放到一个被 git 忽略的位置。版本和哈希与 DispatchDock 相同（Version 4.003，`5daf8d5447bfd423cfdec94a0e07c53b205892223ccc6ea21b7b8a37248b44d9`）。可以复用它的实现，复用的部分在汇报里说明。
- 构建和打包时把这个文件原样带进应用。不转换成 woff2，不子集化。
- 文件缺失或哈希不符时：本地开发和测试照常进行，界面落到替补字体并打印一行警告；**打包发布时必须失败**，不能发出没有 MiSans 的安装包。
- CI：截图和打包的步骤需要它。用缓存避免每次都下载；下载失败时截图步骤的处理方式由你决定并说明理由，但不能让打包在没有字体的情况下成功。`release.yml` 同步处理。

### 2. Newsreader 与 IBM Plex Mono

两者都是 OFL 授权，可以作为依赖安装（例如对应的 `@fontsource` 包），随构建产物分发。

- Newsreader 用可变字体，需要字重 400–500 和光学尺寸轴。
- IBM Plex Mono 需要 400 和 500 两个字重。
- 只带拉丁字符集即可，中文由 MiSans 承担。

### 3. 去掉旧字体

- 移除 HarmonyOS Sans SC 和 Geist、Geist Mono 的字体文件和相关依赖（`@lobehub/webfont-*`），删掉 `src/fonts.css` 里对应的声明。旧页面里写死这些字体名的地方，改为使用令牌的字体变量。
- 构建产物里不再有这几个字体文件。在汇报里给出产物体积的前后对比。

### 4. 默认字体与已有设置

- 外观设置的默认值改为：界面字体 MiSans，等宽字体 IBM Plex Mono，段落字体 Newsreader。
- 字体下拉列表里，三种内置字体排在最前面并标注"（内置）"，后面才是系统字体。
- **已经选过字体的用户保持原来的选择**，只有一种情况例外：他们选的是 Geist、Geist Mono 或 HarmonyOS Sans SC 这三种被移除的内置字体，而本机系统里又没有安装同名字体。这时改用新的默认值，不提示。
- 字体设置只作用于界面；改字体不能影响任何数据。

### 5. 声明与文案

- 关于页"查看声明"的对话框里，用下面的文字替换 007 留下的 `【文案待定】`，并附上三种字体的完整许可文本（MiSans 的许可协议全文，Newsreader 与 IBM Plex Mono 的 OFL 全文）：

  > 界面字体 MiSans VF（版本 4.003），版权归北京小米移动软件有限公司所有，按其许可协议随本软件原样分发。段落字体 Newsreader 与等宽字体 IBM Plex Mono 按 SIL Open Font License 1.1 分发。

- 打包时把这些许可文本放进安装包的 `LICENSES` 目录，和现有做法一致。
- 顺带修一处 007 留下的文案：设置 → 图片库 → "升级前的备份"没有备份时，显示"还没有升级前的备份。软件在升级数据格式之前会自动留一份。"
- README 的许可证部分加一句，说明 MiSans 不在仓库里，需要运行哪条命令获取。

## 不做

- 不改任何页面的布局和组件。
- 不对 MiSans 做任何形式的修改。
- 不移除 `@lobehub/ui` 本身。

## 验收标准

1. `npm run format:check`、`npm run typecheck`、`npm test`、`npm run build`、`npm run audit:ui` 全部通过。
2. 没有 MiSans 文件时，`npm test` 和 `npm run build` 仍然能跑通；`npm run package` 失败并给出清楚的提示。给出证据。
3. 有 MiSans 文件时，打一个不签名的 Windows 目录包，确认三种字体都在包里、旧字体都不在。
4. `npm run screenshots:app` 的截图里，界面、Tag、段落分别用的是这三种字体。用一个能核实实际使用字体的方法证明（例如在截图模式下读取页面实际渲染用的字体），不要只凭肉眼。
5. 仓库里没有任何字体二进制文件被新加入 git。
