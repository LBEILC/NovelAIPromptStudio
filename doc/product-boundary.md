# 当前产品边界

> 状态：当前有效
>
> 最后核对：2026-08-13
>
> 适用平台：Windows / macOS，尽量保持 Linux 兼容
>
> 视觉规范：[Lobe 视觉层级与颜色语义规范](./lobe-visual-language.md)

## 1. 产品定位

NovelAI Prompt Studio 是一个由图片驱动的 Prompt / Tag 编辑器，并提供一个轻量的本地图片库。

它解决两件事：

1. 从 NovelAI 图片读取 Prompt，在本地完成结构化编辑、翻译、分类与复制。
2. 保存值得复用的图片，并在需要时重新送入工作台。

应用不生成图片，也不重复实现必须回到 NovelAI 才能验证效果的调参流程。

## 2. 信息架构

应用有两个业务页面：

- **工作台**：打开图片后立即解析并编辑 Prompt。
- **图片库**：持久保存、查找和重新打开图片。

设置是应用级辅助页面，不构成第三个业务资源库。

```text
应用
├─ 工作台（默认）
├─ 图片库
└─ 设置
```

### 两种图片入口

| 入口 | 行为 | 是否写入图片库 |
| --- | --- | --- |
| 打开到工作台 | 从文件、拖放、剪贴板或图片库创建工作标签 | 否 |
| 导入图片库 | 从文件、ZIP、拖放或剪贴板复制到用户资源目录 | 是 |

打开工作台不会修改原图，也不会把草稿自动回写到图片库。

## 3. 工作台

### 图片与会话

- 同时打开多张图片，每张图片拥有独立标签、来源、草稿和修改状态。
- 从文件、拖放、剪贴板或图片库打开图片；重复打开同一来源时复用已有标签。
- 保存标签顺序、当前标签和每个标签的 Prompt 草稿，重启后继续工作。
- 关闭有修改的标签前明确确认，支持跨平台的标签关闭与切换快捷键。
- 工作台只保存自己的草稿状态，不写回图片 metadata，也不自动收藏源图。

### Prompt 整理

- 读取 NovelAI V4 / V4.5 PNG metadata，并兼容应用已经支持的历史 Prompt 写法。
- 区分 Base / Character Prompt 与各自的 Undesired Content。
- 以结构、分类或原始文本查看 Prompt，并在原文、译文和对照显示之间切换。
- 添加、删除、排序、选择和批量处理 Tag；编辑 Tag 文本、翻译、分类与权重。
- 在结构化 Tag 与原始 Prompt 文本之间同步；解析失败时保留原始文本。
- AI 只辅助翻译和分类，结果进入本地缓存并允许用户最终修正。

### 复制与导出

- 主操作复制当前筛选后可见的正向 Prompt。
- 可复制全部正向 Prompt、完整 Base Prompt、指定 Character Prompt，以及单个 Tag 的纯文本或带权重形式。
- 所有 Prompt 复制保留原始 NovelAI Tag、顺序、权重和作用域，不把译文或 Undesired Content 混入正向结果。
- 只读识别图片中可恢复的 Vibe 数据，并按需导出 `.naiv4vibe` 文件；不提供 Vibe 参数编辑或本地效果预览。
- 图片舞台支持查看、复制可见位图和下载保留原始格式与 metadata 的图片。

## 4. 图片库

- 导入 `PNG`、`JPG`、`JPEG`、`WEBP` 和 NovelAI 导出 `ZIP`，支持文件选择、拖放与剪贴板。
- 将主动导入的图片副本、缩略图和可恢复资源持久保存在用户资源目录中。
- 按文件名、Tag 或译名搜索，按导入时间排序，并提供全部、收藏和回收站视图。
- 根据图片内容指纹跳过重复项；根据完整 Prompt 指纹把仅 Seed 等结果属性不同的图片折叠成组。
- 支持组内浏览、持久化头图、收藏、重命名、批量选择和从图片库送入工作台。
- 多选模式以图片组为操作单位，详情侧栏只操作当前图片；界面文案必须明确二者的作用范围。
- 普通删除进入应用内部回收站；恢复、永久删除与清空回收站都提供明确确认和逐项结果。
- 详情侧栏保持挂载，支持折叠、拖拽调宽和宽度持久化；大图预览提供缩放、旋转、翻转、复制和下载。

图片库是收藏与回访入口，不承担独立 Tag 资产管理、关系图谱或生成历史管理。

## 5. 设置与本地数据

设置承载以下应用级能力：

- 跟随系统、浅色与深色主题，以及主题色、界面密度和动效偏好。
- 分别选择界面非衬线字体与 Prompt 等宽字体，并基于系统字体提供预览。
- 配置 OpenAI-compatible AI 服务、测试连接和编辑翻译/分类 Prompt。
- 查看、搜索、筛选、修正和删除已经生成的 Tag 翻译与分类缓存。
- 查看和迁移图片库资源位置，迁移前验证目标并保留可恢复备份。
- 检查官方稳定版本；Windows 支持应用内下载与安装，未签名 macOS 构建引导至官方 Release 手动更新。

Tag 缓存管理是对自动生成译文和分类结果的纠错入口，不是独立 Tag 资产库，也不改变图片中保存的原始 Prompt。

敏感连接信息继续使用操作系统安全存储。路径、文件对话框、字体、快捷键、更新和资源迁移均按跨平台能力实现。

## 6. 明确不做

- 独立 Tag 资产库与 Vibe 库。
- Vibe 强度编辑、混合、试听或效果模拟。
- 图片系列、分支、版本树、实验、关系和对比系统。
- Tag 收藏、标签关系图谱或统计面板。
- 在应用内生成图片。
- 修改原始图片 metadata。
- 未经用户确认，将工作台草稿写回图片库资源。

未来功能可以提高工作台与图片库的效率，但不应重新引入上述资源库或实验管理系统。

## 7. 数据安全

- 原始图片保持不可变；图片库只管理用户主动导入的副本。
- 数据迁移前创建可恢复备份；迁移失败时保留旧目录并给出明确提示。
- 删除操作区分“移入应用回收站”“永久删除应用副本”和外部原始文件。
- 文件清理只允许作用于经过验证的应用管理资源目录。
- 不因界面移除旧功能而静默删除历史数据表或用户文件。
- Prompt 解析失败时保留原始文本，不能因结构化失败丢失内容。
- 更新安装前持久化工作台标签与草稿，更新失败不得损坏图片库和偏好设置。

## 8. 实施约束

- 页面与交互遵循 [Lobe 视觉规范](./lobe-visual-language.md)。
- Lobe UI 组件选择、导入路径和弃用迁移遵循 [项目 Skill](../.agents/skills/lobe-ui-frontend/SKILL.md)。
- 具体组件 API 以项目已安装的 `@lobehub/ui` 版本和本地类型定义为准。
- Windows 与 macOS 是一等支持平台；共享 npm 脚本与业务代码不引入平台专属 shell 语法。
- 当前实现状态以代码和测试为准；已完成的开发规格保存在 [`archive/`](./archive/) 中，仅用于追溯决策和验收来源。
