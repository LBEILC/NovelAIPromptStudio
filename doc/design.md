## 1. 产品定位

**以 Prompt 为核心的 NovelAI 本地创作客户端。**

原来的定位是"由图片驱动的 Prompt 整理工具，加一个轻量图片库"，明确不在应用内生成图片。用户 2026-10-11 说明：当初把生成、分支、Vibe 库列为"不做"，是因为做过一版、对交互不满意后删掉了，不是不需要。现在决定做。

要补上的断点是：改完 Prompt 之后必须复制出去、到 NovelAI 网页生成、再把图拖回来。把这一步接上，创作的循环才完整。

模型取向：兼容 V4 / V4.5，但以 V5 为最优先支持的对象（用户 2026-10-11）。

## 2. 已定

以下均为 2026-10-11 与用户确认。

### 2.1 Prompt 是由"块"组成的文档

V5 的 Prompt 是 Tag 和自然语言混写的：通常第一段是带权重的风格与画师 Tag，空行之后是成段的自然语言，分别写主体、构图、各个角色，漫画页会写 `Panel 1: …`。现有工作台一律按逗号拆分，会把一段话拆成几十个没有意义的碎片（实测一张 V5 图被拆成 83 个"Tag"）。

所以新工作台的基础数据结构是**块**：

- **Tag 块**：一组可拖拽、可调权重的 Tag，和现在的体验一致。
- **段落块**：一段自然语言，整段编辑、整段翻译，并标注用途（风格、主体、构图、角色、场景、分镜）。

导入时自动判断每一块的类型，用户可以手动改。V4 / V4.5 的 Prompt 表现为只有一个 Tag 块。

**分块和判断的规则**（设计负责人 2026-10-11 用一个真实图库只读验证：118 张 V4.5、30 张 V5）：

1. **按空行分块。** V4.5 平均每张 1.3 块，V5 平均 3.5 块，最多的一张有 17 块。
2. **块可以带一个标签。** 真实的 V5 Prompt 里常见 `Rossi: …`、`Panel 1: …`、`<style> …` 这样的开头。冒号或尖括号前面的这一小段单独识别成块的标签，后面的内容再判断类型。写着角色名的标签也是"拆分角色"这个 AI 动作的线索。
3. **判断类型**：
   - 有句号等句末标点、并且有较长的分句，是段落。
   - 含有成段的中文，是段落。用户确实会直接用中文写（图库里有这样的图）。这种块不需要再配中文译文。
   - 很长的列表先看比例：用逗号分成不少于 20 项、其中不像 Tag 的项不超过一成、没有一项超过 24 个词、整块汉字少于 16 个、含英文冠词或代词的项少于两成，就是 Tag 块，个别长项作为一个长 Tag 保留。这条先于上面两条判断。后三个条件是为了不误伤段落：成段的中文和带冠词代词的英文长句，按逗号也能分出很多短项（任务 011b）。（真实图库里有一份 61 项的排除预设，其中一项有 13 个词、两处带句号，按"每项都短"会被整块判成段落。）
   - 含有成段的中文：整块汉字不少于 16 个、含汉字的项平均每项不少于 4 个汉字，是段落（没有句号也算）。含冠词、代词或 be 动词的项不少于 3 项且占三成以上，是段落。这两条先于下一条。
   - 用逗号分开、每项都很短，是 Tag 块。`数字::…::` 的权重组整体算一项。
   - 用逗号分开的描述性短语（例如 `Relaxed everyday atmosphere, intimate team gathering, …`）也按 Tag 块处理：每一项是一个短语，没有词典译文，由 AI 逐项翻译。
4. **拿不准的时候当作段落。** 实测约 9% 的 V5 块两边的特征都有。把 Tag 误当成段落，只是显示成一段可读的文字，用户点一下就能转回来；把段落误当成 Tag，会被切成一堆没有意义的碎片，这正是现在的问题。
5. **用户改过的类型要记住**，同一张图再次打开时不重新判断。

按这套规则，V4.5 的块 98.7% 被判为 Tag 块，和现在的体验一致。

### 2.2 在软件里直接生成图片

- 用户自己配置 NovelAI 的 API Key，存进系统安全存储。
- **永远从一张图出发。** 生成时以原图的参数为起点，只改用户改动的部分。不做从零定义的模型选择器和参数表单。
- **但元数据不能原样当作请求发出去**（任务 002 的结论）：图片里的约 50 个参数和接口的请求字段不是一一对应的，模型名也要换成接口用的标识。所以软件要按模型维护一张"元数据 → 请求"的对照表，对照表没有覆盖的参数不发送。NovelAI 出新模型时需要更新这张表，这是这个功能长期的维护成本。
- 生成前必须显示这次要消耗多少 Anlas。
- 生成的图自动存入图片库，不能丢。

### 2.3 版本：自动记录，不做 Git 式的分支管理

两层结构：**版本**（一份 Prompt 与参数）和它下面的**若干张图**（不同 Seed）。

1. Prompt 没改就生成，是在当前版本下加一张图。
2. Prompt 改了再生成，是产生一个子版本。
3. 回到任何旧版本接着改，就自然分出一条岔路。用户不需要"创建分支"，也不需要给分支起名。

每个版本自动显示它相对上一版改了什么：加了、去掉了哪些 Tag，权重怎么变，哪个段落改了。

### 2.4 编辑分三层，在同一个页面里逐层展开

不做"简易页"和"完整页"两个页面。

- **第一层，默认可见**：Prompt、Seed、张数。
- **第二层，展开"更多参数"**：尺寸、步数、引导强度、采样器、角色及其位置、Vibe 和参考图。
- **第三层，需要在图上动手的**：局部重绘、图生图、导演工具。**搁置**，前两层用起来之后再单独决定做不做。

### 2.4a 复制：看到什么、选了什么，就复制什么

用户 2026-10-11 提出：现在"复制可见 Prompt"和"复制选中的 Tag"一律把排除内容过滤掉，只选了排除内容时按钮是灰的，想复制排除内容只能一个一个来。改为：

- **全是正向内容**（选中的，或筛选后可见的）：复制它们，和现在一样。
- **全是排除内容**（只选了排除内容里的 Tag，或筛选成只看排除内容）：复制这些排除内容。按钮上的字跟着变成"复制排除内容 · N"，通知写"已复制 N 个排除 Tag"。
- **两种都有**：只复制正向的，避免把排除内容粘进正向 Prompt；通知里说明"没有包含 M 个排除 Tag"，按钮旁的菜单里提供"复制其中的排除内容 · M"。
- **整段复制**：每一节（基础 Prompt、各个角色、各自的排除内容）的标题上都有一个复制按钮，一次复制这一节的原文；复制菜单里有"复制全部排除内容"。
- NovelAI 自动添加的 Tag 是否包含，规则不变。

### 2.5 其他确认的功能

- **Tag 提示**：输入时补全，支持用中文找 Tag，数据来自内置词典。
- **Vibe 库**：跟着第二层一起做。
- **工作台的图可以存入图片库**；**图片库详情可以直接复制 Prompt**，并且显示带译文的结构化内容，不再是原始文本。
- **多选不再是一个模式按钮**：Ctrl/Cmd 点击加框选，选中后底部出现操作条；第一次进入时提示一次。
- **Windows 改用自绘标题栏**，导航和图片标签放进标题栏那一行。macOS 已经是这种形式。

### 2.6 能力独立于界面，Agent 可以接入

软件的每项能力（读 Prompt、改块和 Tag、搜图库、生成、建版本）都是一条不依赖界面的**命令**。界面、内置 AI、外部 Agent 调用的是同一套命令。阶段 1 拆分主进程时就按命令来组织；任务 001 写出的 63 个带类型的接口是这份命令清单的起点。

- **外部 Agent**：一个命令行工具，加一份教 Agent 怎么用的技能。任何能运行命令的 Agent 都能接入，等于给 Agent 跑图的能力。以后可以在上面再包一层 MCP。
- **内置 AI 以"修改提案"为主，暂不做聊天框。** AI 给出对 Prompt 的修改，用和版本差异同样的方式展示（加了什么、去掉什么、哪段改了），由用户接受或拒绝。
- 计划中的 AI 动作：段落翻译、用中文写再转成英文段落、Tag 与段落互转、从基础 Prompt 拆分出角色并建立角色、按意图修改、看图写 Prompt。
- **"整理 Prompt"**（用户 2026-10-11 提出，1.1，和其他 AI 动作一起）：让 AI 重新划分块、判断每块是 Tag 还是段落，并修正有问题的 Tag（多余或缺少的 `::`、没闭合的括号、明显的拼写错误、混进 Tag 里的句子等）。规则：
  - 平时的分块和判断仍然由算法完成，不需要 AI、不花钱、离线可用。AI 只在用户点"整理"时才调用，不自动运行。
  - 结果以修改提案的形式出现，和其他 AI 动作一样可以接受、放弃或逐项挑。接受的块类型等同于用户手动改过的类型，以后不再被算法覆盖。
  - 只改结构和明显的错误，不改用户的意图：不增删有意义的 Tag，不改权重的数值（除非权重语法本身写错了）。每一处修正在提案里说明理由。
  - 要把 Prompt 发给用户配置的 AI 服务，第一次使用时说明这一点。
- V5 的段落可以直接用中文写（用户 2026-10-11 指出），所以"用中文写再转英文"是可选的便利，不是必需。

### 2.7 把能力做出来，把风险说清楚

用户 2026-10-11 定下的原则：**软件负责把能力做出来，并把使用风险提示到位；怎么用是使用者自己的事。** 不替用户做限制。

背景是用户对条款的判断：它针对的是无限制的大批量生成；本软件只是替用户省去重复点按钮，并且请求只能一个接一个地发。

任务 002 查到的原文（摘录见 `doc/research/novelai-v5.md` E 节）：

- NovelAI 有公开的接口文档，并且写明第三方集成可以向用户索取持久令牌。也就是说，**用自己的令牌接第三方客户端是官方描述过的用法**。
- 生成接口的说明里写着"所有生成请求必须由人的操作发起"。服务条款 9.1.6 另有针对自动化系统的限制。
- 所以风险不在"第三方客户端"，而在**无人值守的连续生成和 Agent 自行发起的生成**。这两项的风险提示要把上面这句原文说清楚。

具体做法：

- **请求严格串行**，同一时间只有一个生成请求，不并发。这是软件的工作方式，不是可以关掉的限制。
- **无人值守的连续生成可以有，默认关闭**。打开时给出一次说明风险的提示，由用户确认。
- **Agent 的 Anlas 预算上限可以有，默认不启用**。在引导用户接入 Agent 时说明有这个选项。
- **Agent 生成默认要人确认**（用户 2026-10-11）：Agent 把要生成的内容排好队，用户点一下确认后串行发出。"Agent 直接生成"是需要手动打开的选项，打开时提示风险。这样默认状态符合"生成请求必须由人的操作发起"。
- **可追溯**：Agent 生成的图同样进入版本树，并标明来源。
- **告知**：配置 API Key 时用一两句话说明这是通过用户自己的账号调用 NovelAI，是否符合其条款由用户自行判断并承担。README 里同样写明。
- 每次生成前显示这次要消耗多少 Anlas，这一条不变。

### 2.8 V5 的事实（任务 002）

设计第二层参数时以 `doc/research/novelai-v5.md` 为准，这里只记影响结构的几条：

- V5 多了 **Effort** 这一档：High 和 Medium。Medium 固定 14 步，并且不能编辑排除内容。
- V5 仍然有独立的角色 Prompt 和位置，官方上限 22 个角色，位置可以自由指定。
- **V5 目前没有 Vibe Transfer 和精确参考**，这两项只在 V4.5 上有。素材里的 Vibe 暂时只对 V4.5 有用。
- V5 的免费生成除了 Anlas 之外，还受一个"用量"额度限制。所以生成前除了显示 Anlas，也要显示用量。
- 质量 Tag 预设有三档，排除内容预设有五档。
- NovelAI 提供官方的 Tag 补全接口，可以作为内置词典之外的补充来源。

### 2.9 页面结构

用户 2026-10-11 确认"目前的设计基本没问题"。结构稿在 `design/structure.html`，可以切换页面，也可以切换"看到哪一期"。

- **导航**：工作台、图片库、素材，放在标题栏那一行；设置入口在右上角。
- **工作台**：三栏，左边版本、中间图片、右边 Prompt。没有配置 API Key 时版本栏不出现。一个标签是一个"系列"（一张原图加上从它改出来的各个版本）。右栏底部固定一条操作栏：复制 Prompt 一直在，配置 Key 后多出 Seed、张数和生成。"更多参数"和"参考"是右栏的页签，不是另一个页面。
- **图片库**：左边常驻侧栏（全部图片、生成记录、收藏集、智能收藏集，回收站在最底下）；工具栏只留搜索、筛选、视图、导入；详情栏用和工作台相同的方式只读显示 Prompt，可以直接复制。一个系列折叠成一摞。
- **素材**：放可以反复使用的东西，分为常用块、角色、Vibe。常用块存的是整块（例如一整段风格与画师 Tag），不是单个 Tag。
- **设置**：外观、图片库、NovelAI 账号、AI 服务、翻译词典（原"Tag 缓存"）、Agent 接入、关于与更新。
- **AI 提案**：在 Prompt 文档里原位显示改动，新增和移走分别标出，可以接受、放弃或逐项挑。

### 2.10 视觉识别：括号里的图

用户 2026-10-11 在三套方案里选定。完整的规范手册、标志文件和源文件在 `design/identity/`。

- **想法**：Prompt 的花括号里放着一张图。括号是文字，朱红的方块是图，也像盖在纸上的一方印。由现有的 `{N}` 演变而来，去掉了字母 N。
- **气质**：以白纸黑字为主，像画室而不像控制台。同类产品几乎都以深色界面为主，这是有意的区别。深色主题仍然提供，两套主题要同样完整。
- **颜色**：朱砂 `#D4351C` 是唯一的品牌色，用于标志里的方块、"当前这一张"和主要操作。它的明度居中，不做大面积的文字底色。
- **字体**：标题用 Newsreader（衬线），正文用 MiSans VF，Tag 与数字用 IBM Plex Mono。Newsreader 和 IBM Plex Mono 没有中文字形，中文一律由 MiSans 承担，所以衬线的气质主要出现在字标、英文标题和数字上。
- **名称**：字标写全名 "NovelAI Prompt Studio"（用户 2026-10-11）。NovelAI 是第三方的商标，所以在"关于"页和 README 里写明：这是非官方工具，与 NovelAI 没有隶属关系。
- 没选的两套：A"加权"（`::` 的四个点，中性灰加克莱因蓝）、C"逗号"（只有字标和一个琥珀色逗号，深色底）。

### 2.11 界面的视觉语言

用户 2026-10-11 确认方向。数值以 `design/tokens.css` 为准，样子以 `design/preview.html` 为准。

- **界面本身没有颜色**，颜色留给图片和 Tag 的分类标记。
- **朱砂只出现在三处**：标志里的方块、"当前这一张"的标记（当前标签、当前图片的细框）、"生成"按钮。"生成"是整个界面里唯一的朱砂按钮。
- **其他主要按钮用墨色**。危险操作只用绛红的文字或描边，不用实心红底，避免和朱砂混淆。
- **键盘焦点环用墨色**。试过用朱砂，它和输入框的报错状态几乎分不清。
- **三种字体各管一件事**：界面和中文用 MiSans，Tag 和数字用等宽，成段的自然语言用衬线。一眼能分出哪块是 Tag、哪块是段落。
- **Tag 的分类只用一个小圆点表示**，不做彩色底。十种分类色保持原有的色相含义，明度和彩度按实测调整：任意两种的色差 ΔE2000 不低于 15（原来最低 4.9）；三种色觉障碍模拟下最低约 7（原来约 2）。十种颜色不可能在色觉障碍下全部分清，所以**分类必须同时有文字**：按分类查看时的小节标题、悬停提示、编辑浮层里的分类名。
- **图片像一张放在纸上的照片**：细微的投影，没有边框和底板。
- **版本差异和 AI 提案用同一种表示**：绿底是新增，红底加删除线是移走。
- **图标用 Remix Icon 的线条风格**（用户 2026-10-11，和 DispatchDock 同一套）。只在帮助扫读或代替文字节省空间的地方用：侧栏、工具栏、搜索框、状态横幅、小号的图标按钮，以及下拉箭头、勾、加减这类小符号。"生成"和"AI"按钮不加图标。尺寸 16px，小号控件里 14px。它的许可不允许用作标志或应用图标，品牌标志是自绘的。
- **设置页的范围（2026-10-11）**：1.0 的设置分为外观、图片库、AI 服务、翻译词典、关于与更新五页；NovelAI 账号和 Agent 接入在 1.1 加入。外观里新增"段落字体"。原来的"反馈与支持"并入"关于与更新"。"Prompt 默认显示原文、译文还是对照"属于工作台的视图设置，不放在设置页。翻译词典暂不提供"重新翻译"，现有功能里没有它。
- **去掉"主题色"设置**（用户 2026-10-11 确认）。界面本身没有颜色、朱砂只用在三处，主题色已经没有地方可用。
- **"动效关闭"的含义**：所有过渡立刻完成，时长不超过 1 毫秒。允许保留一个极短的过渡，让依赖"过渡结束"事件的代码照常触发（2026-10-11，任务 009 验收时确认）。
- **菜单与浮层的 Tab 键**：菜单里按 Tab 关闭菜单、焦点回到触发处（通行做法，任务 004 的实现）；编辑浮层和对话框里 Tab 在内部循环。
- **列表不做卡片**：设置是一行一项，素材是一行一块，用细线分隔。
- 没有检测到 Vibe、图片源不可用、余额不足这类状态用浅色横幅，文字说清发生了什么和能做什么。
- **一行里的控件不换行**：页签、按钮、快捷键提示的文字都不折行。一行放不下时，由这一行里的输入框让出宽度，占位文字用省略号截断；输入框缩到最小宽度（96 像素）还放不下，先隐藏快捷键提示，再把带文字的安静按钮收成只有图标。Prompt 栏顶部的搜索框占位文字是"搜索 Tag"，完整说明"搜索 Tag 或译名"放在提示里。

### 2.13 图片库的界面与交互

界面稿：`design/preview.html?page=lib&sub=<状态>`，状态有默认、一组图片、筛选、视图、多选、加入收藏集、智能收藏集、导入、导入 ZIP、拖入、大图、回收站、永久删除、空图片库、没有结果。

- **等高排列**（用户 2026-10-11 确认）：每一行一样高，图片按自己的宽高比占宽度，一行排满，不裁切；最后一行不拉伸。顺序仍是从左到右、从上到下。一摞图片按封面的比例显示。宽高比限制在 1:2 到 5:2 之间，超出的才裁切。不做方格和瀑布流；方格选项等有人提再加。
- **选中与打开**：单击选中一张，详情栏显示它；双击或按 Enter 在工作台打开；按空格看大图。方向键在网格里移动选中项：左右按顺序走，上下找相邻一行里水平位置最接近的那张。
- **去掉悬停弹出大图**：详情栏一直在，悬停预览重复，而且会挡住旁边的图。
- **两种外框**：朱砂外框是"当前这一张"（详情栏正在显示的）；墨色外框加勾是"多选选中的"。两者可以同时出现在不同的图上。
- **多选**：Ctrl（macOS 是 Cmd）加单击逐个选，Shift 加单击连选，拖动框选，Ctrl A 全选，Esc 退出。多选时网格底部出现操作条，详情栏显示选中的数量。
- **一摞图片**：选中后，详情栏的图片下面出现一排小图，可以逐张查看、设为封面。下面带一条线的是封面。原来叫"头图"，界面上统一叫"封面"。
- **筛选**：条件有包含的 Tag（全部都有或有任意一个）、排除的 Tag、模型、Vibe、导入时间。生效后按钮变成墨色描边并带条件数，条件逐条列在工具栏下面，可以单独去掉。
- **智能收藏集**就是存下来的一组筛选条件，在筛选浮层里"存为智能收藏集"，编辑规则用同一个浮层。
- **视图**：大小（调的是行高，120 到 360 像素）、排序、合并方式。"合并"就是原来的"自动分组方式"，四个选项含义不变：不合并、Prompt 完全相同、基础 Prompt 相同、Prompt 相似（带相似度，70% 到 95%）；另有"Vibe 不同的也合并"。
- **导入**：按钮直接打开文件选择（图片和 ZIP 都可以选），旁边的小箭头里有"从剪贴板导入"；也可以把文件拖进来，或在图片库里按 Ctrl V。ZIP 先让用户挑选要导入哪几张。导入进度浮在网格底部，可以取消剩下的，并说明跳过了几张重复的。
- **大图**：盖住标题栏以下的整个窗口，底色和页面相同，不用黑色遮罩。可以缩放、旋转、翻转、复制图片、另存为、在工作台打开；一摞图片时下面有小图条，左右键切换。
- **删除分两步**：详情栏和多选条里的是"移入回收站"，完成后的通知里可以撤销；"永久删除"只出现在回收站里，需要确认，并说明不影响用户原来的文件。回收站不自动清理。
- **段落的译文**：详情栏里有就显示，没有就不显示，不在图片库里发起翻译。段落翻译随工作台一起做。

## 4. 保留的原则

- 作品是视觉中心，界面不和图片抢颜色。
- 可读性优先于密度，说明文字不小于 11px。
- Tag 的分类色是产品自己的语义，独立于主题色。
- 持续的选中状态用完整的底色或边框表达，不用单侧色条。
- 动效只用来说明"什么变了"，可以被打断；系统开启"减少动态效果"时全部关掉。
- 原始图片不可变；任何会花钱或删除数据的操作，在执行前说清楚后果。
