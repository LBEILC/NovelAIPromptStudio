# V5 Prompt 保真与角色管理手动验证

## 受测变更

- 变更：NovelAI V5 自然语言与 `Text:` 区块保真、最多 22 个 Character Prompt、角色行内重命名与安全删除、移除角色位置编辑界面。
- 受测提交：`84d530b`（`feat: support V5 prompt and character workflows`）。

## 目标操作系统

- Windows 11
- macOS（当前支持的 Intel 或 Apple Silicon 版本）

## 前置条件

1. 使用包含本次变更的最新代码完成 `npm ci`、`npm test` 和 `npm run build`。
2. 准备一张包含 Base Prompt、至少两个 Character Prompt、Undesired Content 与角色坐标的 NovelAI V4.5 图片。
3. 准备一张包含英文或日文自然语言、引号内逗号、多行 `Text:` 内容的 NovelAI V5 图片。
4. 如没有 7 个以上角色的 V5 图片，可在工作台草稿中连续添加至少 7 个角色进行界面验证。

## 验证步骤

1. 打开 V4.5 图片并切换到“按结构”视图。
   - 预期结果：Base、Character 与 Undesired Content 均正常显示；角色标题右侧不再出现“AI 位置”或坐标按钮，也没有 5 × 5 位置编辑器。
   - 实际结果：

2. 点击一个角色标题右侧的重命名按钮，将名称改为包含中文和空格的名称，按 Enter 保存。
   - 预期结果：输入框获得焦点；Enter 保存后标题立即更新，Prompt 与 Undesired Tag 不变，出现成功提示。
   - 实际结果：

3. 再次进入重命名，修改文本后按 Escape；随后进入重命名并分别使用保存和取消图标。
   - 预期结果：Escape 与取消图标均恢复原名称；保存图标提交非空名称；空名称无法保存且有明确提示。
   - 实际结果：

4. 使用角色标题右侧的“更多”菜单。
   - 预期结果：菜单包含“重命名”和危险色“移除角色”；鼠标、Tab、Enter/Space 和 Escape 均可正常操作，菜单在最小窗口宽度下不越界。
   - 实际结果：

5. 选择“移除角色”，先取消确认，再次操作并确认删除。
   - 预期结果：第一次取消后角色及其内容保持不变；第二次确认后仅目标角色及其 Prompt/Undesired Tag 被移除，其他角色不受影响。
   - 实际结果：

6. 连续添加角色直到第 7 个，并继续验证到第 22 个；尝试再添加一个。
   - 预期结果：第 7–22 个角色均可正常创建、重命名和显示；达到 22 个后添加按钮禁用，不会静默覆盖或删除已有角色。
   - 实际结果：

7. 打开 V5 自然语言图片，分别执行“复制全部 Prompt”“复制完整 Base Prompt”和单个 Character Prompt 复制。
   - 预期结果：引号内逗号、多行 `Text:`、中日文标点、原始换行和 Base/Character 分隔均保持；Undesired Content 不混入正向 Prompt。
   - 实际结果：

8. 在原始 Prompt 编辑器中保存包含 `"Hello, world!"` 与多行 `Text:` 的内容，然后再次复制。
   - 预期结果：引号中的逗号不会产生额外 Tag；`Text:` 至结尾作为一个完整区块处理，复制内容不丢行、不拆散对白。
   - 实际结果：

9. 返回 V4.5 图片，执行完整 Prompt、可见 Tag、选中 Tag、Base 与 Character 的复制，并切换分类和搜索筛选。
   - 预期结果：原有 V4.5 Tag 工作流、权重、花括号强调、翻译、分类、筛选和复制行为没有回归；完整 Prompt 优先保留图片中的原始文本格式。
   - 实际结果：

10. 在浅色、深色、跟随系统及最小窗口宽度下重复角色重命名、更多菜单和删除确认操作。
    - 预期结果：文本、焦点环、菜单、危险状态与确认框在各主题下清晰可用；长角色名正确截断，输入框和操作按钮不重叠或裁切。
    - 实际结果：

11. 重启应用并重新打开或恢复上述工作台草稿。
    - 预期结果：角色名称、角色数量、Prompt 修改和原图恢复行为保持一致；旧 V4.5 坐标元数据未因界面移除而导致项目加载失败。
