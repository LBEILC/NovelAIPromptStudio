# 图库与 Tag 框选手动验证

## 受测变更

- 变更：图库卡片与 Prompt Tag 总览新增鼠标框选批量选择；支持替换、追加和反选手势，并阻止原生文本/图片拖拽。
- 提交：本文件所在提交及其后续 macOS 交接提交。

## 目标操作系统

- Windows 10/11（主要验证）
- macOS 13 或更高版本（交叉平台验证，重点检查 Command 修饰键）

## 前置条件

- 已执行 `npm ci`、`npm test` 和 `npm run build`。
- 图库内至少有 8 组图片，能在同一视口显示多行卡片。
- 工作台打开一张包含 Base Prompt、Base Undesired 和至少一个 Character Prompt 的 NovelAI 图片，每个区域包含多个 Tag。
- 分别准备深色和浅色主题；窗口能够缩至应用允许的最小尺寸。

## 验证步骤

1. 打开图库，在卡片之间的空白位置按住鼠标左键，拖出一个覆盖多张卡片的矩形后松开。
   - 预期结果：出现蓝色半透明完整边框；与矩形相交的卡片实时进入选中状态；松开后保留选择；页面不出现文本高亮，也不出现浏览器图片拖拽预览。
   - 实际结果：

2. 从一张未选中卡片的图片表面开始拖动，让矩形跨过其他卡片。
   - 预期结果：超过短距离阈值后进入框选，起始卡片和所有相交卡片按矩形命中结果选择；松开时不会额外触发卡片预览或误切换一次选择。
   - 实际结果：2026-08-20 首轮验证发现框选生效，但普通单击选择不生效；原因是容器在按下时过早捕获指针，已改为超过拖动阈值后才捕获，等待复验。

3. 先选中两张卡片，再按住 `Shift` 框住另外两张；随后按住 Windows 的 `Ctrl` 或 macOS 的 `Command`，框住一个已选项和一个未选项。
   - 预期结果：`Shift` 只追加框内项目；`Ctrl/Command` 对框内项目逐个反选；框外原有选择保持不变。
   - 实际结果：

4. 不按修饰键重新框选另一组卡片，然后单击图库空白处。
   - 预期结果：普通框选用当前命中项替换旧选择；空白单击清空批量选择，并保持图库浮动预览面板原有的收起规则。
   - 实际结果：

5. 分别验证未选卡片单击预览、卡片双击打开工作台、左上角选择标记、右键菜单和分组卡片横向成员预览。
   - 预期结果：未形成框选的普通点击、双击、选择按钮、右键和分组成员预览行为均与变更前一致。
   - 实际结果：

6. 在 Prompt Tag 总览进入“多选”，先在“按结构”视图中从空白处和 Tag 表面各执行一次框选，再切换到“按分类”重复操作。
   - 预期结果：两种视图都显示同一风格框线；所有相交 Tag 实时选中；跨 Base、Character、Prompt 和 Undesired 区域的选择键保持准确；顶部已选数量同步更新。
   - 实际结果：

7. 在 Tag 多选模式下验证 `Shift` 追加与 `Ctrl/Command` 反选，然后单击空白处清空；退出多选后拖动一个 Tag 调整顺序。
   - 预期结果：修饰键规则与图库一致；空白单击清空；退出多选后不再启动框选，原有 Tag 拖拽排序和点击编辑仍可用，Tag 文本不会被原生选中。
   - 实际结果：

8. 在图库和 Tag 区域分别滚动到内容中部后框选当前视口内项目，并在拖动过程中越过容器边缘再返回。
   - 预期结果：仅实际与框线相交的已渲染项目被选择；指针离开项目表面时框线连续；松开或系统取消指针后框线和十字光标立即消失，不残留全局禁选状态。
   - 实际结果：2026-08-20 首轮验证发现滚动后较早框到的项目会失去选择；原因是命中范围使用视口坐标，已改为滚动内容坐标并将显示框裁切到当前视口，等待复验。

9. 在深色、浅色主题和最小窗口宽度下重复一次图库与 Tag 框选。
   - 预期结果：框线、选中卡片和选中 Tag 在两种主题下均清晰可辨；窄窗口中没有横向溢出或遮挡批量工具栏。
