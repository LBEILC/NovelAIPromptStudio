## 冲突处理

1. 代码与测试代表已经实现的事实。
2. “当前产品边界”代表现阶段产品意图；实现与它冲突时，应先确认是代码回归还是边界需要更新。
3. “效率功能开发规格”只描述下一阶段目标，不应被误读为已经上线。
4. Lobe 视觉规范负责稳定的设计语义，具体组件 API 以已安装版本、项目类型定义和 Lobe UI Skill 为准。
5. [`archive/`](./archive/) 只用于理解历史决策，不作为新功能的默认开发依据。

## 维护规则

- 产品边界变化时，先更新“当前产品边界”，再调整其他文档。
- 新功能规格完成后，将仍然有效的产品事实并入“当前产品边界”，不要长期保留多份完成报告。
- 组件迁移经验优先沉淀到 Lobe UI Skill；视觉规范不复制版本相关 API 清单。
- 截图与界面不一致时，以代码和当前规格为准，并在合适的发布节点更新截图。
