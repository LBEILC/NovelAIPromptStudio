## 当前待验收

手工验证文档在等待用户结果期间保留在 `doc/` 根目录；记录结果后移入 `archive/`。当前没有仅由本机继续执行的待验收文档。

需要另一操作系统完成的检查不在这里重复维护，以 [`coordination/`](../coordination/README.md) 中的当前交接文件为准。

## 冲突处理

1. 代码与测试代表已经实现的事实。
2. “当前产品边界”代表现阶段产品意图；实现与它冲突时，应先确认是代码回归还是边界需要更新。
3. 开发规格在实施完成后不再建立待办；仍有效的产品事实应并入“当前产品边界”，原规格进入归档。
4. Lobe 视觉规范负责稳定的设计语义，具体组件 API 以已安装版本、项目类型定义和 Lobe UI Skill 为准。
5. [`archive/`](./archive/) 只用于理解历史决策、实施过程和验收记录，不作为新功能的默认开发依据。

## 维护规则

- 产品边界变化时，先更新“当前产品边界”，再调整其他当前文档。
- 新功能规格完成后，将仍然有效的产品事实并入“当前产品边界”，并归档实施规格。
- 手工验证文档只在等待结果期间停留于 `doc/` 根目录，结束后按协作约束归档。
- 组件迁移经验优先沉淀到 Lobe UI Skill；视觉规范不复制版本相关 API 清单。
- 截图与界面不一致时，以代码和当前产品边界为准，并在合适的发布节点更新截图。
