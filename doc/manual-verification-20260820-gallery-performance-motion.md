# 图库性能与过渡手工验证

## 验证对象

- 变更或提交：`359a859 fix: stabilize gallery result transitions`（包含此前图库性能、导航、启动与工作台预览修复）
- 目标操作系统：Windows 11
- 验证范围：工作台与图片库切换、收藏集与筛选切换、全部与回收站切换、分批呈现、相似 Prompt 分组、缩略图与预览图加载、动效降级

## 前置条件

- 已安装依赖，并使用包含上述提交的构建启动桌面应用。
- 图片库至少包含 500 张图片；建议同时准备多个普通收藏集、至少一个智能收藏集、若干回收站图片，以及可用于“相似 Prompt”分组的图片。
- 设置中可以切换浅色/深色主题和“完整/跟随系统减少动态效果/关闭”三种动态效果模式。
- 验证期间不要打开开发者工具的 CPU 或网络节流，以免改变正常交互表现。

## 验证步骤

1. 完全退出后重新启动应用，启动期间立即在工作台内点击已有标签、切换标签或打开图片。
   - 预期结果：工作台先正常呈现并可交互，不再被“正在读取图片库”全页等待界面阻塞；后台读取图库不会明显冻结工作台。
   - 实际结果：

2. 在工作台与图片库之间连续切换 8～10 次，并在切换前分别记录工作台当前标签、图库滚动位置、筛选条件和预览面板状态。
   - 预期结果：切换立即响应，出现短而克制的淡入与轻微位移动画；返回后工作台左侧预览图保持可见且不会卡在加载状态，各页面状态和图库滚动位置得到保留，没有整页白屏或内容重新硬切出现。
   - 实际结果：

3. 在图片库中快速依次切换“全部图片”和至少 3 个不同收藏集，其中包含普通收藏集和智能收藏集。
   - 预期结果：控件点击即时生效；旧图片立即退出并由稳定骨架承接，图库同步回到顶部；快速连续切换时中间收藏集的图片不会反复闪现，只有最终结果出现；新结果先呈现首屏卡片，再在空闲时补齐其余卡片，最终数量和收藏集名称一致。
   - 实际结果：

4. 首次打开“筛选”面板，分别选择和取消包含 Tag、排除 Tag、模型、Vibe 与导入时间；关闭面板后再次打开，并连续切换多个筛选组合。
   - 预期结果：筛选面板立即打开；首次需要生成选项时显示“正在准备筛选选项”和控件加载状态；连续修改筛选时，旧图片不会在原位置频繁换成中间结果，而是保持骨架直到最终结果从顶部出现；同一图库范围再次打开时直接复用选项，最终数量正确。
   - 实际结果：

5. 快速往返切换“全部”和“回收站”5 次，然后停留在任一视图。
   - 预期结果：已加载视图可直接复用缓存；未加载视图显示稳定的骨架占位；最终内容严格对应当前视图，不出现回收站图片混入全部图片或反向覆盖。
   - 实际结果：

6. 将图库分组切换为“相似 Prompt”，连续调整相似度阈值，并在计算期间操作搜索框、排序控件和侧边栏。
   - 预期结果：相似分组在后台完成，界面输入和导航保持响应；更新期间有延迟出现的状态提示，结果就绪后平滑替换；不会长时间卡住窗口。
   - 实际结果：

7. 在图库中快速滚动长列表，观察首次进入视口的缩略图；随后打开不同图片的右侧预览。
   - 预期结果：进入结果页时首屏卡片优先出现，其余卡片自动补齐且不会造成明显滚动停顿或位置跳变；主缩略图与多图组的后层缩略图都从固定尺寸底色上淡入，不会硬切；预览图正常加载，多图组装饰仍由真实成员图片组成。
   - 实际结果：

8. 选择一组图片移入回收站，在“全部”和“回收站”之间切换确认数量，再恢复这些图片并重复确认。
   - 预期结果：两个视图的缓存都在操作后更新；图片和数量只出现在正确视图，选择状态被清理，不需要重启应用才能看到结果。
   - 实际结果：

9. 依次验证“完整动态效果”“跟随系统减少动态效果”和“关闭动态效果”，每种模式下重复页面切换、收藏集切换和图片预览。
   - 预期结果：完整模式使用短促过渡；减少动态效果模式在系统启用减少动态效果时不使用空间位移；关闭模式没有可感知动画，但加载状态和内容切换仍完整可用。
   - 实际结果：

10. 分别在浅色和深色主题下查看骨架、更新提示、图片淡入、卡片选中态和键盘焦点。
   - 预期结果：所有状态均清晰可辨，颜色与 Lobe UI 主题一致；提示不会遮挡关键操作，键盘焦点与原有交互不受影响。
