# 产品品味与体验改进计划

> 状态：当前有效，待分阶段实施
>
> 建立日期：2026-08-21
>
> 当前基线：v0.8.0
>
> 适用范围：产品界面、首次使用体验、README 与对外宣传素材
>
> 关联文档：[当前产品边界](./product-boundary.md) · [Lobe 视觉规范](./lobe-visual-language.md) · [设计背景](../.impeccable.md)

## 1. 背景与结论

NovelAI Prompt Studio 已经从快速原型发展为具有明确产品边界、完整桌面工作流、跨平台交付和持续验证能力的成熟独立软件。当前体验的主要问题不再是功能缺失，而是以下四类质量上限：

1. **对外呈现弱于产品本体**：现有宣传截图仍停留在 v0.4.2，包含 UUID、截断文件名和较典型的深蓝科技背景，无法准确表现 v0.8.0 的产品成熟度。
2. **专业工作台的认知密度偏高**：Prompt 作用域、结构方式、显示语言和分类筛选同时出现，对熟练用户高效，但首次使用者不容易理解各维度的关系。
3. **高级交互的发现性不足**：框选、右键批量操作、组内悬停浏览、滚轮缩放、快捷键和 Tag 跨作用域移动等能力较多依赖偶然发现或外部文档。
4. **品牌辨识度尚未覆盖整个产品**：工作台与图库已经具有领域特征，但设置页、README 包装和宣传背景仍较依赖通用 Lobe UI 或“AI 科技工具”视觉语言。

本计划的目标不是进行一次大规模换肤，而是在不破坏现有专业效率的前提下，让产品更容易被理解、更容易被记住，并让对外观感与真实完成度一致。

## 2. 设计目标

### 2.1 产品感知目标

- 即使不说明开发方式，用户也会把它视为经过长期打磨的独立桌面软件，而不是快速生成的 AI 演示项目。
- 第一眼传达“NovelAI 创作档案与 Prompt 整理工作台”，而不是泛化的“未来 AI 工具”。
- 让产品自身的工作流、数据安全和交互质量成为高级感来源，不依靠发光、渐变或装饰性效果制造高级感。

### 2.2 使用体验目标

- 新用户在进入空工作台后 5 秒内能理解第一步是打开或拖入 NovelAI 图片。
- 熟练用户的现有快捷操作、批量能力和信息密度不被削弱。
- 核心任务始终保持：打开图片 → 找到目标 Tag → 编辑或复制 Prompt。
- 高级功能应当可以通过上下文提示、可见入口或快捷键帮助发现，不要求用户先阅读 README。
- 工作台认知负荷检查由当前约 2 项失败降低到 0–1 项失败。

### 2.3 品牌目标

品牌方向定义为：

> **精密、克制的数字创作档案台。** 作品是视觉中心，Prompt、Tag 和 metadata 像经过整理的创作标本，而不是漂浮在赛博空间中的技术数据。

应保留：

- 图像优先的构图。
- Lobe UI 提供的组件语义、主题和可访问性。
- 克制的蓝色主色和 Tag 分类色。
- 专业、紧凑、桌面工具化的整体气质。

应避免：

- 深蓝背景配电蓝发光线条的通用 AI 科技包装。
- 紫蓝渐变、霓虹描边、装饰性玻璃和无信息价值的动态效果。
- 为追求辨识度引入第二套组件系统或与 Lobe UI 冲突的视觉语法。
- 把所有功能包装成卡片、徽章或宣传性标签。

## 3. 目标用户与关键场景

### 3.1 熟练 NovelAI 创作者

关心批量操作、Prompt 精确性、图片查找速度和工作状态恢复。不能因为新手优化而增加强制步骤、教程弹窗或低价值确认。

### 3.2 第一次使用 Prompt Studio 的创作者

理解 NovelAI、Prompt、Tag 和 Vibe，但不了解本应用的信息架构。需要知道从哪里开始、筛选维度如何组合，以及哪些操作会修改数据。

### 3.3 依赖键盘或辅助功能的用户

不能依赖悬停、颜色或右键菜单才能完成关键任务。所有核心能力需要具备可聚焦入口、清晰状态和必要的键盘替代路径。

## 4. 改进方向与实施要求

### 4.1 P1：重做对外呈现与演示内容

这是投入较低、感知提升最大的改进，应优先于界面重构。

#### 需要完成

1. 为 v0.8.x 准备独立演示数据，不直接使用日常图库。
2. 使用简短、可读、能说明场景的图片名称，禁止在正式宣传图中出现 UUID、随机哈希和大段下划线 Prompt 文件名。
3. 选择视觉风格相对统一、适合公开展示的图片集，并覆盖：
   - 工作台双语 Tag 与分类整理。
   - 多标签工作状态。
   - 图库分组、收藏集、筛选和批量框选。
   - 主题、动效与本地数据设置。
4. 重新截取当前版本界面，替换 `v042` 系列宣传图。
5. 重做 README 主视觉：保留真实界面，不修改产品 UI；外部背景改为安静的“创作档案台”构图，可使用低对比度 Tag 结构、纸张/画布层次或轻微分类标记，但不使用霓虹科技线路。
6. README 首屏优先说明用户痛点和核心工作流，避免把内部工程能力当作第一卖点。

#### 宣传素材验收标准

- 所有截图来自当前正式版本或明确标记的开发版本。
- 不含 UUID、隐私路径、API 地址、Key、调试 Toast 或无意义截断文本。
- 缩小到 README 常见显示宽度后，仍能一眼分辨工作台和图库的核心价值。
- 去掉外部背景后，应用界面本身仍然成立；背景只负责构图，不负责掩盖产品问题。
- 通过 AI Slop 检查：无紫蓝渐变字、霓虹描边、玻璃卡片堆叠、虚构指标或通用 SaaS Hero 模板。

### 4.2 P1：补足首次使用与高级功能发现性

不采用强制教程或多步引导。通过空状态、上下文提示和可随时打开的帮助入口完成渐进教学。

#### 需要完成

1. 强化空工作台：
   - 保留“拖入图片”作为主要动作。
   - 明确支持本地文件与剪贴板。
   - 用一句话说明打开到工作台不会修改原图或自动写入图库。
2. 强化空图库与无结果状态：区分“尚未导入”“筛选无结果”“收藏集无匹配”“回收站为空”，并给出准确下一步。
3. 增加一个非侵入式“快捷操作”入口，可随时查看：
   - 打开、导入、粘贴和标签切换快捷键。
   - 图库框选、追加/反选和滚轮缩放。
   - Tag 框选、右键批量操作和移动到其他 Prompt 作用域。
4. 第一次进入相关交互区域时，仅显示一次可关闭的轻量提示；关闭后不重复打扰，并能从帮助入口重新查看。
5. Tooltip 和菜单文案优先解释结果，而不是只重复按钮名称。例如说明“复制当前筛选后可见的正向 Prompt”。
6. 检查高级鼠标手势是否有键盘或可见菜单替代路径，尤其是组内悬停浏览、框选和右键批量操作。

#### 发现性验收标准

- 不阅读 README 的用户能在 5 秒内找到打开图片入口。
- 不使用右键的用户仍能完成打开、复制、导入、收藏、移动到回收站和恢复等核心操作。
- 快捷操作入口不长期占用工作台主要空间。
- 所有一次性提示均可关闭、不会阻塞任务，也不会在升级后反复出现。
- 关闭动效和减少动态效果时，教学提示不依赖动画才能理解。

### 4.3 P2：降低工作台认知密度

目标是整理层级，而不是删掉专业能力，也不引入“新手模式 / 专家模式”两套难以维护的界面。

#### 当前高密度区域

工作台顶部同时包含：

- Prompt / Undesired。
- 全部区域 / Base / Character。
- 按结构 / 按分类。
- 原文 / 翻译 / 对照。
- 分类筛选、搜索、AI 翻译、角色管理和多选操作。

这些控制各自合理，但同时具有相近视觉权重，用户需要先理解多个正交维度才能预测结果。

#### 改进原则

1. 将控制明确分成三组语义：
   - **内容范围**：Prompt / Undesired、Base / Character。
   - **组织方式**：按结构 / 按分类。
   - **显示方式**：原文 / 翻译 / 对照。
2. 内容范围始终可见；组织方式与显示方式可以弱化或收纳到紧凑的视图控制中，但当前状态必须仍然可识别。
3. 分类筛选只在“按分类”有意义时强调；在“按结构”时降低存在感，避免同时形成两套导航。
4. 多选操作沿用现有稳定布局，不因状态变化推动 Tag 区域。
5. 搜索、筛选和复制结果之间保持明确反馈，用户不需要记住隐藏条件。
6. 保留所有状态持久化，避免用户每次打开图片都重新选择熟悉的工作视图。

#### 认知负荷验收标准

- 首屏不存在四组以上视觉权重相同的操作区域。
- 用户能用一句话解释当前看到的是“哪类 Prompt、按什么方式组织、用什么语言显示”。
- 切换任一维度后，Tag 位置、复制范围和筛选状态都有可预测反馈。
- 熟练用户完成现有高频任务的点击数不增加。
- 不新增长期占位的说明文字或重复标题。

### 4.4 P2：建立更完整的品牌辨识度

品牌改进应从领域结构中产生，而不是增加装饰。

#### 可发展的识别元素

- `{}`、权重、Prompt 作用域与 Tag 芯片形成的结构语言。
- Base / Character / Undesired 之间清晰但克制的分类标记。
- “图片原作 + 结构化文字档案”的双栏构图。
- 低对比度、非发光的 metadata 网格或档案索引语义。
- 来自应用图标的括号与 `N` 结构，但避免在所有区域重复 Logo。

#### 应用内改进边界

- 工作台和图库继续以内容为主，不添加大型品牌装饰。
- 设置页可以通过更清晰的页面节奏、主题实时预览或领域化示例增强辨识度，但不制作无功能价值的展示卡。
- 空状态插图应使用应用自身的 Tag、图片和 Prompt 结构，不使用通用机器人、星光或魔法棒插图。
- 主题色继续承担操作和状态语义，不让品牌色覆盖 Tag 分类色。

#### 品牌验收标准

- 遮住 Logo 后，工作台仍能通过信息结构被识别为 Prompt Studio。
- 浅色和深色主题具有同一产品气质，不把深色主题作为唯一“高级”表现。
- 设置页、空状态、README 与主应用使用同一套语气、字体层级和结构元素。
- 所有装饰都能解释其与图片、Prompt、Tag 或 metadata 的关系。

### 4.5 P3：帮助、微文案与可访问性收束

1. 将 README 中稳定的操作知识整理成任务导向的应用内帮助，而不是按功能模块复制整篇文档。
2. 检查按钮、Tooltip、Toast、确认框和错误信息是否使用一致术语：图片、图片组、收藏集、工作台标签、Prompt 作用域、回收站。
3. 错误信息必须说明发生了什么、数据是否安全以及下一步能做什么。
4. 对重要状态使用文字、图标和结构共同表达，不能只靠蓝色边框或分类颜色。
5. 对框选、拖拽、悬停和右键操作执行一次键盘与屏幕阅读器专项审查。

## 5. 优先级与建议批次

| 批次 | 范围 | 价值 | 风险 | 建议交付物 |
| --- | --- | --- | --- | --- |
| A | 演示数据、v0.8 截图、README 主视觉 | 高 | 低 | 新宣传素材与 README 更新 |
| B | 空状态、快捷操作入口、一次性提示 | 高 | 中 | 新手与发现性改进 |
| C | 工作台控制层级与渐进披露 | 高 | 中高 | 工作台顶部信息架构优化 |
| D | 设置页、空状态和外部品牌语言统一 | 中 | 中 | 品牌一致性改进 |
| E | 微文案、键盘与辅助功能专项收束 | 中高 | 中 | 可访问性与帮助改进 |

批次必须依次评估，但不要求合并为一个版本。每个批次都应拆成小任务，完成自动测试、生产构建和必要的人工验收后再进入下一批次。

## 6. 验证方法

### 6.1 自动检查

- 现有测试全部通过。
- 生产构建通过。
- Lobe UI 审计无新增问题。
- 新增状态具有对应的组件或逻辑测试。
- 不引入新的弃用组件、深层样式依赖或第二套设计系统。

### 6.2 人工体验检查

每个涉及界面的批次建立独立中文手工验证文档，至少覆盖：

- Windows 与 macOS 受影响平台。
- 浅色、深色和跟随系统主题。
- 100% / 125% 常用缩放与窄窗口。
- 动效完整、减少动态效果和关闭动效。
- 空数据、正常数据、长文本和大量图片。
- 鼠标、键盘和必要的辅助功能路径。

### 6.3 角色走查

#### 熟练用户

- 能否在 60 秒内打开图片、筛选目标 Tag、完成批量操作并复制结果？
- 新手提示是否可以完全跳过？
- 原有快捷键、右键菜单和批量路径是否保留？

#### 第一次使用者

- 是否能在 5 秒内找到第一步？
- 是否能理解工作台和图片库的区别？
- 是否能发现至少一个高级能力，而不需要阅读外部文档？

#### 辅助功能用户

- 是否能用键盘完成核心流程？
- 状态变化是否被正确宣布？
- 选择、错误和危险操作是否不依赖颜色表达？

## 7. 明确不做

本计划不授权以下变化：

- 不改变“工作台 + 图片库”的两页产品边界。
- 不引入新的业务模块、生成能力、Tag 资产库或 Vibe 编辑器。
- 不为了品牌感替换 Lobe UI 或建立平行组件系统。
- 不进行一次覆盖全应用的大重构或统一换肤。
- 不强制展示教程，不阻塞熟练用户进入工作。
- 不通过隐藏关键功能来换取表面简洁。
- 不把桌面专业工具改造成移动端、网页 SaaS 或营销站式布局。

## 8. 完成定义

当以下条件全部满足时，本计划可以归档：

1. README 和宣传截图已经反映当前稳定版本，不再使用 v0.4.2 素材。
2. 正式宣传素材没有开发环境痕迹和通用 AI 科技包装。
3. 新用户无需外部说明即可开始核心流程，并能找到应用内快捷操作帮助。
4. 工作台控制层级完成收束，认知负荷检查达到低负荷区间。
5. 高级鼠标交互具有可发现入口或可用替代路径。
6. 工作台、图库、设置、空状态和 README 形成一致且可解释的品牌语言。
7. 相关自动测试、生产构建、Lobe UI 审计和跨平台人工验收全部完成并记录。

完成后，将仍然稳定有效的设计原则并入 `.impeccable.md` 或 [Lobe 视觉规范](./lobe-visual-language.md)，把本实施计划移动到 `doc/archive/`，不继续作为新的待办来源。
