# 工作台与图片库效率功能开发规格

> 状态：讨论结论，待开发
> 日期：2026-07-22
> 最后更新：2026-07-27
> 适用平台：Windows / macOS，尽量保持 Linux 兼容
> 关联文档：[工作台与图片库两阶段重构计划](./two-page-workbench-gallery-refactor-plan.md)、[Lobe 视觉层级与颜色语义规范](./lobe-visual-language.md)

## 1. 文档目的

本文定义 NovelAI Prompt Studio 下一阶段的已确认功能与交互边界，作为后续设计、实现、测试和跨平台验收的共同依据。

本阶段包含：

1. 工作台多标签。
2. 从文件或剪贴板向工作台和图片库读取图片。
3. 工作台 Prompt 复制规则与 Split Button。
4. 图片库批量选择、收藏、重命名和回收站。
5. 软件内版本检查与自动更新能力。
6. 文件选择器记忆上次使用的图片目录。
7. 完整 Prompt 相同图片的折叠分组、组内浏览与头图管理。
8. 大图工具栏、图片居中、危险按钮和设置侧栏的一致性修复。

本文是现有两页面产品结构的增量规格。它取代旧计划中“工作台一次只编辑一张图片”和“不提供图片库批量操作”的限制；其他关于本地优先、工作台不自动写入图片库、图片库保存应用管理副本、原图 metadata 不被修改等边界继续有效。

## 2. 总体产品原则

### 2.1 工作台与图片库保持不同语义

| 当前页面 | 从文件读取 | 从剪贴板读取 | 是否加入图片库 |
| --- | --- | --- | --- |
| 工作台 | 打开为新的工作台标签 | 打开为新的工作台标签 | 否 |
| 图片库 | 导入一张或多张图片或 ZIP | 导入一张剪贴板图片 | 是 |

工作台使用“打开”，图片库使用“导入”。界面文案不能让用户误以为工作台中的图片已经被收藏到图片库。

### 2.2 一项主操作只使用一个强调按钮

- 工作台的主要输出操作是“复制 Prompt”。
- 图片库的主要输入操作是“导入图片”。
- 同一操作的默认路径与次要来源使用 LobeUI Split Button 组织，不平铺多个同等强调的按钮。
- 使用 `@lobehub/ui/base-ui` 中的新版 `Tabs`、`SplitButton`、`DropdownMenu` 和其他基础组件；不使用已经弃用的旧 `@lobehub/ui/es/Tabs`。

### 2.3 所有危险操作必须可解释

- 普通删除只进入应用内部回收站。
- 永久删除和清空回收站必须二次确认。
- 确认内容必须包含图片数量，以及是否存在仍在工作台打开或包含未保存修改的图片。
- 批量操作必须返回成功、跳过和失败数量，不能只显示笼统的“操作失败”。

## 3. 工作台多标签

### 3.1 标签栏位置与结构

标签栏位于工作台页面标题栏下方、图片与 Prompt 编辑区上方。标签过多时横向滚动，不压缩到无法辨认，也不换行增加工作区高度。

每个标签至少包含：

- 图片显示名称。
- 当前标签的完整选中表面或完整边框。
- 有修改但尚未复制/处理完成时的状态圆点。
- 关闭按钮。

标签栏使用 LobeUI 新版 `Tabs` 负责选中状态、焦点和键盘导航；关闭按钮、未保存状态、横向滚动和标签右键菜单由应用层封装。Prompt 编辑区只渲染当前激活标签，避免同时挂载多个完整编辑器。

### 3.2 打开与切换规则

- 从文件、剪贴板、拖放或图片库打开图片时，默认创建新标签。
- 同一个本地源文件或同一个图片库项目已经打开时，直接切换到已有标签，不创建重复标签。
- 从剪贴板读取的像素图片使用独立会话标识；每次主动粘贴视为新的输入，除非内容指纹与已有剪贴板标签完全一致且该标签仍未关闭。
- 新标签成为当前标签。
- 关闭当前标签后，优先切换到它左侧最近使用的标签；没有左侧标签时切换到右侧标签。
- 不设置很小的固定标签数量上限；大量标签通过横向滚动和溢出处理保持可用。

### 3.3 草稿与恢复

- 每个标签独立保存 `originalProject`、当前草稿、来源、更新时间和未保存状态。
- 应用重启后恢复标签顺序、当前标签和每个标签的 Prompt 草稿。
- 会话格式从单工作台 `v1` 迁移为多标签 `v2`；读取到旧会话时自动转换为一个标签。
- 文件来源失效时，该标签显示明确错误并允许关闭，不影响其他标签恢复。
- 剪贴板像素图片需要先写入应用管理的工作台临时资源目录，保证应用重启后标签仍可恢复；关闭且不再被任何标签引用后才清理对应临时文件。

### 3.4 关闭与快捷键

- 关闭没有修改的标签无需确认。
- 关闭有修改的标签时确认是否丢弃修改。
- `Ctrl/Cmd+W` 关闭当前工作台标签；不能因此直接关闭整个应用窗口。
- `Ctrl/Cmd+Tab` 与 `Ctrl/Cmd+Shift+Tab` 切换标签。
- 中键关闭可作为增强项，但不能代替可见关闭按钮和键盘操作。

## 4. 图片读取与 Split Button

### 4.1 工作台入口

工作台标题栏和空状态都使用 Split Button：

- 主按钮：`打开图片`
- 下拉项：`从剪贴板打开`

点击主按钮打开标准文件选择器。读取成功后创建新工作台标签，不加入图片库。原有“更换图片”文案取消，因为多标签下的默认行为不再替换当前图片。

### 4.2 图片库入口

图片库标题栏使用主操作 Split Button：

- 主按钮：`导入图片`
- 下拉项：`从剪贴板导入`

主按钮继续支持多选图片和 ZIP。剪贴板入口一次处理一张剪贴板图片，成功后加入图片库并选中新导入项目。重复内容沿用现有内容指纹规则，不因入口不同产生重复记录。

### 4.3 剪贴板读取规则

读取优先级：

1. 如果剪贴板暴露了可访问的受支持本地图片文件，优先读取原始文件，以保留 PNG metadata。
2. 否则读取剪贴板位图，将像素编码为应用可处理的 PNG。

必须明确以下事实：网页“复制图片”、截图工具和大部分位图复制只保留像素，通常已经失去 NovelAI PNG metadata。此类图片仍可正常打开或导入，但当未检测到 NovelAI metadata 时显示非阻塞提示：

> 已读取剪贴板图片，但剪贴板只包含像素，未检测到 NovelAI Prompt 元数据。

其他状态：

- 剪贴板没有图片：提示“剪贴板中没有可导入的图片”。
- 图片为空、损坏或尺寸无效：保留当前标签或图片库状态并显示具体错误。
- 文本输入框、文本域或可编辑区域获得焦点时，`Ctrl/Cmd+V` 保持普通文本粘贴行为。
- 非文本区域可以支持 `Ctrl/Cmd+V` 作为按钮之外的辅助入口，但可见 Split Button 是主要入口。

### 4.4 记忆上次图片目录

工作台“打开图片”和图片库“导入图片”共用一个最近图片目录：

- 用户成功选择文件后，记录第一项所在目录。
- 下次打开图片文件选择器时将该目录作为 `defaultPath`。
- 取消文件选择不更新记录。
- 从拖放、剪贴板或图片库打开不更新最近图片目录。
- ZIP 与普通图片共用该目录。
- 目录不存在、磁盘离线或权限失效时忽略记录，并回退到操作系统默认目录。
- 更改图片库资源位置的文件夹选择器使用独立目录语义，不读取或覆盖最近图片目录。
- 最近目录存入应用偏好设置并跨重启保留，使用跨平台绝对路径验证。

### 4.5 图片展示与大图工具栏

图片库详情预览、图片库全屏大图和工作台图片区统一使用共享的 `ImageStage` 布局：

- 可用区域使用居中布局，图片的水平和垂直中心与展示区域中心对齐。
- 图片使用 `object-fit: contain`，不得因为侧栏宽度、图片方向或窗口尺寸变化而贴向某一侧。
- 展示区域应以实际可用空间计算尺寸；图片库详情面板和工作台侧栏的宽度不得被误算进图片画布。
- 加载中、加载失败和无图片状态沿用同一居中基准，避免状态切换时产生明显跳动。

全屏大图继续使用 LobeUI 图片预览能力提供翻转、旋转和缩放，但“复制”和“下载”改由应用层实现，不依赖渲染器对 `novelai-media://` 地址直接执行 `fetch`：

- `复制图片`：由 Electron 主进程读取应用已验证的本地资源，并把位图写入系统剪贴板。
- `下载图片`：打开原生“另存为”对话框并复制原始资源字节，保留图片格式与 NovelAI metadata；默认文件名使用当前显示名称和原扩展名。
- 用户取消“另存为”不显示错误；读写失败显示中文、可操作的错误信息。
- 复制成功、下载成功、复制失败和下载失败均提供非阻塞中文反馈。
- LobeUI 内建提示文本通过 `ConfigProvider` 注入中文资源；应用自定义按钮、Tooltip 和错误文案不得回退为英文。

复制到系统剪贴板只承诺复制可见位图，不承诺保留 PNG metadata；需要保留 metadata 时应使用“下载图片”。

## 5. Prompt 复制规则与 Split Button

### 5.1 顶部复制入口

工作台标题栏的 `复制 Prompt` 改为 LobeUI Split Button。

主按钮：

- 标签：`复制可见 Prompt`，可在不造成拥挤时附带可复制 Tag 数量。
- 复制当前筛选结果中仍然可见的正向 Prompt Tag。
- 搜索、分类、Base/Character 区域筛选会影响结果。
- `Prompt / Undesired` 极性筛选也会影响可见结果，但 Undesired Tag 永远不会进入结果。
- 当前视图只剩 Undesired Tag 或没有正向 Tag 时，主按钮禁用。

下拉菜单：

1. `复制全部 Prompt`
2. 分隔线
3. `复制完整 Base Prompt`
4. 根据实际角色动态生成 `复制角色 1 Prompt`、`复制角色 2 Prompt` 等条目

下拉中的“全部”“完整 Base”和单个角色操作不受当前搜索、分类或区域筛选影响。空的 Base 或角色 Prompt 对应条目禁用。没有角色时不显示角色分组。

### 5.2 复制内容语义

所有顶部 Prompt 复制操作必须：

- 只使用 `polarity === 'prompt'` 的作用域。
- 永远排除 Base Undesired Content 和 Character Undesired Content。
- 使用原始 NovelAI Tag，而不是当前显示语言中的译文。
- 保留权重、合法的原始语法和 Tag 顺序。
- 同一作用域内使用 `, ` 分隔。
- 复制多个作用域时保持 Base 和各角色的作用域边界，沿用项目既有的 `\n|\n` 分隔格式。
- 不因为当前按结构或按分类显示而改变相同 Tag 集合的输出顺序。

`复制全部 Prompt` 是现有完整正向 Prompt 复制能力的明确入口；主按钮不再默认复制所有作用域。

### 5.3 多选工具栏

Prompt 总览中的“复制已选”继续存在，但其语义同步收紧：

- 只复制已选项中的正向 Prompt Tag。
- 已选择的 Undesired Tag 被忽略。
- 如果存在被忽略项，完成提示显示：`已复制 8 个 Prompt Tag，忽略 3 个排除 Tag`。
- 只选中 Undesired Tag 时复制按钮禁用，并说明没有可复制的 Prompt Tag。

## 6. 图片库管理

### 6.1 顶部视图切换

图片库工具栏提供：

- `全部`
- `收藏`
- `回收站`

优先使用 LobeUI `Segmented` 或同等紧凑控件。搜索和排序作用于当前视图。回收站不加入侧边主导航，避免把辅助状态升级为新的一级业务页面。

### 6.2 完整 Prompt 图片分组

图片库把“完整 Prompt 语义相同、仅 Seed 等生成结果属性不同”的图片折叠为一个图片组。分组依据是规范化后的完整 Prompt 指纹，不使用文件名或简单字符串截断比较。

完整 Prompt 指纹必须包含：

- Base Prompt 与 Base Undesired Content。
- 每个角色的 Prompt 与 Character Undesired Content。
- 角色顺序、角色位置坐标，以及会改变角色位置语义的结构字段。
- Prompt 作用域、条目顺序、权重和其他会改变实际生成语义的结构信息。

完整 Prompt 指纹明确不包含：

- Seed。
- 图片名称、文件名、导入时间、收藏状态和删除状态。
- 图片像素、尺寸和应用管理资源路径。
- 不属于 Prompt 语义的其他生成结果或管理字段。

因此，排除内容不同、角色顺序不同或角色位置不同的图片不能归入同组；只有 Seed 不同的图片可以归入同组。无法解析出完整 Prompt 的图片保持为独立卡片，不与其他无 Prompt 图片互相分组。指纹生成必须使用稳定的规范化序列化，兼容等价的换行、分隔符和非语义空白，但不得把真实的 Tag 顺序或作用域差异错误合并。

分组卡片规则：

- 两张及以上同组图片显示为有层叠感的单张组卡片，并显示图片数量。
- 一张图片的组按普通图片卡片显示，不额外制造层叠视觉。
- 默认头图为组内最近导入的图片；用户设置过头图后，持久化该选择。
- 组卡片的名称、缩略图和主要元信息取自当前头图。
- 搜索命中组内任意成员时显示整个组；排序时间取组内最近导入时间。
- 点击组卡片时，详情预览默认从头图开始。

详情预览中的组内浏览规则：

- 图片区域左右两侧提供上一张、下一张按钮，并显示“当前序号 / 组内总数”。
- 焦点不在文本编辑控件时，左右方向键可以切换组内图片。
- 切换图片后，名称、尺寸、Prompt、收藏状态和操作对象同步为当前图片。
- 当前图片不是头图时显示“设为头图”；设置后组卡片立即更新，且重启后保持。
- 删除当前头图后，如果组内仍有图片，则自动使用剩余图片中最近导入的一张作为头图。

选择与删除作用域是两套明确规则：

- 在图片库多选模式中，图片组是最小选择单位。选中一个组卡片并执行“移入回收站”，会把该组当前视图中的全部成员移入回收站。
- 多选确认文案同时显示组数和实际图片数，例如“将 3 组共 18 张图片移入回收站”。
- 在右侧详情预览中点击“移入回收站”，只删除当前正在预览的这一张图片，不删除同组其他成员。
- 详情预览删除成功后，优先显示同组下一张；没有下一张时显示上一张；组内没有剩余图片时关闭该组预览并选择相邻组。
- 所有菜单和确认文案必须明确使用“删除当前图片”或“删除整个图片组”，不得只显示语义不清的“删除”。

组的折叠只改变图片库的展示和批量选择单位，不改变底层每张图片独立的项目记录、收藏状态、名称、资源文件和工作台打开状态。

### 6.3 收藏

- 图片卡片提供可访问的收藏按钮，收藏状态在卡片和预览面板保持一致。
- 支持单张收藏、取消收藏，以及批量收藏和取消收藏。
- 收藏视图只显示未进入回收站的收藏图片。
- 图片进入回收站后保留收藏状态；恢复后仍然是收藏图片。
- 收藏不是删除保护，但删除收藏图片时确认信息必须明确包含收藏图片数量。

数据库已有 `projects.is_favorite` 字段，后续实现应复用该字段，不建立第二套收藏关系。

### 6.4 图片名称修改

- 修改的是图库显示名称 `projects.name`，不重命名应用资源目录中的 UUID 图片文件和缩略图文件。
- 名称去除首尾空白，不能为空，并设置合理长度上限。
- 允许不同图片使用相同显示名称。
- 可从预览标题或右键菜单进入编辑；键盘操作需要支持 Enter 保存、Escape 取消。
- 修改后同步更新卡片、搜索结果、工作台中从该图库项目新打开的标签名称。
- 已经打开的工作台标签不强制覆盖用户当前会话标题；重新打开或恢复时读取最新图库名称。
- 回收站中的图片不可重命名，需先恢复。

### 6.5 多选与批量操作

- 图片卡片悬停和选择模式下显示统一选择标记。
- 支持 `Ctrl/Cmd` 增减选择、`Shift` 范围选择和“全选当前筛选结果”。
- 选择跨搜索或视图变化时，移除已经不属于当前操作上下文的选择，避免对不可见图片执行批量删除。
- 批量工具栏至少提供：收藏、取消收藏、移入回收站。
- 回收站批量工具栏至少提供：恢复、永久删除。
- 操作完成后显示成功、跳过和失败数量。

批量操作遇到图片组时以整组为单位：收藏、取消收藏、移入回收站和恢复均作用于选中组在当前视图中的全部成员。结果反馈同时报告组数和实际处理的图片数。

### 6.6 回收站

普通删除和批量删除执行软删除：

- 写入 `projects.deleted_at`。
- 图片记录从“全部”和“收藏”视图隐藏。
- 应用管理的原图和缩略图继续保留。
- 对应工作台标签继续可用，不因移入回收站立即关闭。

回收站支持：

- 单张或批量恢复：清空 `deleted_at`。
- 单张或批量永久删除。
- `清空回收站`：永久删除回收站中的全部图片。

第一版不做“30 天后自动清理”。清理完全由用户主动执行，避免后台静默删除本地资产。

普通“移入回收站”按钮使用 LobeUI `danger + fill` 语义，在亮色和暗色主题下都必须有清晰的危险色文字、图标或表面，不得显示成普通中性按钮。

### 6.7 永久删除与清空回收站

`清空回收站` 只在回收站视图中显示，使用危险但非全局主操作的按钮样式。确认信息至少包含：

- 将永久删除的图片数量。
- 预计释放的磁盘空间；如果无法可靠计算则省略，不显示猜测值。
- 仍在工作台打开的图片数量。
- 其中包含未保存修改的标签数量。
- 明确说明操作不可撤销。

确认永久删除后：

1. 关闭对应工作台标签；存在未保存修改时必须在最终确认中明确说明会丢弃修改。
2. 删除应用管理的原图与缩略图。
3. 仅在资产清理达到可接受状态后永久删除数据库记录。
4. 单项失败不阻止其他项目继续处理；失败项目保留在回收站并允许重试。
5. 返回成功、失败与可能残留的文件清单摘要。

永久删除只能处理应用资源目录内经过验证的资产路径，禁止删除外部原始文件、工作区根目录、用户目录或未验证路径。

永久删除与“清空回收站”的最终确认按钮使用 LobeUI `danger + primary` 语义；危险色的对比度和可辨识度必须在亮色、暗色主题中分别验收。

## 7. 设置页面侧栏

设置页移除左下角的“关闭 / 返回”按钮。应用全局侧边导航已经提供离开设置页的明确入口，不再保留第二套返回机制。

设置分类导航改为 LobeUI `DraggablePanel`：

- 使用左侧 `placement`、固定布局和稳定占位模式，展开时推动主内容，不覆盖主内容。
- 展开宽度固定为约 `220px`，不提供自由拖拽改宽；“DraggablePanel”在这里用于其折叠侧栏结构，不用于让用户改变宽度。
- 保留可访问的展开 / 折叠控制，折叠后主内容使用释放出的空间。
- 窄窗口下默认折叠；窗口恢复足够宽度后尊重用户本次会话的折叠选择。
- 切换折叠状态不得重置当前设置分类、滚动位置或未提交的表单状态。
- 分类导航、折叠控制和主内容的键盘焦点顺序必须连续可理解。

设置页的唯一页面级离开方式是全局主导航；系统窗口关闭仍沿用应用现有的窗口行为。

## 8. 软件内版本更新

### 8.1 用户体验目标

设置页新增“关于与更新”区域：

- 当前版本。
- `检查更新`。
- 最新版本、发布时间和简要更新说明。
- 下载进度和错误状态。

默认不强制安装更新。检查失败不能阻止应用启动和本地功能使用。自动检查可以在应用启动稳定后延迟执行一次，并提供关闭自动检查的设置。

### 8.2 分阶段交付

阶段 A：软件内检查更新。

- 从 GitHub Release 获取最新稳定版本。
- 比较语义化版本并展示更新说明。
- 在当前未签名发布条件下允许用户打开官方 Release 下载页。

阶段 B：软件内下载并安装。

- 使用适配 electron-builder 的更新方案和 GitHub Release provider。
- Windows 使用可更新的 NSIS 构建。
- macOS 除 DMG 外生成自动更新所需的 ZIP 和 `latest-mac.yml`。
- 发布流程上传 Windows/macOS 更新元数据、安装包及必要的校验信息。
- macOS 自动更新启用前必须完成应用签名和公证；Windows 也应完成代码签名，避免更新链路缺乏可信校验。

### 8.3 更新安全与工作台状态

- 只接受来自项目官方发布源并通过完整性校验的更新。
- 开发模式和未打包运行时不执行真实下载或安装。
- 调用“重启并安装”前持久化全部工作台标签、当前标签和草稿。
- 如果会话持久化失败，阻止自动退出并提示用户。
- 不在有图片导入、资源库迁移、永久删除或清空回收站操作进行时开始安装。
- 更新失败保留当前可运行版本和用户数据，不修改图片库资源目录。

## 9. 数据与接口调整建议

本节描述开发时应具备的能力，不限定最终函数命名。

### 9.1 项目数据

复用现有字段：

- `projects.name`：图库显示名称。
- `projects.is_favorite`：收藏状态。
- `projects.deleted_at`：回收站状态。

新增或补齐数据库操作：

- 修改项目名称。
- 设置单个或多个项目收藏状态。
- 将单个或多个项目移入回收站。
- 恢复单个或多个项目。
- 查询正常、收藏和回收站项目。
- 永久删除已进入回收站的项目。
- 清空回收站并返回逐项结果。
- 按完整 Prompt 指纹查询图片组，并返回当前视图内的成员数量与成员列表。
- 保存、读取和清理图片组的用户指定头图。

所有批量数据库修改使用事务；文件系统清理与数据库提交之间必须设计可恢复顺序，避免一半记录消失、一半资产无法定位。

完整 Prompt 指纹可以持久化或在查询层稳定计算，但必须满足以下数据约束：

- 同一套规范化逻辑被导入、查询、迁移和测试共同复用。
- 指纹包含 Base / Character 的正向与排除内容、角色顺序和位置，不包含 Seed。
- 头图偏好使用“Prompt 指纹 + 项目 ID”的稳定关系保存，不把组复制成新的图片项目。
- 头图项目不在当前视图、已永久删除或不再属于该指纹时，查询层回退到组内最近导入的有效成员。
- 正常、收藏和回收站视图分别只统计当前视图内的成员，避免隐藏成员被无提示地纳入批量操作。

### 9.2 工作台会话

会话 `v2` 至少保存：

- `tabs`
- `activeTabId`
- 每个标签的来源类型、来源标识、原始 Prompt 快照、草稿快照、显示名称和更新时间
- 标签顺序

图库项目标签使用项目 ID 作为稳定身份，外部文件使用规范化路径，剪贴板标签使用临时资源 ID 和内容指纹。

### 9.3 偏好设置

偏好设置至少新增：

- `recentImageDirectory`
- 是否自动检查更新

目录值必须通过跨平台绝对路径和长度校验；无效旧值在读取时安全忽略。

## 10. 错误与边缘情况

- 打开同一图片时不得覆盖另一个标签中的草稿。
- 图库图片移入回收站后，从已有工作台标签再次操作不得意外恢复图库记录。
- 永久删除后，恢复会话不能重新创建已经被删除的图库项目。
- 剪贴板位图没有 Prompt 是正常状态，不作为导入失败。
- 剪贴板原始文件已失效时可以回退到可读取的位图；两者都不可用时才失败。
- 最近目录包含中文、日文、空格、括号或长文件名时仍可正常打开。
- 文件选择器取消、剪贴板为空、重复导入和单项删除失败都不能清空当前选择或工作台内容。
- 当前筛选只包含 Undesired Tag 时，“复制可见 Prompt”不得复制排除内容作为替代。
- 复制角色 Prompt 时不得混入 Base Prompt、其他角色 Prompt 或任何 Undesired Tag。
- Base 或 Character 的排除内容不同、角色顺序不同或角色位置不同的图片不得错误合并成同组；Seed 不同不得阻止分组。
- 多选删除一个组必须移动整个组选中的当前视图成员；详情预览删除必须只移动当前图片。
- 详情预览删除组内最后一张图片后不得留下空组、失效头图或悬空选择。
- 图片复制或下载失败不得关闭大图预览；取消“另存为”不得显示失败提示。
- 侧栏展开、折叠和窗口缩放后，图片仍保持在实际展示区域中心。
- 更新安装前不得丢失未保存的多标签草稿。

## 12. 验收清单

### 工作台

- 同时打开多张图片时，每张图片有独立标签和草稿。
- 重启后标签顺序、当前标签和草稿恢复。
- 从图库重复打开同一项目时切换到已有标签。
- 关闭未修改标签无需确认；关闭有修改标签会确认。
- LobeUI 标签在键盘、亮色/暗色主题和窄窗口下均可使用。
- 图片在侧栏宽度变化和不同窗口尺寸下始终相对实际图片区水平、垂直居中。

### 图片入口

- 工作台主按钮从文件打开，下拉从剪贴板打开，均不加入图片库。
- 图片库主按钮从文件导入，下拉从剪贴板导入，均进入图片库。
- 文件选择器默认打开上次成功选择的图片目录。
- 剪贴板只有像素时仍能读取，并明确提示 metadata 可能缺失。
- 文本编辑状态下粘贴不会被图片入口劫持。

### Prompt 复制

- 主按钮只复制当前可见的正向 Prompt Tag。
- Base、每个角色和全部 Prompt 可以独立复制。
- 所有顶部复制和多选复制都不会包含 Undesired Tag。
- 输出始终使用原始 Tag、权重、顺序和作用域分隔。

### 图片库

- 完整 Prompt（包括排除内容、所有角色及角色位置）相同而 Seed 不同的图片折叠为一组。
- 排除内容、角色顺序或角色位置不同的图片不会错误分组。
- 组卡片显示层叠效果、成员数量和头图，并支持持久化“设为头图”。
- 详情预览可以用左右按钮和方向键浏览组内图片，元信息与操作对象同步切换。
- 多选组卡片后移入回收站会处理整个组，确认文案同时显示组数与图片数。
- 详情预览中的“移入回收站”只删除当前图片，并正确选择下一个预览对象。
- 支持单张和批量收藏、取消收藏、移入回收站与恢复。
- 名称修改只改变显示名称，不改变资产文件路径。
- 普通删除后图片文件仍存在并可恢复。
- 永久删除和清空回收站会删除应用管理的资产并返回逐项结果。
- 清空回收站会正确处理仍在工作台打开及包含未保存修改的图片。
- 批量操作不会作用于筛选后不可见的残留选择。
- 普通删除、永久删除和清空回收站在亮色与暗色主题下都具有清晰、分级正确的危险样式。

### 图片预览与设置

- 全屏大图的复制按钮能把位图写入系统剪贴板，下载按钮能用原生对话框保存原始文件。
- 下载的 PNG 保留原始 NovelAI metadata；复制位图不承诺保留 metadata。
- 大图工具栏 Tooltip、成功反馈和错误提示均为中文。
- 图片库详情、全屏大图和工作台图片在可用区域内居中显示。
- 设置页没有重复的“关闭 / 返回”按钮。
- 设置分类侧栏使用约 `220px` 固定宽度的可折叠 DraggablePanel，折叠时释放主内容空间且不丢失页面状态。

### 更新

- 能显示当前版本并检查官方稳定版本。
- 无网络或 GitHub 不可用时不影响应用使用。
- 签名发布条件满足后可以下载、校验、重启并安装更新。
- 更新前多标签草稿可靠保存，更新失败不会损坏图片库与偏好设置。
