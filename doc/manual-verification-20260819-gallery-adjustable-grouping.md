# 图片库可调自动分组手动验证

## 验证对象

- 功能提交：`bf54609 feat: add adjustable gallery grouping`
- 目标操作系统：Windows 11（本轮用户验证）；macOS 复验记录在 `coordination/MACOS.md`

## 前置条件

1. 已拉取包含 `bf54609` 的最新 `main`，并正常启动桌面应用。
2. 图片库中准备以下可辨认的 NovelAI 图片；可以使用现有图片，不要求重新生成：
   - 至少两张完整 Prompt、Vibe、模型完全相同，仅 Seed 不同的图片。
   - 至少两张完整 Prompt 和模型相同、Vibe 不同的图片。
   - 至少两张 Base Prompt 与 Base Undesired Prompt 相同，但角色 Prompt 或角色位置不同的图片。
   - 至少一张 Base Undesired Prompt 不同的图片。
   - 至少一张生成模型不同的图片。
3. 如果旧版本中为一个图片组设置过头图，保留该图库用于验证迁移；没有旧头图时可跳过步骤 8 的迁移部分，但仍需验证新头图持久化。

## 验证步骤

1. 打开图片库，检查工具栏中的“分组”滑杆和“跨 Vibe 合并”开关，并缩窄窗口到应用允许的最小宽度。
   - 预期结果：滑杆有“全部分开 / 完整 Prompt / 基础 Prompt”三档，当前档位文字清晰；控件在窄窗口下自然换行，不遮挡搜索、排序、缩略图大小和图片计数。
   - 实际结果：

2. 将滑杆移到“全部分开”。
   - 预期结果：每张图片各自成为一组；“跨 Vibe 合并”开关禁用且视觉上不显示为开启；图片计数不变，组数等于图片数。
   - 实际结果：

3. 将滑杆移到“完整 Prompt”，保持“跨 Vibe 合并”关闭。
   - 预期结果：只有完整 Prompt、Vibe、模型相同且仅 Seed 等非分组参数不同的图片合并；不同 Vibe 或不同模型的图片保持分开。
   - 实际结果：

4. 在“完整 Prompt”档开启“跨 Vibe 合并”。
   - 预期结果：完整 Prompt 和模型相同的不同 Vibe 图片合并；不同模型仍不合并；原来仅 Seed 不同的图片不会被拆开。
   - 实际结果：

5. 将滑杆移到“基础 Prompt”，先关闭“跨 Vibe 合并”。
   - 预期结果：Base Prompt、Base Undesired Prompt、Vibe 和模型相同的图片合并，即使角色 Prompt、角色 Undesired、角色顺序或位置不同；Base Undesired、Vibe 或模型不同的图片仍分开。
   - 实际结果：

6. 在“基础 Prompt”档开启“跨 Vibe 合并”。
   - 预期结果：Base Prompt、Base Undesired Prompt 和模型相同的不同 Vibe 图片进一步合并；Base Undesired 或模型不同的图片仍不合并。
   - 实际结果：

7. 在各档位间来回切换，同时保持右侧详情打开并选择若干组。
   - 预期结果：切换立即生效且无闪退；当前详情图片仍保持打开并归入新组；已经不再存在的组选择会安全清除，不会把批量操作错误应用到旧组。
   - 实际结果：

8. 回到“完整 Prompt + 跨 Vibe 合并关闭”，在一个多图组中把非当前头图设为头图；随后切换到其他档位再切回，并重启应用。
   - 预期结果：只有该精确模式显示“设为头图”；动态分组模式不显示该入口，且默认显示最新图片；切回精确模式以及重启后，所设头图仍恢复。旧版本头图只迁移到包含原头图的精确子组，不会复制到其他 Vibe 或模型子组。
   - 实际结果：

9. 在动态分组模式下搜索一个位于组内、但不是该组最新图片的文件名或 Tag。
   - 预期结果：结果卡片临时显示实际命中的组内图片，而不是仍显示最新图片；悬停文件名、擦动预览、单击详情和双击工作台仍与指针所在成员一致。清除搜索后恢复动态组默认展示。
   - 实际结果：

10. 选择一个非默认组合，例如“基础 Prompt + 跨 Vibe 合并开启”，切换到工作台再返回图片库，然后完全退出并重新启动应用。
    - 预期结果：分组档位和跨 Vibe 选项均被持久化；重新进入后组数和分组结果一致。
    - 实际结果：

11. 分别在浅色、深色主题下检查滑杆、开关的启用/禁用、键盘焦点和文字对比度，并用键盘方向键操作分组滑杆。
    - 预期结果：控件状态和焦点清晰，三档都可通过键盘到达；没有低对比度、裁切或意外横向滚动。
