# 工作台标签拖拽排序手工验证

## 待验证变更

工作台标签支持鼠标横向拖拽与键盘排序；排序后保持当前激活标签和各标签草稿，并通过现有工作台会话自动保存顺序。

## 目标操作系统

Windows 10/11。

## 前置条件

- 已执行 `npm ci`、`npm test` 与 `npm run build`。
- 准备至少六张可由工作台打开的 PNG、JPG 或 WEBP 图片。
- 至少修改其中一个标签的 Tag，使其带有“已修改”状态。
- 使用 `npm run dev` 启动应用。

## 验证步骤

1. 在不同标签上执行普通单击，并尝试只有少量位移的按下与松开。
   预期结果：普通单击继续切换标签；不足拖拽启动距离的小幅移动不会改变标签顺序，也不会造成误切换或卡住状态。
   实际结果：

2. 按住一个非当前标签并向左、向右拖过相邻标签后放下。
   预期结果：被拖标签完整抬起，其他标签使用短促平滑的位移动画让出位置；移动被限制在标签栏水平方向；即使指针放下位置与最终槽位有少量偏差，被拖标签也会平滑吸附回槽位；放下后顺序与预览位置一致，当前正在查看的标签不变。
   实际结果：

3. 拖动当前激活标签跨越多个标签后放下。
   预期结果：拖动中的标签保持清晰背景与轻微阴影，不出现留在原位的重复激活背景；放下后该标签仍为当前标签，工作区内容不切换。
   实际结果：

4. 在标签数量较多、宽度已经自动收缩时，连续执行多次相邻交换和跨越多个标签的排序。
   预期结果：窄标签仍可稳定命中并排序；标签不换行、不重叠、不产生横向滚动条；未参与让位的标签之间仍保留分隔线，仅拖拽占位处隐藏对应分隔线，结束后所有分隔线恢复到正确位置。
   实际结果：

5. 从标签关闭按钮开始拖动，然后分别单击关闭按钮、右键标签和鼠标中键关闭标签。
   预期结果：关闭按钮不会启动拖拽；三种原有关闭方式保持可用；带有工作区草稿的标签仍出现原有确认流程。
   实际结果：

6. 先触发一个标签的悬停图片预览，再开始拖拽并将指针经过其他标签。
   预期结果：拖动开始时悬停预览关闭，拖动期间不会连续弹出其他标签预览；拖动结束后，正常停留约半秒仍可再次显示预览。
   实际结果：

7. 开始鼠标拖拽后按 `Escape`，然后松开鼠标。
   预期结果：本次排序取消，所有标签恢复原顺序，当前标签及其工作区内容不变。
   实际结果：

8. 使用 `Tab` 或方向键将键盘焦点移动到一个标签，按空格键开始排序，使用左右方向键调整位置，再按空格键放下；另一次排序使用 `Escape` 取消。
   预期结果：键盘可以完成与鼠标一致的排序和取消操作；焦点保持在被移动标签；屏幕阅读器说明不会把标签语义降级为普通按钮。
   实际结果：

9. 排序后使用 `Ctrl + Tab` / `Ctrl + Shift + Tab` 循环切换标签，再正常退出并重新启动应用。
   预期结果：循环切换遵循新的标签顺序；重新启动后标签顺序、当前标签、已修改状态和各标签草稿均与退出前一致。
   实际结果：

10. 分别在浅色、深色主题以及动画“完整”“跟随系统”“关闭”设置下重复拖拽。
    预期结果：两种主题下拖动态均清晰；完整动画保持短促流畅；跟随系统与关闭动画时尊重系统或应用设置，不出现残留变换、闪烁或无法点击的标签。
